# 1.5 循环结构 · gcc 实测凭据

每个 `.c` 都是**可独立编译运行**的最小实验。表格里每一行「gcc 实测」都对应这里的真实源码，不是手写推演。

## 怎么跑

**⚠️ 关键坑**：`gcc.exe` 在 `D:\w64devkit\w64devkit\bin\`，但**它不在默认 PATH 里**。直接调 `gcc` 会报：

```
gcc.exe: fatal error: cannot execute 'as': CreateProcess: No such file or directory
```

（`gcc` 自己找到了，但找不到汇编器 `as`。）

**必须先把它加进 PATH**：

```bash
export PATH="/d/w64devkit/w64devkit/bin:$PATH"
gcc break1.c -o break1.exe && ./break1.exe
```

加 `-Wall` 能看到额外警告（见下面 F2 的说明）。

## for1.c —— `for` 基础七问

| 实验 | 代码 | 预期输出 |
|:--|:--|:--|
| F1 | `for (i=1;i<=5;i++) printf("%d",i)` 标准式 | `F1: 12345` |
| **F2** | **`for (i=1;i<=5;i++);` ← 末尾多一个分号**，后面跟 `{ s2 = s2+100; }` | **`F2: s2 = 100`** |
| **F2b** | 去掉那个分号，其余一字不改 | **`F2b: s2b = 500`** |
| F3 | `for (i=1;i<=5;i++)` 跑完后 `i` 是几 | `F3: 结束后 i3 = 6` |
| F4 | 同一个任务，`for` 与 `while` 各写一遍 | `F4-for: 123` / `F4-while: 123` |
| F5 | `for (;;)` 三部分全省略 + `break` | `F5: 123  (n=4)` |
| F6 | `for (j=10;j<=5;j++)` 条件一开始就假 | `F6: (空)` |

**F2 与 F2b 是全部凭据里最重要的一组** —— 同一段代码只差一个分号，`100` 和 `500`。原因：分号把循环体换成了一条**空语句**，循环照样转 5 次，只是每次什么都没干；后面的大括号因此掉到循环外面，只执行 1 次。

> ⭐ `gcc -Wall` 对 F2 这种写法会**主动报警告**：
> ```
> warning: this 'for' clause does not guard... [-Wmisleading-indentation]
> note: ...this statement, but the latter is misleadingly indented as if it were guarded by the 'for'
> ```
> 意思是「这个 `for` 看着像在管下面那段，其实没管」。编译器自己会替你标记这个坑。

## for2.c —— `for` 末尾分号：三种写法对照

| 行 | 代码 | 预期输出 |
|:--|:--|:--|
| 1 | `for (i=1;i<=3;i++);` 后面跟 `printf` | `0 4` |
| 2 | 去掉分号，`s2 = s2 + i2;` 当循环体 | `6 4` |
| 3 | 分号**后面跟大括号**，块里 `s3 = s3 + 1;` | `1 4` |

第 3 行是 F2 的缩小版：分号 + 大括号 → 大括号在循环外 → `s3` 只加 1 次。

## for3.c —— 三个数辨析（A/B 只差一个分号）

| 实验 | 代码 | 预期输出 |
|:--|:--|:--|
| **A** | **无分号**，`s = s + 1`，`i<=3` | **`A: 3 4`** |
| **B** | **有分号**，`s = s + 1`，`i<=3` | **`B: 1 4`** |
| C | 无分号，`i<=5` | `C: 5 6` |
| D | 有分号，`i<=5` | `D: 1 6` |
| E | 无分号，循环体印 `[k]` | `E: [1][2][3]` |

**A vs B 是核心对照**：只有分号之差，`s` 从 `3` 变成 `1`。`i` 两种都是 `4`。

**三个数要分清**（同一段代码里同时存在，互不相等）：

1. **循环体执行次数** —— 数圈数（`i<=3` 从 1 起 → `{1,2,3}` → **3 次**）
2. **循环变量的最终值** —— 最后一个数 +1（**4**）
3. **不在循环里的语句执行次数** —— 在里面 N 次，在外面 **1 次**，没有第三种可能

## for4.c —— 迁移题（换数字换增量）

```c
int i, s = 0;
for (i = 1; i <= 4; i++);
{ s = s + 10; }
```

预期输出：**`10 5`**
- 圈数 4（`i` 走 `1,2,3,4`）
- `i` 最后 5
- 大括号不在循环里 → 执行 1 次 → `s = 0 + 10 = 10`

## break1.c —— `break` / `continue` 六问

| 实验 | 代码 | 预期输出 |
|:--|:--|:--|
| B1 | `for 1..5` + `if (i==3) break;` 然后印 `i` | `B1: 12` |
| B2 | 同样条件换成 `continue` | `B2: 1245` |
| B3 | `break` 出去后 `i` 是几 | `B3: break 出去后 i3 = 3` |
| B4 | 正常跑完 `i` 是几（对照） | `B4: 正常跑完 i4 = 6` |
| **B5** | **`while` 里 `continue` 写在 `m++` 之前** | **`B5: 12(卡死！m 一直是 3)`** |
| B6 | 把 `m++` 补到 `continue` 之前 | `B6: 1245` |

**B1 vs B2**：同一个位置、同一个条件 —— `break` 是「到此为止」，`continue` 是「跳过这一个」。

**B3 vs B4**：同一句「`i` 最后是几」，**退出方式不同答案就不同** —— `break` 停在跳出那一刻（`3`），正常跑完走越界值（`6`）。

**B5 是真陷阱**：`while` 的推进（`m++`）写在循环体里，`continue` 一执行就把它跳过了 → `m` 永远停在 3 → 条件永远为真 → **死循环**。
（代码里用 `guard` 计数器强制退出，否则这个程序跑不完 —— 输出里那句「卡死！」就是它。）
`for` 没这个坑，因为推进写在 `for` 括号里，`continue` 跳不到它。

## break2.c —— `continue` / `break` 各出一题

| 代码 | 预期输出 |
|:--|:--|
| `for 1..5` + `if (i==3) continue;` + `s = s + i;` | `12 6` |
| `for 1..5` + `if (j==3) break;` + `t = t + j;` | `3 3` |

第一行：`s = 1+2+4+5 = 12`（3 被跳过），`i` 正常跑完 = `6`。
第二行：`t = 1+2 = 3`（到 3 就跳出），`j` 停在跳出那一刻 = `3`。
