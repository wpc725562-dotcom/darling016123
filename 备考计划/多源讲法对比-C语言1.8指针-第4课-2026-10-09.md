## §1 各源**怎么讲**

### ① 鹏哥 p102（**const 修饰变量**）

> 📁 **可回溯定位**：`BV17a7K64ELH`（UP 主「鹏哥C语言」）**P102「102.【指针】const 修饰变量」**
> → `data/bili-analyze/BV17a7K64ELH/subtitle_p102.txt`

**核心**：`const` 修饰的变量叫 **常变量** —— 它有了「常属性」，但**骨子里还是变量**。

**鹏哥给的证明（很妙）**：
> 「`int arr[n];` 这种写法，**在 C99 之前是不行的** —— 因为数组的长度必须是一个**常量**。而 `const int n = 10;` 定义的 `n`，**仍然不能**用来定义数组长度。**这就证明了：`const` 修饰的变量，本质上还是个变量**，只是你不能通过它去改。」

**⇒ 一句话**：`const` 给变量加的是**只读约束**，不是把它变成真正的常量。

### ② 鹏哥 p103（**const 修饰指针**）

> 📁 **可回溯定位**：**P103「103.【指针】const 修饰指针」**
> → `data/bili-analyze/BV17a7K64ELH/subtitle_p103.txt`

**🔴 核心判据：看 `const` 在 `*` 的左边还是右边。**

| 写法 | 锁住什么 | 鹏哥的比喻 |
|:---|:---|:---|
| `const int *p`（= `int const *p`） | **锁 `*p`**（指向的内容不能改），`p` 本身可改 | **只锁门，能翻窗户** |
| `int * const p` | **锁 `p`**（指针本身不能改），`*p` 可改 | **锁窗户，能开门** |
| `const int * const p` | **两边都锁** | **门窗全锁** |

**鹏哥的比喻链（原文）**：
> 「把 `*p` 想象成**房子里的东西**，`p` 想象成**房子的门牌号**。
> `const` 在左边 → 锁的是 **`*p`**，你不能动房子里面的东西，但**可以换门牌号**（换指向）。
> `const` 在右边 → 锁的是 **`p`**，你不能换门牌号，但**能进房子动东西**。」

**另一组比喻（凉皮 / 换男朋友 / 渣男）**：
> 「`const int *p` 就像**凉皮** —— 凉皮本身（内容）不能变，但你可以**换一家店买**（换指向）。
> `int * const p` 就像**认定了一个男朋友** —— 不能换人（指针不能改），但**能改变他**（内容可改）。
> 两个都不行 → **渣男**，什么都不让你碰。」

### ③ 鹏哥 p104（**野指针 · 三大成因**）

> 📁 **可回溯定位**：**P104「104.【指针】野指针」**
> → `data/bili-analyze/BV17a7K64ELH/subtitle_p104.txt`

**🔴 定义**：野指针 = 指向的位置**不可知 / 随机 / 不正确 / 没有明确限制**的指针。
**更本质的一句**（鹏哥原话）：
> 「**指针指向的那块内容，不属于当前程序。**」

**三大成因**：

| # | 成因 | 说明 |
|:--:|:---|:---|
| **1** | **指针未初始化** | 局部指针变量默认是**随机值**（栈上的垃圾值） |
| **2** | **指针越界访问** | 数组越界后指针指向了不属于自己的空间 |
| **3** | **指针指向的空间已释放** | 指向的内存已被 `free` / 函数返回后局部变量销毁 |

**鹏哥的比喻（如家酒店 302 房）**：
> 「你订了 **302 房**（申请了一块内存），退房之后（`free`）还拿着房卡去开门（继续用这个指针）—— 那 302 房现在**可能住着别人**（内存被重新分配），你开进去就是**非法闯入**。」

### ④ 鹏哥 p105（**如何规避野指针**）

> 📁 **可回溯定位**：**P105「105.【指针】如何规避野指针」**
> → `data/bili-analyze/BV17a7K64ELH/subtitle_p105.txt`

**三招**：

| # | 招法 | 具体做法 |
|:--:|:---|:---|
| **1** | **初始化** | 不知道指哪 → 给 `NULL`：`int *p = NULL;` |
| **2** | **不越界** | 访问前确认在合法范围内 |
| **3** | **不用时置空 + 用前检查** | `p = NULL;` + `if (p != NULL) { ... }` |

**鹏哥引的芒格名言**（原文）：
> 「**如果我知道我未来死在哪里，那我永远不会去那个地方。**」
> ⇒ 知道野指针会崩，就**别制造野指针**。

**野狗拴树比喻**：
> 「野指针像**一条野狗**，到处乱咬。
> 给它置 `NULL`，就像**把野狗拴在树上** —— 它咬不到人了。
> 但如果你**已经是 `NULL` 了还去 `*p = 100`**，那就像**站在树根前尿尿**，狗照样咬你。」
> ⇒ **`NULL` 只是"拴住"，不是"消失"** —— 用之前必须 `if (p != NULL)` 检查。

**`NULL` 三个事实**：
| # | 事实 |
|:--:|:---|
| 1 | `NULL` **就是 0**（`#define NULL 0` 或 `((void*)0)`） |
| 2 | C 语言里它是 **`((void*)0)`** |
| 3 | **0 号地址不可读写** —— 对 `NULL` 解引用**直接报错**（段错误），这是好事：**崩溃好过悄悄出错** |

## §3 ✅ 本课要点（**4 条**）

| # | 要点 | 来源 |
|:--:|:--|:--|
| **1** | **`const` 修饰的是「常变量」** —— 有只读约束，但本质仍是变量（`const int n=10` 不能当数组长度） | 鹏哥 p102 |

| **4** | 🔴 **规避三招**：初始化（给 `NULL`）/ 不越界 / 用前置空 + `if (p != NULL)`；**`NULL` = 0，解引用必崩** | 鹏哥 p105 |
