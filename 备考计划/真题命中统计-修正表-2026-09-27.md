## §1 错误机制（完整链条）

**我当时的命令**：
```bash
cd 历年真题/真题txt/计算机基础与程序设计
grep -c "gets" *.txt | awk -F: '{s+=$2} END{print s}'
```

**实际发生了什么**（逐文件拆开）：

```
2021年真题.txt            : 0
2022年真题.txt            : 1
2023年真题.txt            : 0
2024年真题.txt            : 0
《C语言程序设计》.pdf.txt  : 30   ← 🔴 685KB 的课本，贡献了 30
────────────────────────────────
求和                        = 31   ← 我报的「31 次」
```

**⇒ 我报的「31 次」里，30 次来自课本。真题只有 1 次。**

### 三个致命细节

| # | 细节 | 后果 |
|:--:|:--|:--|
| **1** | **`*.txt` 匹配了 5 个文件，不是 4 个** | 多算了一个 |
| **2** | **课本是 685KB，真题只有 6KB** | 课本的词频**压倒性** |
| **3** | **`grep -c` 是「每个文件一个计数」，`awk` 直接求和** | 把「课本 + 真题」混成一个数 |

## §5 ✅ 正确的统计方法（机械禁令）

### 禁令

> **1. 统计「真题命中」时，glob 必须写 `*真题*.txt` 或 `*试题*.txt`，不许写 `*.txt`。**
> **2. 统计前先 `ls -la` 看清目录里有几个文件、哪个是课本/合集。**
> **3. 凡报出的数字，必须能复现 —— 报数字时把命令一起写上。**
> **4. 拿数字做「优先级判断」之前，先问一句：「这个数是怎么算出来的？」**

### 正确命令模板

```bash
# ✅ 正确：只匹配真题文件
cd 历年真题/真题txt/计算机基础与程序设计
grep -o "gets" *真题*.txt | wc -l

# ✅ 正确：先看清目录
ls -la *.txt

# ❌ 错误：会匹配到课本
grep -c "gets" *.txt
```

### 为什么用 `grep -o | wc -l` 而不是 `grep -c`

| 命令 | 输出 | 风险 |
|:--|:--|:--|
| `grep -c "x" *.txt` | **每个文件一行「文件名:计数」** | ⚠️ **多文件时会混** |
| **`grep -o "x" *.txt \| wc -l`** | **一个总数** | ✅ **但 glob 必须写对** |

**⇒ 关键不在命令，在 glob。**
