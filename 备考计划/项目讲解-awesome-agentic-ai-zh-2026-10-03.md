# §2 它的结构（**这是它最值钱的部分**）

## 2.1 一张图：先分流，再分路

```
Stage 0 ─ 1 ─ 2  （共用基础）
       │
       ├──► Track A · CLI Power User   A1 → A2 → Stage 5 → A3 → Stage 8
       │      （用现成 CLI Agent 把工作做完）
       │
       └──► Track B · Agent Builder    3 → 4 → 5 → 6 → 7 → 7.5 → 8
              （自己从零打造 Agent）
                    ↓
              两条路共用 Stage 5 和 Stage 8
```

**核心设计**：**先确认 Stage 0–2 是共用地基，然后「你想做什么」决定走哪条。**
- **会 Python / Git / API** ⇒ **可跳过 Stage 0**，直接从 Stage 1 进
- **完全没写过程序** ⇒ 从 Stage 0 + 「零基础设置指南」进
- **只想安全用 AI，暂时不写代码** ⇒ 直接走「日常用户路线」

# §3 它的亮点（**五条，按含金量排**）

## 亮点 1 · 🔴 「先选一条路，再一步一步走」—— 反资源大全

作者对自身定位非常清楚：
> **「这里的角色是**学习路线图 + 精选资源 + 可直接运行的小练习**。需要完整章节时，我们会带你去官方文档、Datawhale Hello-Agents 或对应的 Cookbook，**不重写另一套百科全书**。」**

**⇒ 这是成熟的取舍**：不重复造教材，只负责「排序」和「入口」。同类项目（`liyupi/ai-guide`）做广度，它做**顺序**。

## 亮点 2 · 🔴 一句话点破概念焦虑

> **「Prompt、Context、Harness、Loop、Graph 会一起工作；它们不是五层，也不是互相取代的产品世代。」**

**⇒ 这句话能防住大部分「新概念又来了，我是不是学错了」的内耗。** 概念是**同时工作**的，不是世代替换。

## 亮点 3 · **「看懂不等于做得到」被写进方法论**

`docs/HOW_TO_USE.md` 的**六步学习循环**（原文）：

1. **看成果** —— 先读「你会做出什么」和成功条件
2. **直接执行** —— 复制第一组命令，让原版测试通过
3. **选一个小改动** —— **只改一个输入、规则、工具或停止条件**
4. **先猜结果** —— 用一句话写下「我觉得会发生什么」
5. **再跑测试** —— 看实际结果是否和猜的一样；不一样就读错误信息
6. **说出原因** —— **用自己的话解释这一行为什么改变了系统**

> **「一次只改一件事，像一次只换一块积木；倒了时才知道是哪一块造成的。」**
> **「做到完成条件再往下走：**看懂不等于做得到**。」**

**⇒ 第 4 步「先猜结果」是这段里最狠的一招** —— 它把「跑测试」从「看有没有报错」升级成「验证你的心智模型」。

## 亮点 4 · **练习真的能跑，而且有 Mock / Live 分层**

`examples/README.zh-Hans.md` 用**五个词**把初学者最容易混的东西分开了：

| 核心词 | 白话说法 | 正确意思 |
|:--|:--|:--|
| **Example** | 已经拼好的小积木 | 可直接运行、观察结果的示范程序 |
| **Starter** | 留几块给你自己拼 | 练习用的最小程序入口，通常 `starter.py` |
| **Path** | 到同一个终点的不同道路 | **Path A/B/C** 表示不同运行方式 |
| **Mock** | 先用玩具电话练习 | **不连接真实模型**，先检查程序逻辑 |
| **Live call** | 真的把电话打出去 | 连接本地或云端模型，**结果、时间和费用都可能变** |

**⇒ 关键设计：先用 Mock 找程序错误，再做 Live call 看模型行为。**
**⇒ 这条直接省钱**：不用烧 API 额度就能验证代码逻辑对不对。

## 亮点 5 · **Stage 7 的一句话把「上线」说清了**

> **「先说清楚怎样算成功 → 留下做事纪录 → 危险动作先问人 → 确认跌倒后能继续 → 最后才交给别人使用。」**

并且配了一张「你卡在哪里 → 先做什么 → 要拿出的证据」对照表。**每一格都要求「证据」，不要「感觉搞定了」。**
