## §1 四个源**各自怎么讲**（原文提炼）

### ① 精编讲义（**机构讲义 · 按课本**）

**7.1 函数是什么** —— **从「为什么」讲起**：

> 「如果程序的功能比较多，规模比较大，把所有的程序代码都写在一个主函数中，就会使主函数变得**庞杂、头绪不清**，使阅读和维护程序变得困难。
> 有时程序中要多次实现某一功能，就需要**多次重复编写**实现此功能的程序代码。这使程序冗长，不精炼。
> 采用『**组装**』的办法简化程序设计过程 —— **事先编好一批函数实现各种不同的功能，用到什么函数就直接装使用**。」

**⇒ 核心定义（三句）**：
> 「**函数就是功能（Function）**」
> 「**每一个函数用来实现一个特定的功能**」
> 「**函数的名字应反映其代表的功能**」

**7.2.1 为什么要定义函数** —— **一句硬规则**：
> 「C 语言要求，在程序中用到的所有函数，必须『**先定义，后使用**』」

**⇒ 定义要指定 4 样东西**：
| # | 指定什么 | 作用 |
|:--:|:--|:--|
| 1 | **函数名字** | 以便**按名调用** |
| 2 | **函数类型** | **返回值的类型** |
| 3 | **参数的名字和类型** | 以便调用时**传递数据** |
| 4 | **函数的功能** | **最重要** —— **在函数体中解决** |

**7.2.2 定义格式**：
```
无参：类型名 函数名() { 函数体 }
有参：类型名 函数名(形式参数表列) { 函数体 }
```

**7.2.3 调用格式**：
```
无参：函数名()           如 print_star()
有参：函数名(实参表列)    如 max(a,b)
```

**🔴 而且对「值传递」有官方解释**：
> 「在定义函数中指定的**形参，在未出现函数调用时，它们并不占内存中的存储单元**。
> 在发生函数调用时，函数的**形参被临时分配内存单元**。**将实参的值传递给形参**。」

**⇒ 关键**：**形参是「临时分配」的** ⇒ **它和实参是两个不同的存储单元** ⇒ **改形参不影响实参** ✅

### ② 黄金知识汇编（**考点速记**）

**「一、C 程序是由函数构成的」**（5 条）：
1. C 源程序必须包含**一个 `main` 函数**
2. 可以包含**若干个其他函数**
3. **函数是 C 程序的基本单位**
4. 被调函数可以是**库函数**，也可以是**用户编制设计的函数**
5. 程序全部工作都由各个函数分别完成

**「二、一个函数由两个部分组成」**：
1. **函数首部**：例如 `int max(...)`
2. **函数体**：`{ ... }`

**⇒ 特点**：**直接给「要背的条目」**，不解释为什么。

### 冲突 2：**「值传递」用哪个视角讲？**

| 源 | 视角 |
|:--|:--|
| **精编讲义** | **内存视角**（「形参临时分配内存」） |
| **笔记站** | **类比视角**（「复印不是原件」） |

> **形参和实参是【两个不同的存储单元】** ⇒ **所以改一个不影响另一个**
