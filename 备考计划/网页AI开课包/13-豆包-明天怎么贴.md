# 豆包 · 明天怎么贴（照抄即可）

> **为什么单独写这份**：豆包和 ChatGPT / Claude 不一样 ——
> ① 没有「项目 / 知识库」（**智能体功能已于 2026-07-15 下线**），所以**没有持久知识库**
> ② 上下文公开资料写 **128K**（约 **8.5 万中文字**），以实际界面为准
> ⇒ **结论：`12-全集-按科/` 在豆包上完全用不了**（政治一科 100 万字，超 12 倍）。必须走「按需贴」。
> 写于 2026-11-03

---

## 一、豆包的预算表（先记住这个数）

| 项 | 数值 |
|:--|:--|
| 上下文 | 128K token ≈ **8.5 万中文字** ≈ **255 KB** |
| 留 40% 给回答 | 输入控制在 **5 万字 / 150 KB 以内** |
| 单轮安全线 | **3 份文件 / 合计 < 80 KB** |

**每轮贴 3 份：规则 + 状态卡 + 当节材料。** 超过就拆。

---

## 二、一科一个对话（绝不混）

豆包没有「项目」，所以**换科必须换对话**。混在一起它会串科，而且上下文很快被上一科占满。

| 规则 | 为什么 |
|:--|:--|
| 一科 = 一个独立对话 | 串科 + 上下文污染 |
| 感觉它开始忘事 → 重开 | 重开就重贴「规则 + 状态卡」 |
| 一个对话别超过 20 轮 | 128K 会被对话本身吃掉 |
| 换章 → 重开对话 | 上一章的原文没必要继续占位 |

## 四、贴完必须做的一件事：让它复述

贴完三份、打完那句之后，**先别急着学**。加一句：

> 先复述你从我状态卡里读到的：① 我学到哪了 ② 下次开课顺序 ③ 首检题是哪一道。我确认后你再出题。

**这一步是防它读错的唯一办法。** 它读错了你当场能看出来；不核对直接学，学到一半才发现它把进度搞反了，白费一轮。

---

## 五、收工必须把结论带回来

豆包不会写你的看板。**学完让它输出这段**，你复制回来给我（本机 AI），我落账：

```
【收工摘要】
日期（学习日，13:00 之后到次日 06:00 都算同一天）：
科目：
① 过关格：考点编号 / 结果 / 是否撤脚手架
② 未过格：考点编号 / 错在哪 / 根因
③ 新欠账：编号 / 题面 / 下次首检方式
④ 学到哪了 / 下次开课顺序
```

⚠️ **考点编号一定要让它写**（`#P122` `#M040` `#C012` `#E002` `#D02`）——
没有编号，掌握度引擎读不到，这条记录等于白写。

## 六、豆包做不到的三件事（别指望）

| 做不到 | 替代办法 |
|:--|:--|
| ❌ 记住跨对话的进度 | 每次重贴状态卡（这就是为什么要贴） |
| ❌ 读你硬盘上的文件 | 你把文件内容粘进去 |
| ❌ 跑 C 代码 | 它说预期输出 → 你本机 gcc 跑 → 把真实输出贴回去 |

> 💡 **如果哪天想要「真·知识库」**（上传一次、永久复用）：用字节的**扣子 / Coze**（`coze.cn`），
> 它支持知识库上传，可以把 `12-全集-按科/` 整份丢进去。豆包 App 本身没有这个能力了。
