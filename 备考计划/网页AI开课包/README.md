# 🌐 网页 AI 开课包 · 使用说明

> **用途**：在**网页 AI 对话框**（ChatGPT / Claude / Gemini / 任意网页版）里开一节课，不依赖本机的 Reasonix / Studio / 任何脚本。
> **建立日期**：2026-09-17
> **适用**：四科 —— C 语言 · 高等数学 · 计算机基础 · 英语

---

## 为什么需要这个包（先懂限制，再懂用法）

网页 AI 和本机 AI（Reasonix / 我）有**三个硬限制**，整套设计都是绕着它们来的：

| 限制 | 后果 | 本包的解法 |
|:--|:--|:--|
| 🔴 **看不到你的硬盘** | 它读不到看板、开场卡、课本、真题 | **所有资料必须粘贴**。包里的文件就是「该贴的东西」 |
| 🔴 **没有编译器 / 没有你的文件** | 它不能 gcc 实跑，不能查课本 | C 语言：**它说预期输出 → 你在本机跑 → 把真实输出贴回去**。课本：**你用 `textbook.mjs` 查好 → 粘贴** |
| 🔴 **不会写回看板** | 一节课的结论会丢，下次从零开始 | **收工导出模板**：让它输出一段固定格式，你复制回本地存档 |

> ⚠️ **最关键的一条**：网页 AI 每开一个新对话 = **失忆**。所以每次都要重新贴「教练规则 + 状态卡」。
> 这不是麻烦，这是「它不知道你是谁」的必然代价。

## 二、对话怎么规划（**一科一对话，绝不混**）

### 硬规则

| 规则 | 为什么 |
|:--|:--|
| **一科 = 一个独立对话** | 混在一起，AI 会串科、会重复问、上下文很快被塞满 |
| **一节课 = 一个概念**（你已经拍板过） | 「一天可以交很多新概念，但**一次交一个概念**」 |
| **概念过了才开新对话** | 一个对话能连上多节课；但**换科必须换对话** |
| **对话太长（感觉它开始忘事）就重开** | 重开 = 重新贴「教练规则 + 状态卡」，别硬撑 |

### 每轮固定动作（AI 侧，你不用记）

```
读状态卡 → 首检 + 清欠账 → 新课（1 概念）→ 当场 1 题 → 判卷（只认过程）
```

### 🗺️ 「下一课是什么」它怎么知道（**靠状态卡里的全程地图**）

每张状态卡的**第一节都带一张「全程地图」**，把那科的**完整学习序列**列出来，并标好当前位置：

| 标记 | 含义 |
|:--:|:--|
| ✅ | 已过关 |
| 🔴 | 正在进行 / **下一课就是它** |
| ⬜ | 未开 |

**判定规则（写在每张地图开头）**：从上往下扫，**第一个 🔴 或 ⬜ 就是下一课**；但**账没清完不许往下走**。

所以它**不需要**读 Studio、不需要读看板、不需要读课本 —— **「教练规则 + 状态卡（含地图）」就是它的全部上下文**。

> ⚠️ **地图只到「能判断下一课」的粒度就够**，别指望它细化到每节课。
> C 语言细到「1.4-④ 嵌套 if」、高数细到「1-② x→0」，再往后是节级 —— **够用，且不会编错**。
> 它要课本原文时，你本机 `node scripts/textbook.mjs --page N` 查好贴过去即可。

### 你侧的动作只有三件

1. **贴**：教练规则 + 该科状态卡
2. **答**：每题交**过程**，不只交数字
3. **跑**：C 语言题在本机 gcc 跑，把输出贴回去

## 三、喂哪里的资料（三段式：必贴 / 按需贴 / 别贴）

### ✅ 必贴（每开一个新对话）

| 顺序 | 贴什么 | 文件 | 大小 |
|:--:|:--|:--|:--:|
| 1 | **教练规则**（不变） | `0-教练规则-每个新对话都贴.md` | 约 12 KB |
| 2 | **该科状态卡**（会变） | `1-C语言` / `2-高等数学` / `4-英语` / `5-政治` | 8–20 KB |
| 3 | **本章考点原文**（学新章时） | `6-考点原文-按章贴/<科目>/…-第NN章.md` | 20–48 KB |

前两个加起来约 30 KB，任何网页 AI 都吃得下。第三个**只在开新章时贴一次**，之后同一章内继续学不用重贴。

### 📎 按需贴（它问了再贴）

| 场景 | 贴什么 | 怎么拿 |
|:--|:--|:--|
| 它要课本原文 | 谭浩强《C 程序设计》对应段落 | 本机跑：`node scripts/textbook.mjs <概念词>` → 把输出贴过去 |
| 它要真题 | 某年真题 | `历年真题/计算机程序设计/2024.md` 等，**截取单题**贴，别整份 |
| 它要知道我错过什么 | 该科错题本 | `7-错题本-按科贴/<科目>错题本.md`（4–8 KB） |
| 它要考纲 | 21 模块 / 12 章 | `docs/guide/2026考纲全解.md` 或 `高等数学/00-考试大纲与考情.md` |

> 📕 **课本版本必须说清**：考纲指定的是**谭浩强第 5 版**，但本地有全文的 txt 是**第 4 版**（2020.6，ISBN 978-7-302-54404-3）。**引用一律标「第4版第N页」**，别让 AI 以为手上是第 5 版。

### 🚫 别贴

| 别贴 | 为什么 |
|:--|:--|
| ❌ 整份 `学习进度看板.md`（310 行） | 大部分是历史，会把今天的重点淹掉 |
| ❌ 整份笔记 / 讲义库 | **那是弹药库，不是今天的课**（教练手册原话） |
| ❌ `学习日志.jsonl`（26 KB） | 它只需要结论，不需要流水 |
| ❌ 任何 API key / 个人隐私 | 网页 AI 是外部服务 |

## 四、开新对话的完整动作（照抄即可）

**以 C 语言为例：**

1. 打开网页 AI，**新建对话**
2. 复制 `0-教练规则-每个新对话都贴.md` **全文** → 粘贴 → 发送
3. 复制 `1-C语言-状态卡.md` **全文** → 粘贴 → 发送
4. 打一句：**「开始」**
5. 它会复述「你学到哪了 + 下次开课顺序」，**核对一遍**（防止它读错）→ 确认后它出首检题
6. 答题。**每题交过程**，格式：
   ```
   第①道门：条件是 ___，结果是 ___，所以 ___
   第②道门：……
   结论：___
   ```
7. C 语言题：**它说预期输出 → 你在本机跑 gcc → 把真实输出贴回去**
8. 下课时，让它按**收工模板**输出摘要 → 你复制回本地

## 五、收工（把结论带回来，否则这节课白上）

网页 AI 不会写你的看板。**你必须把结论带回来**，否则下次它还是从零开始。

### ① 让它输出这段（模板在 `0-教练规则` 第六节）

```
【收工摘要】
日期：
科目：
本节课内容：
- 过关格：（考点 / 结果 / 是否撤脚手架）
- 未过格：（考点 / 错在哪 / 根因）
- 新欠账：（编号 / 题面 / 下次首检方式）
- 复检队列变动：
- 需要更新看板的话：
```

### ② 你带回来，二选一

| 方式 | 怎么做 |
|:--|:--|
| **省事** | 把摘要贴回**本机 AI**（我 / Reasonix），说「按收工落账」→ 我写进看板 / 日志 / 错题本 / 开场卡 |
| **自己来** | 手动改这四处：① `学习进度看板.md` ② `学习日志.jsonl` 追加一条 ③ `错题本模板.md` ④ `开新话题/<科目>.md` |

### ③ 状态卡要跟着更新

**状态卡是快照，会过期。** 每上完一节课，把 `网页AI开课包/<科目>-状态卡.md` 里的「首检 / 复检队列 / 学到哪了」刷新一遍。

> 🔧 最省事的做法：收工摘要贴回本机 AI，让它**同时**更新看板 **和** 状态卡。

## 🚨 先决定：你的网页 AI 有没有「项目 / 知识库 / 文件上传」

这一步决定你走哪条路，走错就白折腾。

| 平台形态 | 能不能全给 | 怎么给 |
|:--|:--:|:--|
| **有知识库 / 项目 / 文件上传**<br>（ChatGPT Projects、Claude Projects、Gemini Gems、Kimi 文件、扣子/Coze…） | ✅ **能，而且该全给** | 建一个项目 → 上传 `12-全集-按科/` 里**该科那一个 .md** → 以后所有对话共享，不用再贴 |
| **只有对话框**<br>（**豆包**、普通网页版） | ❌ **不能全给** | 每轮贴 `0-` 规则 + 状态卡 + 当节的小文件（`6-` 或 `10-`） |

### 📱 用豆包的话，直接看 `13-豆包-明天怎么贴.md`

豆包有两个硬约束，决定它走不了「全给」这条路：

1. **智能体功能 2026-07-15 已下线** ⇒ 没有持久知识库，每次新对话都是白纸
2. **上下文约 128K token ≈ 8.5 万中文字** ⇒ `12-全集` 里政治一科就 100 万字，超 12 倍

`13-` 那份里已经算好每科该贴哪三份、各多大、贴完该说什么话，照抄就行。
> 想要「上传一次永久复用」→ 改用字节的 **扣子 / Coze**（`coze.cn`），它支持知识库。

### 为什么对话框里塞不下（算给你看）

四科全集合计 **188 万字 ≈ 5.3 MB**，中文约 **1.5 token/字** ⇒ **约 280 万 token**。
单科最大是政治 **99.8 万字 ≈ 150 万 token**。

- 主流网页 AI 上下文：32 K – 200 K token（Claude 200K、GPT 128K、Gemini 100 万–200 万）
- ⇒ **除了 Gemini 顶配，没有一家吃得下政治一科**
- 就算勉强塞进去，也会「上下文污染」：100 万字里今天的重点被淹掉，回答变泛、开始胡说

### ⚠️ `6-` 和 `10-` 的区别（别贴错）

| | `6-考点原文-按章贴` | `10-讲义-按节贴` |

### `8-政治默写-按篇贴/` 怎么用

```
毛中特-篇01-毛1-2-2-毛泽东思想活的灵魂.md    （5–12 KB / 篇）
习概-篇01-习1-2-2-社会主要矛盾变化是关系全局的历史性变化.md
…
```

每个文件分两段：**「一、默写区」只给标签和字数**（比如「总述 135 字 / 定位 91 字 / 含义 31 字」），
**「二、答案区」给原文**。所以网页 AI 能**先抽我默写、再翻答案判分**，不用我另外找答案。

> ⚠️ 一个文件含答案，**先只看「一、默写区」**，默完再往下看。

### `9-真题映射/` 怎么用

AI 讲每个考点前，先查表里「这考点哪年考过、什么题型、几分」，再决定讲多深 ——
**没考过的不值得花 25 分钟，年年考的必须讲透**。这是四标里【真题怎么打】的唯一凭据。

⚠️ **别让 AI 凭记忆说「这个年年考」** —— 要么查这张表，要么明说「这是我的判断，无凭据」。

### `6-考点原文-按章贴/` 怎么用

6-考点原文-按章贴/
  高数/      12 包（第01–12章）
  计算机/    32 包（C 语言 10 章 + 数据结构 8 章，大章已拆成 -1of2 / -2of2）
  政治/      49 包（毛中特 9 章 + 习概 18 章，大章已拆）
  英语/      19 包（E1–E18 语法组 + W1 写作组）

- **单包 20–48 KB（约 7–16 K 字）**，任何网页 AI 都吃得下
- 超过 45 KB 的章已自动拆成 `-1of2` / `-2of2`，**按 1→2 顺序贴**
- 重新生成：`node scripts/export-web-ai-pack.mjs`（考点笔记更新后跑一次即可）

## 附：为什么不用「一个文件包含四科」

试过，**不要**。理由：

1. 一科一对话 → 贴一份含四科的文件 = 3/4 是噪音
2. 状态卡每节课都变，四科挤一份 = 每次都要重贴整份
3. 分开后，改 C 语言不会碰到高数

**规则只写一份（`0-`），状态按科分（`1~5`），资料按章切（`6-`），错题按科切（`7-`）。** 这是唯一不重复又不啰嗦的切法。
