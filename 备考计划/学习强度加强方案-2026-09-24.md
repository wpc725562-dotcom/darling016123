## §1 🔑 先算一笔账：加时间 vs 提密度

**你现在的有效学习量**：

```
名义时长 5h/天 × 推进日密度 55.6% = 有效 2.78 h/天
```

**三条路，效果差很多**：

| 方案 | 名义时长 | 密度 | **有效时长/天** | 相对现在 |
|:--|:--:|:--:|:--:|:--:|
| **现状** | 5h | 55.6% | **2.78 h** | — |
| A · **只加时间** | 6h | 55.6% | 3.34 h | **+20%** |
| B · **只提密度** | 5h | **70%** | **3.50 h** | **+26%** |
| **C · 两个都做** ✅ | **6h** | **70%** | **4.20 h** | **+51%** |

### 🔴 关键结论

> **「只加时间」是最差的一条路**（+20%）—— 因为你有 **44.4% 的天数根本没推进**，
> 加再多时间，断档那几天还是零。
>
> **「提密度」的边际收益比「加时间」更高** —— 而它**不需要你多花时间**，只需要**减少断档**。

**⇒ 本方案按 C 走：6h + 密度 70%。**

## §4 🆕 块 D · 数据结构概念层（30 min/天，启动计划）

**为什么现在能开**（`学习进度看板.md` 数据结构行原文）：
> **「图」提到数据结构第一优先**（真题 4 年 11 题 / 估分 ~20 分）。**但分两层**：
> **概念层（出度入度 / 多对多 / n−1 边 / O(n²)，占图的 45%）现在就能做**；
> **算法层（DFS/BFS/Prim/Kruskal/邻接矩阵）须等 1.6 数组**。

**⇒ 所以块 D 现在只做「概念层」，不碰算法。**

### 4.1 前 20 天的概念层顺序（每天 1 个，30 min）

| 天 | 概念 | 判据 |
|:--:|:--|:--|
| 1–3 | **图是什么**（顶点 / 边 / 有向无向） | 能画一个 4 顶点 5 边的图 |
| 4–5 | **度**（出度 / 入度） | 给一张图能数出每个点的出入度 |
| 6–7 | **完全图**（无向 n(n−1)/2 · 有向 n(n−1)） | 能算 5 个点的完全图有几条边 |
| 8–9 | **稠密图 vs 稀疏图** | 能说出判据 |
| 10–12 | **路径 / 回路 / 连通 / 强连通** | 给图能判断是否连通 |
| 13–15 | **生成树 / n−1 条边** | 能说「为什么 n 个点的树一定 n−1 条边」 |
| 16–18 | **图的存储（概念层）**：邻接矩阵 vs 邻接表 | 能说出各自的**空间复杂度** |
| 19–20 | **时间复杂度记号 O(n²) / O(n+e)** | 能对应到上面两种存储 |

> ⚠️ **不碰**：DFS / BFS / Prim / Kruskal 的具体算法 —— **等 C语言 1.6 数组**。

### 4.2 为什么是 30 min 而不是 60

**认知负荷**：块 D 是**新科目**，且和你现在的 C语言 有交集但不等同。
**30 min 是「每天能持续」的量** —— 一次 60 min 你会在第 3 天放弃。

## §6 ⚙️ 强度提升的四个机制（不只是加时间）

### 机制 1 · 密度从 55.6% 提到 70%

| 做法 | 具体 |
|:--|:--|
| **允许断 1 天，不许连断 2 天** | 连续 2 天无推进 → 触发「最小启动」= **只做 25 分钟、只做 1 题** |
| **周日仍然休息** | 但**周六轻量日不许跳过**（Anki + 复检 + 排期） |
| **断档当天记一笔** | 写进日志（`kind: feedback`），周末自查时看 |

### 机制 2 · 工具时间归零（省出 13%）

**实测：工具 + 综合占 13.0% 的时间，换 0 分。**

| 做法 | 具体 |
|:--|:--|
| **封刀** | 任何「改工具 / 写脚本 / 加面板」的念头 → **只记进待办** |
| **统一处理** | **周六 30 分钟**一次性处理待办 |
| **例外** | 只有「工具坏了挡住学习」才当场修（如 gcc 路径漂移那种） |

### 机制 3 · 每晚 5 分钟自检（从每周改成每天）

| 看什么 | 目标 |
|:--|:--|
| 今天推进了吗 | ✅ / ❌ |
| 英语阅读 + 完形做了吗 | 篇数 |
| 数据结构概念做了吗 | ✅ / ❌ |

**写在同一个地方，周末汇总。**

### 机制 4 · 睡前 10 分钟（睡眠巩固）

把当天新学的东西过一遍（C语言概念 / 高数公式 / 数据结构概念）。
**睡眠期间大脑会把短期记忆转长期** —— 这 10 分钟的性价比**高于白天多刷 20 分钟**。

## §7 ⚠️ 过载信号 + 降档机制（很重要）

**加强强度最大的风险不是「做不到」，是「硬撑到崩」。**

### 7.1 出现下面任意两条 → 当天降到标准档（5h）

| 信号 | 说明 |
|:--|:--|
| 同一个概念**讲 2 遍还不懂** | 不是讲法问题，是今天状态不行 |
| **错题率突然翻倍** | 疲劳的典型信号 |
| **一道题卡超过 15 分钟** | 项目既有纪律是 10 分钟 |
| **连续 3 天睡眠 < 6h** | 睡眠是记忆巩固的前提 |
| **开始频繁想「改工具」** | 🔴 这是逃避信号（工具占 13% 就是这个原因） |

### 7.2 降档不等于放弃

```
降档：6h → 5h（保留 A / B / C 的核心，砍 D 和 F）
最小启动：只剩 25 分钟 → 只做「英语阅读 1 篇 + Anki 20 张」
```

**红线：不许降到零。** 项目实测：**断 4 天，Anki 到期量涨了 184 张**。

## §10 一句话

> **「加强强度」的正确做法不是「每天多坐 1 小时」，而是：**
> **① 把密度从 55.6% 提到 70%**（+26%）
> **② 把工具那 13% 收回来**（+13%）
> **③ 才谈加时间**（+20%）
>
> **三条加起来 = +51% 有效学习量**，而其中**两条不用你多花一分钟**。

## 附：本方案的算法来源

```
有效时长 = 名义时长 × 推进日密度

现状：  5h × 0.556 = 2.78 h
只加时间：6h × 0.556 = 3.34 h  (+20%)
只提密度：5h × 0.700 = 3.50 h  (+26%)
两个都做：6h × 0.700 = 4.20 h  (+51%)
```
