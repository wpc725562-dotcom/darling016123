## 二、系统缺陷：五条，每条都有硬数字

### 缺陷 1 🔴 掌握度引擎的「key」选错了对象 —— 这是三条缺陷同一个根因

`tools/check-mastery.mjs` 实跑结果：

```
日志 178 条；quiz 91 条
考点键（key）总数      145
  只有失败记录         125   ← 永远过不了门（GATE 0.9）
  只有成功记录          20
  成败都有               0   ← 关键：一个都没有
  已过关（≥0.9）         0
```

引擎的门槛是 `GATE=0.9` + `CONF_CAP={1:0.5, 2:0.8}` ⇒ **同一个考点必须被记录 ≥3 次才可能过关**。
那问题就变成：**同一个考点被记录过几次？**

实测两个候选 key 的重复率：

| 用什么当 key | 键数 | 出现 ≥2 次的 | 重复率 |
|:--|--:|--:|--:|
| **自由文本考点名**（引擎现在用的） | **328** | **2** | **0.6%** |
| **`#Cxxx` 稳定编号**（库里已有） | **5** | **4** | **80%** |

**130 倍差距。**

`#C002 / #C004 / #C006 / #C007` 的日期分别是：

```
#C002  ×3   09-10, 09-13, 09-14
#C004  ×3   09-14, 09-14, 09-14
#C006  ×3   09-15, 09-19, 09-19
#C007  ×3   09-19, 09-19, 09-20
```

跨天的、可追踪的、能累积的 —— **编号是唯一符合"同一个考点"语义的键**。它本来就在库里（Anki 卡片号 / 错题本编号），只是引擎没读。

⇒ 结论：**「33 个考点 · 过关 0 个」既不是学生没掌握，也不是引擎算错 —— 是引擎用了一个天然不可能重复的 key，然后要求它重复 3 次。**

### 缺陷 2 🔴 复检做了 53 次，但一次都没被系统认出来

```
含「复检 / 复测 / 重做 / 销账 / 复述」字样的日志：53 / 178 条
```

**复检确实在做**，做得很勤。但复检时写的是**新的描述**，而不是复用第一次的考点名：

```
第一次（09-10）：weak = "C-for循环"                    title = "for 循环三件套"
复检（09-14）：  weak = ""                              title = "for(i<=3) 第三次重做（#C002 销账）"
```

⇒ 系统看到的是两个不相关的记录，而不是"同一考点第 2 次测量"。

> 🔴 **这个病库里治过一次**：2026-10-04 标签治理 —— 脚本报 121 标签/83 单次，独立复核真实 251/202 单次，于是建了 `scripts/tags-vocabulary.mjs`（受控词表）+ `normalize-tags.mjs` ⇒ 251 → 39 个标签。
> **同一套模式没有用到考点上。** 这是同一个病第二次出现，而且这次代价更大（直接让掌握度归零）。

### 缺陷 3 🟡 引擎丢掉了 89 条人工判定，还分裂成两套命名空间

同一批日志里，**`mastery` 字段的分布是**：

```
quiz 89 条有明确判定：passed 37 / partial 35 / failed 17
```

**引擎完全没用 `mastery`。** 它只用正则从 `score` 里抠 `x/y`，而 `score` 是自由文本（`"部分"`、`"过关：轮次1输出 9 ✅ …"`、`"当时未判卷（无记录）"`），91 条里 **25 条抠不出来**，其中 **23 条其实有人工判定**。

再加上：

```
答错 → 记到 weak 里的考点名  （"C-for循环"）
答对 → 记到 title 的会话描述（"for(i<=3) 第三次重做（#C002 销账）"）
```

两套命名空间，同一个考点的"错"和"对"永远落不到同一个 key 上 —— 这正是「成败都有 = 0」的成因。

另外：**全对但顺手写了 weak 的日志有 8 条**，这些「答对了」的事实**不产生任何 ok:true 记录**，只把 weak 又记一次失败。

### ⇒ 三条合起来的修法（一条，不是三条）

```
key    ：优先取 title/note 里的 #Cxxx / #Mxxx / #Exxx 编号
         （没有编号才回退到 weak 的考点名，并打警告）
判据   ：优先用 mastery 字段（passed=1 / partial=0.5 / failed=0）
         （没有 mastery 才回退到 score 正则）
显示名 ：weak / title 只作显示，不参与聚合
```

**成本约半天，收益是"掌握度清单"从 0 变成可用。** 不修的话，往后每做一次复检都是白记 —— 这是"漏水时先堵漏"。

## 三、AI 教学：证据说什么，现在偏在哪

### 3.1 先纠正一个流行说法

「一对一辅导能提两个标准差（Bloom 2 sigma）」被大量 AI 教育产品当卖点。实查 von Hippel（*Education Next*, 2024-03）对原始研究的拆解：

| 来源 | 效应量 | 说明 |
|:--|:--:|:--|
| Bloom (1984) 主张 | **2.00 σ** | 第 50 → 98 百分位 |
| Cohen/Kulik/Kulik (1982) 元分析 65 项 | **0.33 σ** | 其中窄测 0.84、广测 0.27 |
| Nickow 等 (2020) 元分析 96 项 | **0.37 σ** | **0 项**达到 2σ |
| Kraft (2020) 一般教育干预 | ≤ 0.1 σ | 基准线 |

方法学问题：2.0 的证据只来自两篇博士论文、小样本、**从未被复制**；测的是**三周后窄测**；辅导组还额外获得订正反馈+重测、教师培训、替代式授课（不上常规课）、每周多 1 小时。

### 3.2 但拆解里有一条对我们极其重要

Anania/Burke 实验内部拆开：

```
辅导组 vs 全班        ≈ 2.0 σ
mastery learning 组 vs 全班 ≈ 1.1 σ   ← 约一半来自「测试 + 反馈」
剩余归于辅导本身       ≈ 0.9 σ
```

⇒ **「测试-反馈循环」贡献了整个效果的一半，而且它是可以廉价复制的部分。** AI 的天然契合点在这里，不在"模拟人类讲课"。

原文对 AI 的三条判断（直接引用其结论）：

1. **尚无任何已发表的 chatbot 辅导效应证据**，直接许诺 2σ 是草率
2. **LLM 单独教数学会「quickly get lost」** —— 必须把自然语言能力和**可靠的形式化知识库**（题库、真题、教材）结合
3. **不要"过度帮忙"** —— 替学生完成任务的短期提分会剥夺长期收益

### 3.3 所以现在偏在哪

| 精力投向 | 现状 | 证据指向 |
|:--|:--|:--|
| **讲**（讲义、多源对比、知识地图） | 1,144 篇 md / 158 篇笔记 / 17 份多源对比 / 1,138 条考点地图 / 1944 万字字幕 | 讲 ≠ 高效，**重读与划线在 Dunlosky 表里是"低效用"** |
| **测 + 反馈** | 272 道练习题（但带做例题 0）· 复检队列 **88 条过期** · 掌握度引擎**记不进去** | **这是贡献一半效果的部分，却是唯一断掉的部分** |

**一句话**：系统把 80% 的工程量投在「把知识讲清楚」，而证据说「讲清楚」的边际收益远低于「测出来 + 改对」。而恰好「测出来」这条链是断的（缺陷 1/2/3）。

### 3.4 可执行的六条（按投入产出排序）

| # | 动作 | 对应证据 | 成本 |
|:--:|:--|:--|:--|
| 1 | **修掌握度引擎**：优先读 `mastery`，`weak` 走受控词表，`title` 不再当考点键 | 缺陷 1/2/3 | 半天 |
