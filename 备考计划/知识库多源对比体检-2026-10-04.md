## §3 三个结构性问题（比内容缺口更要紧）

### 3.1 🔴 高数源库 = 定时炸弹（2026-09-17 发现，**至今未修**）

| 项 | 源库 `高等数学/` | 站上 `docs/posts/math/notes/` |
|:--|:--|:--|
| 篇数 | **55** | **73** |
| 编号 | `1.1`×2 · `1.3`×2（**撞车**） | `1.1a` / `1.7a` / `1.13a`…（唯一） |
| index.md | 脚本会**重新生成并覆盖** | 手写 ⭐ 阅读顺序表（**6 处**） |

**跑 `npm run docs:sync` 的后果**（`scripts/sync-obsidian-to-blog.mjs` 的 `syncMathNotes()`）：
1. 按源文件名推 slug ⇒ 生成 **2 个旧编号的重复笔记**（`1.1-函数的连续性` 之类）；
2. **覆盖 `index.md`** ⇒ 丢掉手写的 ⭐ 阅读顺序表与编号说明。

**✅ 好消息**：`git log` 显示**从没跑过 sync**（最近一次是「清掉 89 处死链 —— 高数笔记改名残留 78」），炸弹还没爆。

**修复选项**（**均需 darling 拍板**，见 §6）：
- **A（稳）**：给 `syncMathNotes()` 加一张「源文件名 → 站上 slug」映射表，源库不用动；
- **B（彻底）**：把源库 55 篇重命名 + 回填站上独有的 18 篇，让源库重新成为事实源。

### 3.2 🟡 计算机笔记没有源库 —— 只有站上可编辑

`syncComputerNotes()` 找 `计算机程序设计/`，**该目录不存在** ⇒ 脚本主动跳过（防「空索引覆盖 40 篇入口」）。
**实测**：`docs/posts/computer/notes/` **53 篇，53 篇全部已 git 跟踪** ⇒ **不是「无备份」，是「没有可编辑的源库」**。

## §7 数据复现命令

```bash
# 源口径统计（广东占比）
#   高数：BV1vm421s7mv(678,940) + BV1xxXZBKENv(20,881) = 699,821 / 5,025,583 = 13.9%
#   计算机：BV1Ye411Y7Ue(193,638) + BV1KU4y167ds(191,568) + BV1Z4w3znE6h(38,065) = 423,271 / 4,058,466 = 10.4%
#   英语：731,535 / 12,112,417 = 6.0%   （广东 9 源合计，见总索引 §3.2）
#   政治：57,907 / 57,907 = 100%

# 源引用统计（排除索引类文档）
for bv in $(ls -1 data/bili-analyze/ | grep "^BV"); do
  n=$(grep -rl "$bv" 备考计划 docs --include="*.md" \
      | grep -vE "B站网课资源总索引|B站资源利用率|B站视频管道诊断|本地学习资料地图|本地资料索引|本地txt梳理" | wc -l)
  echo "$n $bv"
done | sort -n

# 高数源库编号撞车
find 高等数学 -name "*.md" | sed 's#.*/##' | grep -oE "^[0-9]+\.[0-9]+" | sort | uniq -d

# .bak 统计
find . -name "*.bak*" -not -path "*/node_modules/*" -not -path "*/dist*" -not -path "*/.git/*" | wc -l
```
