# 🧾 讲解覆盖表（Rule Coverage Sheet）

> **用途**：**每讲一个概念，当场填一张**。填完才允许出题。
> **由来**：2026-09-25 学生指出「你在讲课中经常遗漏知识点」—— 诊断发现**不是记性问题，是流程缺环**：
> 我出题时检查的是「**这个概念讲过吗**」，而该检查的是「**这条规则讲全了吗**」。
> **判据太粗 ⇒ 漏讲抓不住。**
>
> **⚠️ 这张表是「机械化动作」，不是「自查一下」** ——
> 手册早有明文：「不是『自查一下』，是**列出来逐个勾**」（因为靠自觉已失效 ≥6 次）。

### 🔴🆕 「应试深度」列（**2026-09-26 新增 · 学生问「这个是不是太过了」后补**）

**讲每条规则前，先查真题：这一条【考到什么程度】？**

| # | 规则 | 真题考法 | **要讲到什么深度** | 可以省掉什么 |
|:--:|:--|:--|:--|:--|
| | | | | |

> **判例（09-26 `strcmp`）**：我把「逐位比 ASCII 的过程」讲得很细，
> **但真题实查只考两处**：① **2024 第 2 题**「使用 `strcmp` 需要包含的头文件是」→ **`string.h`**
> ② **2023 第 18 题**「字符串**连接**函数是」→ **`strcat`**（辨析题）。
> **⇒ 真题从没考过「逐位比 ASCII」** ⇒ **那部分属于「懂原理」，不是应试必需。**
> **⇒ 判据：先给「应试必需」，再问学生「要不要深挖原理」。不要默认讲到底。**

### 🔴🆕 「前置技能」列（**2026-09-26 新增 · 踩坑后补**）

**出每道题时，问一句：算这道题需要几步？每一步的前置技能他学过吗？**

| 题号 | 需要几步 | 每一步的技能 | 学过吗 |
|:--:|:--:|:--|:--:|
| | | | ☐ |

> **判例（09-26）**：关口题「$\beta_2/\beta_1$ 的极限」**需要两步** ——
> ① **代数：提公因式 + 约分** ② 极限：代入。
> **我没检查「他能不能一次做两步」就出了** ⇒ 学生反馈「**看不懂**」。
> **⇒ 判据：一次只出「一步题」。要两步的，先拆。**

**规则条数：____ 条**（**先数出来** —— 数不出来说明这个概念没想清楚）

## 三、出完题后的自检（**新增 · 2026-09-25**）

**把这道题按「四要素」自己走一遍**（教练手册 §2.0.9）：

| 要素 | 走通了吗 |
|:--|:--:|
| **① 条件前提** —— 这一步成立需要什么条件 | ☐ |
| **② 已知信息** —— 这一步用到了什么 | ☐ |
| **③ 适用场景** —— 什么时候能用 / **不能用** | ☐ |
| **④ 隐含假设** —— 背后假设了什么 | ☐ |

> **🔴 走不通的那一步，就是「我漏讲的」那一步。**
> **判例（09-25）**：第 ③ 项走不通 —— 我没讲「补 0 的起点」，所以学生答不出 `\0` 在第几格。

## 四、三种漏讲的形态（**对照自查**）

| 形态 | 长什么样 | 判例 | 隐蔽度 |
|:--:|:--|:--|:--:|
| **① 完全没讲就出题** | 用了没教过的语法 / 概念 | 09-15 出 `printf("%d", a=3)`（用到未教的「赋值表达式本身也有值」）；09-20 出十字相乘 | 🟡 中 |
| **② 讲了结论、没讲推理链** | **规则说了一半** | **09-25 两次**：花括号+不写长度 = 没有 `\0` / 补 0 从哪一格开始 | 🔴 **最隐蔽**（因为「看起来讲了」） |
| **③ 讲了但没给边界** | 没说「什么时候不适用」 | 等价无穷小（加减不能用）—— **学生主动追问才发现** | 🔴 高 |
| **④ 凭印象写数字 / 页码** | 没跑 gcc、没查课本 | 09-14 四笔（`%5d` 空格数 / 备题答案 / 页码） | 🟡 中 |

## 🔴🆕 「提及过 ≠ 讲过」—— 前置技能检查的陷阱（**2026-09-26 新增 · 学生指出后补**）

> **学生原话**：「**`gets` 你只提及了一下并没有教学**，这个符号的作用教学一下」

### 判例

**我在块 F 的覆盖表里，把 `gets` 标成了「前置技能：✅ 今天（6.4.4）」—— 但那是错的。**

**实际情况**：
- **6.4.4 我讲的是「`%c` vs `%s`」** —— **没讲 `gets`**
- **`gets` 只在「表 6.1」里出现过一行**（「从终端输入一个字符串到字符数组」）—— **那是「提及」，不是「讲」**
- **⇒ 但我打勾时，把「在表里列过」当成了「讲过」**

### 🔴 判据（打勾前必须过这一关）

| 状态 | 定义 | 能打勾吗 |
|:--|:--|:--:|
| **提及过** | **只在表格/列表里出现过名字 + 一句话功能** | ❌ **不能** |
| **讲过** | **有独立讲解：是什么 + 怎么用 + 陷阱 + 配一道题** | ✅ 能 |

**⇒ 打勾时问自己一句：「我能说出它的**陷阱**吗？」**
**—— 说不出来 = 只是「提及过」，必须补讲。**

### 判例的代价

**`gets` 真题命中 31 次**（**比 `strcpy` 的 20 次还高**）——
**而我把它当「已讲过」，差点让一个高频考点漏掉。**

## 五、三张检查清单（讲前 / 讲中 / 讲后）

### 📋 讲前（备课，5 min）

- ☐ **这个概念有几条规则？**（数出来写下来）
- ☐ **每条规则的「适用 + 不适用」都准备好了吗？**（不适用必须有一个反例）
- ☐ **每条规则的推理链能不能一步步走？**（不能跳步）
- ☐ **今天要考的题，考的规则在第几条？**

### 📋 讲中（随堂）

- ☐ 每讲一条规则，**立刻给一个「不适用」的反例**（不是我讲完就算）
- ☐ 讲完一节，**主动问「这一节里有没有哪句话你看不懂？」**（09-14 立的规矩）
- ☐ 讲完一节，**让学生复述「这条规则什么时候不能用」**（不是复述「是什么」）
- ☐ **把「规则表」填完**（这是讲完的标志）

### 📋 讲后（出题前，不可跳）

- ☐ **题面里每个符号 / 规则写成一行，逐个打勾**
- ☐ **打不上勾的 → 撤题或补讲**
- ☐ **自己按四要素走一遍**（走不通 = 没讲全）
- ☐ **题面里的数字/答案跑一遍 gcc 或 node**（不凭印象）

## 七、为什么「靠自觉」不管用（**实证**）

**「没教过就出题」这条规矩立过，但仍犯 ≥6 次：**

| 日期 | 事件 |
|:--|:--|
| 09-10 | 只教了三层框架就考 `for` 循环 |
| 09-15 | 出 `printf("%d", a=3)`（未教「赋值表达式的值」） |
| 09-20 | **立过同一条规矩，10 分钟后即违反** |
| 09-25 | **两次**（花括号+不写长度 / 补 0 的起点） |

> **⇒ 结论：对「出题前的覆盖检查」这类问题，写规矩这条路已被实证判为不够。**
> **必须换机制：把「需要自觉」的动作，换成「机器/表格强制」的动作。**
> **这张表就是那个机制 —— 填不出表就不能出题。**
