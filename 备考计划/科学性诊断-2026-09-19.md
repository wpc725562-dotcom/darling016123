# 🔬 科学性诊断报告 · 专升本项目

> **诊断对象**：`备考计划/` 全部文档 + `学习日志.jsonl` + 错题本 + 教练手册 + 复盘档案  
> **诊断日期**：2026-09-19 · by 02  
> **诊断方法**：文档全文通读 + 日志 38 条逐条统计 + 数据交叉核对（错题本统计表 vs 实际编号、看板进度条 vs 日志条数）

## 0. 结论先行

### 这个项目真正的身份

它**不是**"学习方法分享"，是 **single-case design（单被试实验设计，n=1）的自我实验 + mastery learning（掌握学习）**。

这个身份一旦说清，下面所有问题都变得可解 —— 因为这两套方法论**各自有成熟规范**，而项目目前是"用对了直觉，用错了语言"。

| 项目现状                     | 真正的方法论归属                                               | 差距                     |
| :----------------------- | :----------------------------------------------------- | :--------------------- |
| "同型连对 2 次算过关"            | mastery learning 的 **criterion-referenced assessment** | 缺判据版本管理                |
| "09-09 50% → 09-10 100%" | SCED 的 **A-B 设计**                                      | 缺基线稳定期、缺重复测量           |
| 置信度封顶 0.5/0.8            | 贝叶斯知识追踪（BKT）的**参数先验**                                  | 参数是拍的，未拟合              |
| Anki 排程                  | 间隔重复算法                                                 | 已正确使用（FSRS 未开，SM-2 在跑） |

### 🔴 三个最严重的问题（按危害排序）

1. **判据漂移（criterion drift）** —— 过关标准在 5 天内从「1 次」改到「2 次」再改到「≥3 次处分」。这是 **HARKing**（事后假设）。后果：**标准永远在靶后画，项目永远不会"过关"**。证据：教练手册 76–81 行、看板 288 行。
2. **投入与权重严重错配** —— 计算机 200 分（40%）里，数据结构 **0 条日志**；政治 100 分 **0 条日志**；英语 100 分只有 3 条（且 2 条是 Anki 工具记录）。而日志 38 条里 **C 语言独占 22 条（57.9%）**。证据：日志实测统计。
3. **"缺测"被静默当成 0** —— 09-16、09-17、09-18 **三天零记录**（日志文件 mtime 停在 09-15 14:50），但看板进度条**照常显示 32%**，没有任何机制提示"这三天是没学，还是没记"。证据：`学习日志.jsonl` + 看板 263 行。

### ✅ 五个最不该改的好实践（改了就亏）

1. **「只给数字不给过程 = 按错题重做」** —— 这是**过程性评价**的正确实现，比多数教育产品做得好。
2. **「相邻两题答案刻意错开」** —— 这是**探针式测量设计**，用来抓"搬上一题答案"。成本极低、判别力极高。
3. **「答案栏与理由栏互证检查」**（看板 288 行 #C006）—— 这是**双通道一致性检验**，比单看对错更早抓到"跳过计算"。
4. **「写进看板的标准答案必须有 gcc 凭据」** —— 这是**可复现性要求**。同类项目几乎没有。
5. **「Anki 数据不认自报，直读 revlog」** —— 这是**拒绝自我报告偏差（self-report bias）**。极其正确。

## 1. 研究设计（Research Design）

### 1.1 设计类型未声明，导致所有"显著"语言错位

**问题**：项目在描述效果时用了大量准统计语言 ——「缺口已闭合」「50% → 100%」「判据有洞」。但 n=1、无控制组、无随机化，这些数字**不具备频率学派的统计含义**。

**证据**：看板 120 行「高数 6 题 100/100 → 缺口已闭合」；看板 276 行「09-10 已 100%」。

**修改方向**：在 `教练手册-教学纪律.md` 顶部加一节「设计声明」，明确写：

> 本项目的设计类型是 **A-B 单被试设计（single-case A-B design）**，不是随机对照试验。所有百分比只在**同一份题卷内部**可比，**跨日期、跨题卷的百分比不可直接比较**。

**评估标准（可判定）**：

- [ ] 文档中出现「已闭合 / 已过关」时，同句必须给出**题卷编号 + 题目数 + 是否同题重测**三个信息
- [ ] 禁止出现「显著 / 明显提升」等统计术语（除非给了检验统计量）
- [ ] 每个百分比必须能追到「哪天、哪份卷、几题」

---

### 1.2 因变量操作化不完整：「学习量」这个核心变量没有定义

**问题**：项目有「学习量」这个概念（看板 237 行「09-13 学习量终于不再是 0」），但**从来没有定义它怎么算**。

实测日志统计（38 条）：

| kind       |  条数 | 算不算学习量？            |
| :--------- | :-: | :----------------- |
| `quiz`     |  24 | ✅ 算                |
| `lecture`  |  5  | ✅ 算                |
| `anki`     |  2  | ✅ 算                |
| `feedback` |  2  | ⚠️ 模糊              |
| `tool`     |  5  | ❌ 明确不算（教练手册 120 行） |

而 `mastery` 字段里有 **10 条 `na`** —— 这些记录**混在日志里**，会被任何"按行数统计"的口径算进去。

**证据**：`学习日志.jsonl` 实测；教练手册 120 行「`kind:"tool"` 一律不算学习量」。

**修改方向**：

1. 在 `每日学习日志模板.md` 里写死定义：**学习量 = `kind ∈ {quiz, lecture, anki}` 的记录数**，`tool` / `feedback` 不计。
2. 给日志加一个**必填字段** `counts_as_study: true/false`（或直接在写入时就不写 tool 记录进日志，改写到单独的 `工具日志.jsonl`）。

**评估标准**：

- [ ] 任意一天的学习量能被**一条命令**算出，且结果与人工数一致
- [ ] `tool` 记录不再出现在 `学习日志.jsonl`（或已明确标注不计）
- [ ] 看板顶部显示「今日学习量：N 条（quiz 2 / lecture 1）」，N 由脚本算，不手写

---

### 1.3 没有前测/后测的同一量表 → 学习效应与题目难度混淆

**问题**：09-09 高数 4 题 20/40（50%）→ 09-10 高数 6 题 100/100。项目判定为「缺口已闭合」。

但这**不是同一个测量**：

- 题目数不同（4 vs 6）
- 其中 3 题是**上一轮欠交题的重做**，且**答案已在演示中泄露**（看板 246 行明确记载"原题答案已在本话题演示中泄露"）
- 时间隔了一晚，中间还发生了教学干预 + 自然遗忘

**结论**：这 50% → 100% 的变化里，**学习效应、题目难度差异、答案泄露、时间间隙**四个因素混在一起，无法分离。

**证据**：看板 108 行（首测 20/40）、看板 120 行（复测 100/100）、看板 246 行（答案泄露自述）。

**修改方向**：采用 SCED 的标准做法 —— **同一量表重复测量**：

1. 建一个**固定的"锚题池"**（每科 6–8 题，覆盖已过关考点），**每次开课都跑一遍同样的锚题**。
2. 锚题**永不讲解、永不说答案**，只在测量时用。
3. 新教学内容用新题，但**锚题分数作为唯一可跨日比较的指标**。

**评估标准**：

- [ ] 存在一份 `备考计划/锚题池-<科目>.md`，题目固定、答案另存
- [ ] 连续 3 次开课都有锚题成绩，且题目完全相同（可用文件 hash 验证）
- [ ] 看板的"进度"叙述改为「锚题 X/8（上次 Y/8）」，而不是跨题卷比百分比

### 1.4 缺泛化测量（transfer test）

**问题**：所有判据都是「**同型**连对 2 次」。同型题测的是 **near transfer（近迁移）**，无法证明 far transfer（远迁移）—— 而考场考的是后者。

**证据**：教练手册 78 行「同型连对 2 次」。

**修改方向**：每个考点过关后，**7 天内**至少做 1 道「**未教过的变式题**」（换情境、换表述、混合其他考点）。

**评估标准**：

- [ ] 进度条里每个"已过"格子，都有 1 条变式题记录（否则标记为「未验迁移」）
- [ ] 变式题答对率单独统计，与同型题分开报（两者差值 = 迁移损耗）

**问题**：`目标分拆解-410.md` 第 66 行明确写「**四科都不能有短板**」，且给了均衡目标（政治 80 / 英语 75 / 高数 85 / 计算机 170）。但实际日志：

| 科目                   |  满分 |  占比 | 目标分 | **日志条数** | 实际投入占比 |
| :------------------- | :-: | :-: | :-: | :------: | :----: |

**评估标准**：

- [ ] 每科 7 日滚动投入占比，与分值占比的偏离 < 15 个百分点（政治在 12 月前豁免，但必须有"结构分析"记录）
- [ ] 数据结构在 11 月底前有 ≥1 条日志
- [ ] 连续 7 天某科为 0 → 看板出现显式警告（不是靠人记得）

## 2. 方法选择（Method Selection）

### 2.1 判据漂移 = HARKing（最严重）

**问题**：过关判据的演化史：

| 时点      | 判据                  | 触发事件                         |
| :------ | :------------------ | :--------------------------- |
| 09-10 前 | 正确率 ≥60%            | 初始设定                         |
| 09-14   | 改为「同型连对 2 次 + 人工检查」 | 8 题 81% 但他仍说"看不下去"（看板 284 行） |
| 09-15   | 新增「答案与理由矛盾一律按未过」    | #C006 两手打架（看板 288 行）         |
| 09-15   | 新增「阶梯题必须逐门报编号」      | 同上                           |

**为什么这是问题**：判据**每次都是在看到失败数据之后**才加的。这叫 **HARKing（Hypothesizing After the Results are Known）**。后果是**结构性的**：

> 判据永远比失败晚一步 → 永远有新洞 → 永远"还没过关"。

这不是"持续改进"，这是**把失败包装成方法论升级**。项目自己在看板 78 行留了一句关键话：

> 「**判据本身错了，所以"不退回"这个决定也没有意义。**」

这句判断是**对的**，但没有被推到结论。

**修改方向**：

1. **冻结判据**：把当前判据写成 v1.0，标 `effective_from: 2026-09-19`，**30 天内不许改**。
2. **旧数据按旧判据判定**，不追溯重判。
3. 要改判据，必须走一个**书面流程**（见下）。
4. 关键：**先定判据，再做实验**。而不是做完实验发现判据不行。

**评估标准**：

- [ ] `教练手册-教学纪律.md` 的判据章节有 `version` 和 `effective_from` 字段
- [ ] 每次改判据留下四件事：**改前判据 / 改后判据 / 触发事件 / 受影响的历史结论清单**
- [ ] 同一判据 30 天内改动 ≤1 次（超过则说明判据粒度太细）
- [ ] 存在一份「判据变更日志」（可放在教练复盘档案，但必须单列）

### 2.2 进"已过"的门槛（n=1）低于"稳定"的门槛（n=2）→ 进度条系统性高估

**问题**：看板 259 行定义进度条口径是「该考点**撤掉讲义/表格后独立做对**」，**没写要做对几次**。于是 ⑤⑥⑦⑧ 四个格子**全是 n=1**，却都计入了 32%。

而同一行的注释又写「⚠️ ⑥⑦⑧ **当日 n=1**，09-16 起换同型复检」。

**即：进度条用了低门槛（1 次），注释用了高门槛（2 次）来警示。结果是进度条比实际掌握度高一截。**

**证据**：看板 259 行（口径未写 n）、263 行（8 格中 4 格 n=1）。

**修改方向**：进度条改成**双列**：

| 状态         | 门槛                  | 是否计入百分比  |
| :--------- | :------------------ | :------- |
| 🟡 **待复检** | 撤脚手架后独立做对 1 次       | ❌ 不计入    |
| 🟢 **已过关** | 同型连对 2 次，**且跨不同日期** | ✅ 计入     |
| 🔵 **已稳固** | 过关后再 1 道变式题答对       | ✅ 计入，单独标 |

**评估标准**：

- [ ] 进度条百分比只统计 🟢 及以上
- [ ] 每个 🟢 格子必须能追到**两个不同日期**的做题记录
- [ ] 看板显示形如「32%（8 格中：🟢5 / 🟡3）」，而不是单一数字
- [ ] 若按新口径重算导致百分比**下降**，如实显示下降（不许"平滑过渡"）

### 2.3 缺预注册（pre-registration）

**问题**：所有判据、阈值、测量方式**都是事后定的**。这让 §2.1 的漂移无法被察觉 —— 因为没有"我原本打算怎么测"的参照。

**修改方向**：每轮开课前写 4 行「**本轮预注册**」，课后对照：

```
## 本轮预注册（2026-09-XX）
- 假设：<我认为他会/不会 X>
- 判据：<什么算过>
- 预期结果：<我猜正确率多少>
- 如果不符合预期，我改什么：<预先声明>
```

**评估标准**：

- [ ] 存在 `备考计划/预注册/` 目录，每轮一个文件
- [ ] 每次课后对照：假设命中 / 未命中 / 判据需改（**改判据必须走 §2.1 流程**）
- [ ] 连续 5 轮的"假设命中率"可统计（这是教练自己的校准曲线）

> 💡 这条是**成本最低、收益最高**的改动。写 4 行字，就能把 HARKing 挡在门外。

---

### 2.4 循环论证的双标

**问题**：项目**正确地**判定学生答「因为这是 scanf 语句」= 循环论证（教练手册 73 行）。但项目自己在做**同型推理**：

> `grep` 真题搜「ASCII / 大小写 / 字符的编码」→ **命中 0 条** → **结论：不要求背**（看板 243、287 行）

这是 **argument from absence（以不存在为据）**。0 次命中只能推出「未以该术语出现」，**推不出「不考」**。

**关键**：这个推理**碰巧是对的**（因为补了「考研常规 + 考纲没提」两条旁证），但**推理形式是坏的**。同一份文档里，学生的循环论证被判错、教练的 argument from absence 被当结论 —— 这是**双标**。

**证据**：教练手册 73 行 vs 看板 243/287 行。

**修改方向**：所有「没找到 → 不考 / 不重要」的推理，**必须同时写出反证方式**：

| 结论            | 现有依据      | 必须补的反证方式                                        |
| :------------ | :-------- | :---------------------------------------------- |
| ASCII 编号表不要求背 | grep 0 命中 | 逐题人工归类八份真题，看是否有题**隐含**需要编号表（如"已知 'a'=97，求 'd'"） |

**评估标准**：

- [ ] 全文搜索「不考 / 不要求 / 不重要」，每处都紧跟一行「反证方式：…」
- [ ] 存在一份「真题逐题归类表」（见 §3.1），这是反证的执行载体

---

### 2.5 缺独立校准（评分者 = 受训者 = 受益者）

**问题**：判据由教练（AI）制定 → 教练自己判卷 → 教练的表现由学生评价 → 学生的进度由教练汇报。**闭环，无外部锚点**。

这不是道德问题，是**测量问题**：自我评分的偏差无法被自己发现。

**修改方向**（成本可控的三条）：

1. **外部锚点一：真题标准答案**。每次判卷后，把学生的答案与**官方/教辅标准答案**比对（不是教练自己算的答案）。C 语言有 gcc，天然是外部锚点 —— **这是项目最强的一环，应推广**。
2. **外部锚点二：间隔盲评**。同一份答卷，隔 24 小时再判一次，两次判定不一致的条目**单独列出**（这叫 intra-rater reliability）。
3. **外部锚点三：学生反向评分**。每周让学生给教练打分（题目是否超纲 / 讲解是否听懂 / 判卷是否服气），**记录但不许当场辩解**。

**评估标准**：

- [ ] 判卷记录里，凡涉及具体数值的，都有 gcc / node / 标准答案凭据（现有做法，扩展）
- [ ] 存在「重判不一致清单」，条目数 / 总条目数 = 判卷稳定率（目标 >90%）
- [ ] 每周 1 次学生反向评分，连续 4 周有记录

## 3. 数据处理（Data Processing）

### 3.1 关键词计数法的根本局限

**问题**：`grep` 真题数关键词 —— 文档**已经诚实标注**了这个局限（看板 243 行写「命中仅 1 条且是数据结构"串"的定义，与 ASCII 无关」）。这是好的一面。

但**方法本身**仍然不足以支撑"考点权重"判断，因为：

- 「真题不会写"相关变化率"四个字」（审计文档已自述）
- 同义表述、隐含考法、复合题**全都漏计**
- 无法区分"考了 1 分的送分题"和"考了 10 分的综合题"

**修改方向**：升级为**逐题人工归类（manual coding）**：

1. 把八份真题**逐题拆开**，每题一行，打上考点标签（可多标签）。
2. 标签体系用**考纲模块编号**（项目已有 21 模块划分）。
3. **双人编码 + 一致性检验**：第一遍教练编，隔 24 小时第二遍重编，算 **Cohen's κ**（或简单的百分比一致率）。
   - 一致率 < 0.8 → 标签定义太模糊，需要重写标签手册。
4. 输出一张**真考点权重表**：模块 × 出现次数 × 分值占比。

**评估标准**：

- [ ] 存在 `历年真题/考点归类/` 目录，每题一行，格式统一
- [ ] 覆盖率：归类题数 / 真题总题数 ≥ 95%
- [ ] 双编码一致率 ≥ 0.8（低于则先修标签手册再重编）
- [ ] 输出「考点权重表」，且与现有 `grep` 结论**逐条对照**，差异条目单列

> ⚠️ **这是本报告工作量最大的一条，但也是收益最大的一条** —— 它直接决定"该练什么"，而"该练什么"决定 410 分。

### 3.5 进度条分母不透明

**评估标准**：

### 3.6 Anki 数据的统计推断过强

**问题**：看板 84 行的判读：

> 「困难按到 33.2%、重来只有 5.7% —— **你几乎没有"真忘掉"的词，是自己把词按成"难"的。**」

这是**从行为频次反推心理状态**。问题：

1. 「33.2% vs 5.7%」**没给 n、没给置信区间、没给效应量**。
2. 没排除**替代解释**：卡片本身难度不同、新词/复习词比例不同、时间分布不同。
3. 结论语气是**断言**（"是"），不是假设。

**证据**：看板 80–86 行。

**修改方向**：改写成**假设 + 验证方式**：

> **假设 H1**：困难按钮使用率偏高，主因是操作习惯而非记忆失败。  
> **替代解释**：新学卡片占比高（新学 : 复习 = 1.8 : 1）本身会推高困难率。  
> **验证方式**：把近 30 天卡片按「新学/复习」分层，比较两层各自的困难率。若差异 <10 个百分点，则 H1 成立。

**评估标准**：

- [ ] 所有数据判读段落，格式为「**假设 / 替代解释 / 验证方式**」三段
- [ ] 出现比例数字时，必须同时给**分子分母**
- [ ] 禁止用"说明 / 证明"这类断言词，改用"与…一致 / 支持…假设"

## 4. 论证逻辑（Argumentation）

### 4.1 从有限证据做全称判断

**问题**：从「4 题 50% → 6 题 100%（含 3 题泄露答案的重测）」推出「**缺口已闭合**」。

「缺口」是个全称概念（"会读符号、不会算结果"这个能力），6 道题是**有限样本**。用 6 题证明一个全称命题，**推理强度不足**。

**证据**：看板 120 行、248 行。

**修改方向**：建立**结论强度分级**，所有结论必须标级：

| 级别 | 标记     | 含义                    | 允许的措辞        |
| :- | :----- | :-------------------- | :----------- |
| 实测 | `〔实测〕` | 有 gcc / node / 标准答案凭据 | "X 等于 Y"     |
| 推断 | `〔推断〕` | 有依据但无直接凭据             | "倾向于 / 与…一致" |
| 假设 | `〔假设〕` | 待验证                   | "假设 / 若…则"   |

**评估标准**：

- [ ] 看板所有结论带级别标记
- [ ] 「已闭合 / 已掌握」只能用于 `〔实测〕` 且有跨日重复测量
- [ ] 抽查 5 条结论，级别标记与实际证据强度一致

### 4.2 混淆"缺数据"与"缺方法"

**问题**：这是**整份报告里最需要纠正的认知错误**。

高数进度条写 **8%**（看板 265 行）。但高数**总共只有 2 次实测**（09-09 的 4 题、09-10 的 6 题），且**全部集中在"极限求值"一个考点**。

**8% 这个数字暗示"学了两成"，实际是"只测过一个考点"。**

项目自己在别处做对了同类判断 —— `CONF_CAP={1:0.5, 2:0.8}` 的设计意图就是"**做对一题不能说明会了**"（看板 150 行）。这个逻辑是**双向的**：

> 如果"做对 1 题 → 封顶 0.5"是为了防高估，  
> 那么"只测过 1 个考点 → 给整科 8%"**同样是高估**。

**正确做法**：把「**没测过**」和「**测了没过**」分开：

- 没测过 → 显示 `—`（证据不足）
- 测了没过 → 显示 `0%`
- 测了过了 → 显示格子数 / 格子总数

**证据**：看板 265 行 vs 看板 150 行（CONF_CAP 设计意图）。

**修改方向**：

1. 进度条加**覆盖率**维度：`已测考点 1 / 总考点 25`。
2. 主指标从"进度百分比"改为 **「已测覆盖率 × 已过率」** 两个数。
3. 高数显示为：`覆盖率 4%（1/25）· 已过率 100%（1/1）` —— 这才是诚实描述。

**评估标准**：

- [ ] 每科进度显示**两个数**（覆盖率 + 已过率），不是一个百分比
- [ ] 覆盖率 <20% 的科目，禁止显示"进度 X%"
- [ ] 存在「证据不足」这一状态，且不被当成 0%

### 4.3 伪勤奋警告存在但无拦截机制

**问题**：项目**早就写下**了警告 —— 看板 97 行（09-08）：

> 「⚠️ 风险：截至本次会话**还没做过任何一道题**——警惕"囤资料/完善工具"式伪勤奋」

然后：

- 09-10 凌晨：破刀（看板 68 行自述「封刀戒律本轮已破」）
- 09-12~09-13：破刀（看板 148 行「破刀事实」）
- 09-17：**又一次** —— 整天产出 5 份文档，零学习量
- 09-18（今天）：**正在破** —— 就是这份报告

**这是霍桑效应（Hawthorne effect）的教科书案例**：**测量行为本身改变了被测量的对象**。项目越完善，越容易把"完善项目"误当成"学习进展"。

**关键认识**：**提醒是无效的**。看板 124 行（教练手册）已经总结过同类教训：

> 「❌ **不加新面板 / 新按钮**。已有实测结论：**任何"需要你在门户里点一下"的设计都会失效，靠提醒补不上**」

**这句话应该推广到"伪勤奋"上**：靠提醒补不上，**需要硬约束**。

**修改方向**：把"封刀戒律"从**道德条款**改成**技术约束**：

> **规则**：任何 `kind:"tool"` 性质的改动（改门户、改脚本、写文档、建面板），  
> **必须当天先有 ≥1 条 `kind ∈ {quiz, lecture, anki}` 的落账记录**。  
> 否则**拒绝执行**，并回复：「今天还没有学习落账，先做 15 分钟题，再回来改工具。」

**评估标准**：

- [ ] 该规则写入 `教练手册-教学纪律.md` 的禁止项，且**由 AI 主动执行**（不是等人提醒）
- [ ] 统计「破刀次数」：2026-09 迄今 4 次 → 目标 10 月 ≤2 次
- [ ] 每次破刀如实记账（现有做法，保留），且记录"当日学习量"

### 4.4 「发现 → 升级」的叙事陷阱

**问题**：复盘档案的结构是「事故 → 根因 → 沉淀成规矩」。这个结构**很专业**，但有一个副作用：**它让每一次失败都变成一次"方法论升级"，于是失败永远显得有价值**。

结果是：项目**积累了大量规矩，但过关格子只有 8 个**。

**证据**：教练手册 51–65 行有 14 条教学纪律；复盘档案 3 天记了 9 次事故；而进度条 8 格 / 25 格。

**修改方向**：给复盘加**成本核算**：

- 每条新规矩，记录它的**执行成本**（每次开课要多花几分钟）
- 定期**淘汰**低收益规矩（规矩也有边际效用递减）

**评估标准**：

- [ ] 每条教学纪律标「由来 + 生效日期 + 最近 30 天触发次数」
- [ ] 30 天内触发 0 次的规矩，进入「待淘汰」评估（不是自动删，是要求复核）
- [ ] 规矩总数有上限（建议 ≤15 条），超了必须淘汰旧的

- **评估标准**：高数引用要么有教材页码，要么标注"双源交叉：来源 A / 来源 B"。

**缺口 3：没有"依据题"专项**

- **表现**：弱项画像 275 行：「会背 (x²)′=2x 但**写不出依据**」。
- **改进建议**：这是**程序性知识**问题（会结果不会过程）。建"依据题"训练：**要求写推导链，答案栏留空也判过**（只看过程）。
- **评估标准**：每周 ≥2 道"只判过程"的题；连续 3 次推导链完整。

**缺口 4：断档 9 天**

- **表现**：最后一次高数记录 09-10，今天 09-19。
- **改进建议**：高数进"锚题池"（§1.3），每次开课跑一遍，防断档。
- **评估标准**：连续 ≥3 天无高数记录 → 警告（见 §3.4）。

### 5.3 政治（100 分）—— 0 覆盖，且"背诵为主"这个判断未被验证

**缺口 1：完全没有方法设计**

- **表现**：看板 266 行「三轮任务（12 月起）」，零日志、零错题、零分析。
- **改进建议**：**12 月前不做背诵，但要做"题型结构分析"** —— 这是研究方法工作，不是背书：
  1. 查政治真题的**题型分布**（单选/多选/辨析/材料分析各多少分）。
  2. 如果**辨析题 / 材料分析题占 >30%**，那么"背诵为主"这个策略就是错的（纯背拿不到这类分）。
  3. 输出一份「政治题型结构与策略建议」。
- **评估标准**：11 月底前存在该文档，含题型 × 分值 × 建议策略。

**缺口 2："背诵为主"是假设，不是结论**

- **表现**：`目标分拆解-410.md` 63 行「政治 100 分投入产出比最高 —— **背诵为主**」。
- **证据等级**：`〔假设〕`。没有任何真题结构证据支撑。
- **改进建议**：把这条降级为假设，用缺口 1 的分析去验证。
- **评估标准**：该判断要么被证据支持，要么被修正，不能以断言形式留在文档里。

**缺口 3：无间隔重复设计**

- **表现**：Anki 基础设施**已经存在**（2230 词牌组在跑），但**政治没有接进去**。
- **改进建议**：政治天然适合卡片化（概念/事件/原理）。**复用现成基础设施，边际成本接近 0**。
- **评估标准**：12 月前建立政治牌组（至少 50 张），并进入每日复习流。

### 5.4 英语（100 分）—— 策略自相矛盾

**缺口 1：自认最难，投入最少**

- **表现**：`目标分拆解-410.md` 64 行「英语 100 分**最难** —— 零基础 + 需要长期积累」，策略是「靠 Anki 每天 15 分钟**保鲜**」。
- **逻辑矛盾**：**如果最难 → 应该投入最多**；实际投入 3 条日志（7.9%），且 2 条是工具记录。
- **改进建议**：要么修正"最难"的判断（可能英语确实不难，只是没练），要么把投入提上来。**两者必选其一，不能并存。**
- **评估标准**：在文档里给出明确结论，并让投入与结论一致。

**缺口 2：零阅读训练（而阅读是主力题型）**

- **表现**：日志里英语只有 Anki 背词，**没有任何阅读/翻译/写作记录**。
- **改进建议**：
  1. 每周 2 篇真题阅读：**限时做 → 对答案 → 精读（逐句翻译）→ 生词入 Anki**。
  2. 精读时把生词做成**语境卡**（例句挖空），而不是孤立单词卡 —— 孤立词卡测的是"认脸"（看板 84 行自己的判断）。
- **评估标准**：每周 ≥2 篇阅读记录，含「限时用时 / 正确率 / 精读产出」三项。

**缺口 3：Anki 卡片形式单一**

- **表现**：看板 84 行自己判断「**多半在认脸**」。
- **改进建议**：卡片类型升级为三档：
  1. 词 → 义（现有）
  2. 语境挖空（句子里挖掉目标词）
  3. 主动产出（给中文，写英文）
- **评估标准**：三档卡片各自的数量与正确率可分别统计；"认脸档"正确率与"产出档"正确率的差值被记录。

## 6. GitHub 资料查找与 Agent 升级

> darling 的第三个问题。**核心判断先说**：

### 6.1 核心判断：你需要的是"方法论工具箱"，不是"专升本资料"

我实测了 GitHub（见 6.3 锚点清单），得到一个明确结论：

**GitHub 上几乎没有可用的"专升本科目分析"资料** —— 中文应试内容主要在网盘/公众号/教辅书里，不在 GitHub。搜「single-case experimental design」这个本项目最该归属的方法论方向，**最高 star 的仓库是 0 星**。

**但**：支撑这个项目的**方法论层**，GitHub 上有大量成熟、活跃、可直接复用的东西。**你缺的不是资料，是分析资料的方法。**

所以检索方向应该是：

| ❌ 别搜              | ✅ 该搜                                    |
| :---------------- | :-------------------------------------- |
| "专升本 笔记"、"专升本 真题" | `spaced-repetition`、`knowledge-tracing` |
| "广东 专升本 资料"       | `psychometrics`、`item-response-theory`  |
| "高考 题库"           | `single-case-design`、`mastery-learning` |
| "学习方法"            | `learning-analytics`、`student-modeling` |


### 6.2 检索方法论（三级）

**L1 · 领域定位**（找"这个领域有什么"）

```bash
# 用 topic 而不是关键词 —— topic 是人工维护的，噪声低得多
gh search repos --topic spaced-repetition --sort stars --limit 20
gh search repos --topic knowledge-tracing --sort stars
gh search repos --topic psychometrics --sort stars
# 找 awesome 清单 —— 一个 curated list 胜过 100 次搜索
gh search repos "awesome spaced repetition" --sort stars
```

**L2 · 算法复用**（找"能直接抄的代码"）

```bash
# 代码搜索比仓库搜索精准：直接找实现
gh search code "FSRS" --language python
gh search code "bayesian knowledge tracing" --language python
# 看某个组织的全部仓库
gh api /orgs/open-spaced-repetition/repos --paginate
```

**L3 · 方法论对齐**（找"正确的实验设计"）

```bash
gh search repos "single-case experimental design" --sort stars
gh search repos "mastery learning" --sort stars
```

**⚠️ 关键约束**：`gh` CLI 目前**未登录**（`USER.md` 记录）。两条路：

**路线 A：登录（能用 search）**

```bash
gh auth login      # 交互式，选 HTTPS + 浏览器授权
gh auth status     # 验证
```

**路线 B：不登录（只用公开 API，我实测可行）**

```bash
# GitHub 公开 REST API，未认证也可用（限速：search 10 次/分钟，其他 60 次/小时）
curl -s -H "Accept: application/vnd.github+json" \
  "https://api.github.com/search/repositories?q=fsrs&sort=stars&order=desc&per_page=10"
```

> ⚠️ 中文查询词**必须 URL 编码**（我实测「题库」直接拼进 URL 会 400 Bad Request）。
