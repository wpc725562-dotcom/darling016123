# 真题页配置 schema（`scripts/zhenti_cfg/*.json`）

> 2026-09-20 建立。起因见审计条目 **D3**：`total` 的语义从没被定义过，
> 于是「配置说 45 题、页面只有 23 题」这种情况，三方（配置 / 页面 / 报告）
> 谁都不会报错，而任何基于 `total` 的「覆盖率 / 完成度」结论都不可信。

## 契约（v1）

| 字段 | 类型 | 语义 |
|:---|:---|:---|
| `file` | string | 页面路径（相对仓库根）。**必填** |
| `total` | `[题量, 满分]` | ★ **全卷**的题量与满分 —— 不是「本页有多少题」 |
| `covered` | int，可选 | ★ **本页已还原的题量**。省略 = 默认等于 `total[0]`（即本页覆盖全卷） |
| `gap_note` | string，可选 | `covered < total[0]` 时，说明缺口是什么、为什么可接受 |
| `sections` | `{节名: [题号区间, 卷面小题数, 分值]}` | `题号区间` 可为 `null`（该节无题号，如「辨析/简答·同型模板」）；`卷面小题数` 可为带注释的字符串（如 `"1（两问）"`） |
| `core` | `{节名: 考查范围}` | 仅用于「试卷结构」表的最后一列 |
| `section_titles` | `{节名: 卷面原标题}` | 补全分值表述 |
| `topics` | `{题号: 考点名}` | |
| `answers` | `{题号: 答案}` | |
| `answer_start` / `passthru_sections` / `drop_lines` | array | 解析用 |
| `q_fix` | `{题号: [题面, 答案]}` | 逐题覆盖（题面与答案黏在一行、无法机械切分时用） |
| `_note` / `total_note` | string | 给人看的说明 |

## 两条不变量（`zhenti_lint.py --all-configs` 会验）

1. **`covered`（或 `total[0]`）== 页面里 `### 第 N 题` 的实际条数。**
   不等就是**失败** —— 要么页面漏题，要么配置写错。这条**不受 `gap_note` 影响**。
2. **`sections[name][0]` 声明的题号区间，页面要覆盖全。**
   例：声明 `21–30`，页面只有 `21–28` → 缺 2 题，报出来。
   例外：该区间在页面里**一个都没有**（`got == 0`）→ 视为「本节本页未还原」，
   属于覆盖范围问题，交给第 1 条 / `gap_note` 表达，不再单独报缺口。

`covered < total[0]` **不算失败**，但必须有 `gap_note` 说明 —— 否则报警告。
理由：回忆版页面天然只覆盖全卷的一部分，这是事实；但它必须**显式声明**，
不能靠读者从 description 里猜。

### 不校验什么（以及为什么）

- **`sections[name][1]`（卷面小题数）不与题号个数比对。**
  两者语义不同：材料分析题是 **1 小题占 2 个题号**，所以 `["37–38", "1（两问）", "15"]`
  是正确的，不是笔误。
  > ★ 这条是踩过的坑（2026-09-20）：校验器最初拿 `题量` 去比 `题号个数`，
  > 于是把 politics2023 这份**正确**的配置判成「`1（两问）` 不是数字」。
  > 放宽后必须用反向用例证明闸门还活着（去掉 `gap_note` 要重新判失败）——
  > 否则「修误报」很容易顺手把检查改成永远通过。
  现在只在「题量列是纯整数、且与题号个数不符」时提示一句（`note`，不判失败）。


## 为什么不用 description 表达覆盖率

`description` 是给人读的营销文案（会写进页面 meta），里面出现「31 题」
「客观题 35 题」这类数字，既没有格式约束，也没法和 `total` 做机器比对。
覆盖率这类**需要被校验**的事实，必须放在有类型、有契约的字段里。
