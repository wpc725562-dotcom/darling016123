## 二十一、指针进阶与类型识别

### 二级指针
- **要点**：存放一级指针变量地址的指针是二级指针，写作 `int** pp`。类型拆解：靠内的 `*` 说明它是指针变量，`int*` 说明它指向的对象是一级指针类型。`*pp` 得到一级指针，`**pp` 才取到原始变量；同理可得三级指针，但三级及以上很少用。只传一级指针时函数内改的是形参指针、无法影响外部指针变量本身，要修改指针变量本身必须传它的地址即二级指针。
- **关键概念**：`二级指针`、`int**`、`**p`
- **出处**：鹏哥 P113；逊哥 P10

### 指针数组
- **要点**：每个元素都是指针的数组，如 `int* arr[3]`。`arr` 先与 `[]` 结合说明它是数组，去掉名字剩下的 `int*` 就是元素类型。易混点——指针数组是数组，数组指针是指针。
- **关键概念**：`指针数组`、`int* arr[3]`、`模拟二维数组`
- **出处**：鹏哥 P114

### 数组指针变量
- **要点**：指向数组的指针，写法 `int (*p)[10]`。须加括号让 `p` 先与 `*` 结合才是指针（否则 `p` 先与 `[]` 结合成了指针数组）；`[10]` 说明所指数组有 10 个元素、`int` 说明元素类型，两者须与实际数组匹配。对它加减会跳过整个数组，主要用于二维数组传参。
- **关键概念**：`数组指针`、`int (*p)[10]`、`&数组名`
- **出处**：鹏哥 P116

### 函数指针变量
- **要点**：函数指针是存放函数地址的指针。函数名就是函数的地址，`&函数名` 与 `函数名` 完全等价（与数组名不同）。写法 `int (*pf)(int, int)`：括号里的 `*` 说明 `pf` 是指针，右侧圆括号说明它指向函数、括号内写参数类型（形参名可省），最前面的 `int` 是所指向函数的返回类型。调用可写 `(*pf)(x, y)` 或 `pf(x, y)`，带 `*` 时须整体加括号。
- **关键概念**：`函数指针`、`函数名即地址`、`int (*pf)(int,int)`
- **出处**：鹏哥 P118, P119

### 函数指针数组
- **要点**：每个元素都是函数指针的数组，在函数指针变量名后加 `[]`，如 `int (*pfArr[4])(int,int)`。名字先与 `[]` 结合说明它是数组，去掉名字剩下的部分就是元素类型（函数指针）。
- **关键概念**：`函数指针数组`、`int (*pfArr[4])(int,int)`
- **出处**：鹏哥 P121

### 字符指针变量指向字符串与相关辨析
- **要点**：`char* ps = "abcd"` 并非把字符串存进指针，而是把常量字符串首字符的地址赋给 `ps`；`%s` 打印只需起始地址，`%c` 打印需 `*ps`。常量字符串不可修改，通过指针改它会直接导致程序异常终止，规范写法应加 `const`。`char* ps[3] = {"张三","李四","王五"}` 中每个元素是 `char*`，可用 `%s` 打印 `ps[i]`。辨析题：内容相同的两个字符数组是两个独立数组，数组名比较的是各自起始地址、必不相等；内容相同的常量字符串赋给两个字符指针时，因常量不可改、内容一致，编译器只存一份，两个指针里放的地址相同。
- **关键概念**：`常量字符串`、`%s`、`字符指针数组`
- **出处**：鹏哥 P115, P130

### typedef 关键字
- **要点**：用于给类型重命名（只能对类型，不可对函数），可简化复杂类型；同一类型在多处使用时只需改这一句就能整体切换。指针类型重命名时新名字须写在 `*` 旁边，如 `typedef int* pint_t`；数组指针、函数指针类型同理，此时新类型是一个整体，`pint_t a, b` 中两个都是指针。与 `#define` 对比——`#define int* pint_t` 是文本替换，`pint_t a, b` 中只有 `a` 是指针。
- **关键概念**：`typedef`、`类型重命名`、`ElemType`、`pint_t`
- **出处**：鹏哥 P120；逊哥 P2, P3；张无忌 P7

### 回调函数
- **要点**：把函数地址作为参数传给另一个函数，在那个函数内部通过函数指针调用它，被调用的函数就是回调函数。回调函数不由实现方直接调用，而是在特定时机由另一方调用以响应事件或条件。
- **关键概念**：`回调函数`、`函数指针`、`参数抽象`
- **出处**：鹏哥 P123

### 转移表
- **要点**：把若干函数地址按顺序存入函数指针数组，用输入值作下标取出函数指针并调用，即可替代冗长的 `switch-case`，这种数组叫转移表。局限是所有被存函数的参数与返回类型须一致。
- **关键概念**：`转移表`、`函数指针数组`
- **出处**：鹏哥 P122

### qsort 函数的使用
- **要点**：`qsort` 是标准库排序函数（`stdlib.h`），基于快速排序思想，可排序任意类型数据。相比之下自定义冒泡排序形参为整型指针，只能排整型数据，不够通用。
- **关键概念**：`qsort`、`stdlib.h`、`函数指针`
- **出处**：鹏哥 P124

### 比较函数的约定
- **要点**：比较函数接收两个 `const void*` 参数，返回 int：前者大于后者返回大于 0 的数，小于返回小于 0 的数，相等返回 0（不必是 1/-1/0）。`void*` 不可直接解引用，须按实际类型强制转换后再取值；排序结构体则强转成结构体指针后取成员。把返回值逻辑反过来即可得到降序。字符串不可用 `>`、`<` 比较，要用 `strcmp`（`string.h`），按对应位置字符的 ASCII 值（字典序）比较，返回值可直接作为比较函数的返回值。
- **关键概念**：`const void*`、`强制类型转换`、`strcmp`
- **出处**：鹏哥 P124, P125

### qsort 的模拟实现
- **要点**：以冒泡排序为底层写出通用排序，参数与 qsort 一致（`void* base`、`size_t num`、`size_t size`、比较函数指针）。比较时用函数指针调用比较函数；求第 j 个元素地址用 `(char*)base + j * size`，因类型未知，只能强转成 `char*` 按字节偏移。交换两个元素不可借助固定类型的临时变量，要逐字节交换：写一个 `swap(char* b1, char* b2, size_t width)`，循环 `width` 次，每次交换一个字节并让两个指针后移。
- **关键概念**：`void*`、`char*`、`逐字节交换`
- **出处**：鹏哥 P126

## 二十二、结构体、位段、联合体与枚举

### 结构体的概念、声明与初始化
- **要点**：结构体是用户自定义类型，把多个不同类型的值组合在一起（数组只能存同一类型），声明语法 `struct tag { 成员列表 } 变量列表;`，`struct` 不可省、末尾分号不可丢，成员可是标量、数组、指针甚至其他结构体。创建结构体变量时按成员列表顺序依次初始化。
- **关键概念**：`struct`、`成员变量`、`自定义类型`、`结构体初始化`
- **出处**：鹏哥 P90, P155；张无忌 P7；一灯 P5

### 结构成员访问操作符
- **要点**：点操作符 `.` 访问结构体变量的成员，左边是变量名、右边是成员名；成员不可整体打印，须逐个取出。访问结构体指针的成员用箭头 `->`，`ps->name` 等价于 `(*ps).name`；使用 `->` 时强制转换表达式须加括号，因强转优先级低于 `->`。
- **关键概念**：`.`、`->`、`结构成员访问操作符`、`结构体指针`
- **出处**：鹏哥 P90, P125；逊哥 P2

### 匿名结构体类型与结构体自引用
- **要点**：省略标签 tag 即匿名结构体类型，通常只能用一次；即使两个匿名结构体成员完全相同，编译器也视为两个不同类型、互相赋值本质非法。链表节点需找到同类型的下一个节点，成员应写成指向自身类型的指针 `struct Node* next`；写成同类型结构体变量会因不断展开而大小无限。用 `typedef` 时不可在成员中提前使用新名字。
- **关键概念**：`匿名结构体`、`自引用`、`struct Node* next`、`链表节点`
- **出处**：鹏哥 P155

### 结构体内存对齐规则
- **要点**：① 第一个成员对齐到偏移量 0 处。② 从第二个成员起对齐到「对齐数」的整数倍地址处，对齐数取编译器默认对齐数与该成员自身大小的较小值（VS 默认 8，GCC 无默认对齐数）。③ 总大小为最大对齐数的整数倍。④ 嵌套结构体成员对齐到自己成员中最大对齐数的整数倍。用 `offsetof`（`<stddef.h>`）查看成员偏移量；成员顺序不同则总大小不同，如 `char int char` 占 12 字节、`char char int` 占 8 字节，`{char, int}` 占 8 字节而非 5。
- **关键概念**：`偏移量`、`对齐数`、`默认对齐数`、`offsetof`
- **相互关系**：考研与选择题常与指针运算掺考。
- **出处**：鹏哥 P156, P157；逊哥 P2

### 内存对齐的原因与默认对齐数修改
- **要点**：对齐有平台原因（某些硬件只能在特定地址访问特定类型数据）与性能原因（未对齐需两次内存访问再拼接），本质是拿空间换时间。可用 `#pragma pack(n)` 在结构体定义前修改默认对齐数、定义后用 `#pragma pack()` 恢复，n 一般取 2 的次幂，该方式只在 Windows/VS 有效；设为 1 后 `char int char` 只占 6 字节。
- **关键概念**：`平台原因`、`性能原因`、`#pragma pack(n)`、`空间换时间`
- **出处**：鹏哥 P157

### 结构体传参
- **要点**：有传值调用与传址调用两种方案，推荐传地址。结构体变量通常较大，传值时形参要另开辟空间并拷贝数据，参数压栈带来时间与空间双重开销；传地址只拷贝一个指针大小的数据，担心误改原数据可用 `const` 约束。
- **关键概念**：`传值调用`、`传址调用`、`压栈`、`const`
- **出处**：鹏哥 P158

### 位段的声明与作用
- **要点**：位段由结构体衍生而来，成员须是整型家族类型（`int`、`unsigned int`、`signed int`，C99 后可为 `char` 等），不可是 `float`、`double`；成员名后跟冒号和数字，表示占用的二进制位数。典型应用是 IP 数据报等需要按位打包的场景。
- **关键概念**：`位段`、`二进制位数`、`整型家族`、`IP 数据报`
- **出处**：鹏哥 P159, P161

### 位段的内存分配、跨平台性与不可取地址
- **要点**：位段空间按需以 4 字节（`int` 成员）或 1 字节（`char` 成员）为单位开辟，不够再开。故位段省空间但可移植性差；VS 环境下从右向左使用、不够直接浪费。位段成员可能共用同一个字节、起始位置往往不是字节起始位置，故不可取地址 `&`，也不可直接用 `scanf` 输入，需输入时先用普通变量接收再赋值。
- **关键概念**：`内存分配单位`、`从右向左使用`、`不跨平台`、`&`
- **出处**：鹏哥 P160, P161

### 联合体（共用体）的定义与内存共享
- **要点**：联合体所有成员共用同一块内存空间，给其中一个成员赋值会覆盖其他成员；其大小至少为最大成员的大小，且受对齐规则影响。可用于节省空间，也是判断大端小端的常用手段。
- **关键概念**：`联合体`、`union`、`内存共享`
- **出处**：鹏哥 P162, P163

### 结构体嵌套匿名联合体
- **要点**：设计「礼品兑换单」需描述图书、杯子、衬衫：三者都有库存量、价格、商品类型三个通用属性，但特殊属性不同（图书有书名、作者、页数；杯子有设计；衬衫有设计、可选颜色、可选尺寸）。改法是在结构体内嵌入一个联合体，联合体内放三个匿名结构体并分别定义变量 `book`、`mark`、`shirt`——三类特殊属性不同时存在，联合体让它们共用同一块空间。
- **关键概念**：`联合体`、`匿名结构体`、`匿名联合体`、`内存共享`
- **出处**：鹏哥 P163

### 枚举类型的声明与枚举常量
- **要点**：枚举即「一一列举」，把可被一一列举的值抽象成一个类型，关键字为 `enum`。如 `enum Sex { MALE, FEMALE, SECRET };` 声明了性别枚举类型，大括号内列出该类型未来的可能取值，这些取值称枚举常量；取值之间用逗号隔开、最后一个后面不加逗号。枚举的值只限列举范围。
- **关键概念**：`enum`、`枚举类型`、`枚举常量`、`一一列举`
- **出处**：鹏哥 P164；逊哥 P8

### 枚举常量的取值规则
- **要点**：枚举常量的默认值从 0 开始依次递增，其真实数值可用 `%d` 输出。常量本身不可修改，不可对已列出的枚举常量再赋值。但可在声明时给初始值：给某个常量指定值后，其后未指定的常量按「前一个值 + 1」递增；也可逐个指定，在第一个元素显式赋初值即可改变起点。与 `#define` 对比——两者都不可改，但枚举支持自动递增赋值。
- **关键概念**：`枚举常量`、`默认值`、`初始值`、`递增`
- **出处**：鹏哥 P164；逊哥 P8

### 枚举相比 #define 的优点与类型检查
- **要点**：一是增强可读性与可维护性，`MALE`/`FEMALE` 比裸数字更易联想含义；二是有类型检查、更严谨，而 `#define` 只是文本替换；三是便于调试，`#define` 的符号在预处理阶段就被替换删除、调试时所见代码与真正执行的不一致，枚举不被删除；四是使用方便，一次可定义多个常量；五是枚举常量遵循作用域规则，`#define` 无作用域概念。
- **关键概念**：`#define`、`类型检查`、`预处理`、`作用域`
- **出处**：鹏哥 P165

## 二十三、动态内存管理与程序内存区域

### 为什么需动态内存管理
- **要点**：目前申请内存只有创建变量和创建数组两种方式：变量只能放一个数据，数组虽能放多个，但一旦开辟大小就固定，开大了浪费、开小了不够用，属于静态开辟、不够灵活。动态内存开辟把申请和释放空间的权限交给程序员，想要多大就开多大、大了可调小、小了可调大，用完再还回去；但它也是双刃剑，只申请不释放就会出问题。
- **关键概念**：`静态开辟`、`动态内存开辟`、`申请与释放`
- **出处**：鹏哥 P166；逊哥 P2, P3

### malloc 与 calloc
- **要点**：`void* malloc(size_t size)` 向堆区申请一块连续可用的空间并返回起始地址，失败（如内存不足）返回 `NULL`，故返回值须检查；参数为 0 时行为未定义。`void* calloc(size_t num, size_t size)` 为 `num` 个大小为 `size` 的元素开辟空间并把每个字节初始化为 0，可理解为 `calloc` ≈ `malloc` + 置零，故 `malloc` 性能可能更高。`malloc` 参数用 `sizeof` 传、返回值 `void*` 需强转。
- **关键概念**：`malloc`、`calloc`、`堆区`、`强转`
- **出处**：鹏哥 P166, P167；逊哥 P2, P3

### free 与 free 后的野指针
- **要点**：`free` 释放动态开辟的空间，只能释放堆区上动态开辟的空间，且必须从该空间的起始地址开始释放。释放后指针指向的空间已不属于程序，若不置空就成了野指针，规范做法是释放后立即置为 `NULL`。`malloc` 与 `free` 必须成对出现。
- **关键概念**：`free`、`起始地址`、`野指针`
- **出处**：鹏哥 P166, P167；逊哥 P2, P3

### realloc 与扩容的两种情况
- **要点**：`void* realloc(void* ptr, size_t size)` 调整已分配内存块的大小，`size` 为调整后的新大小，调整过程中不丢失原有数据；若 `ptr` 为空指针则等价于 `malloc`。成功返回重新分配的内存块指针（可能与原指针相同也可能不同），失败返回 `NULL` 且原有内存块不变。不可用原指针直接接收返回值——失败会把 `NULL` 赋给原指针，导致旧地址丢失、旧空间无法释放；应用临时指针接收，判断非空后再赋回。
- **关键概念**：`realloc`、`新的大小`、`原地追加`、`重新找空间`
- **出处**：鹏哥 P167

### 六种常见的动态内存错误
- **要点**：① 对空指针解引用：`malloc` 可能失败返回 `NULL`，未判断就使用会崩溃。② 越界访问：动态开辟的空间也有使用范围。③ 对非动态开辟空间的 free 释放：如把栈上局部变量的地址交给 `free`。④ 释放动态内存的一部分：指针移动后 free，释放须从起始地址开始。⑤ 同一块空间多次释放。⑥ 忘记释放：造成内存泄漏，且局部指针变量出函数即销毁、之后想释放都无机会。防护归结为「申请后判断返回值」「释放后置空」「malloc 与 free 成对出现」三条纪律。
- **关键概念**：`空指针解引用`、`越界访问`、`内存泄漏`、`野指针`
- **出处**：鹏哥 P168

### 动态内存经典笔试题
- **要点**：四道题均出自《高质量 C/C++ 编程》。题型一（传值调用失效）：函数内 `malloc` 后把地址赋给形参，形参是一级指针、实参并未被修改，外部指针仍为 `NULL`，后续 `strcpy` 对空指针解引用导致崩溃，且造成内存泄漏；改法是把形参改成二级指针用 `*p` 接收地址（返回型参数），或把申请到的地址作为返回值返回。题型二（返回栈空间地址）：函数返回局部数组名，出函数即销毁，接收到的地址成为野指针；改法是加 `static` 延长生命周期或改用动态开辟。
- **关键概念**：`二级指针`、`返回型参数`、`栈空间生命周期`、`野指针`
- **出处**：鹏哥 P169

### 柔性数组的定义、使用与扩容
- **要点**：C99 中结构体的最后一个元素允许是未知大小的数组，称柔性数组成员，写法有 `int a[0];` 或 `int a[];`。三个特点：① 柔性数组前面至少要有其他成员；② `sizeof` 返回的结构体大小不包含柔性数组的内存；③ 包含柔性数组成员的结构体要用 `malloc` 动态分配内存，且分配的大小应大于结构体大小，多出的部分就是留给柔性数组的空间。用法是 `malloc(sizeof(struct S) + 期望元素个数 * sizeof(int))`，返回值强转成结构体指针后用 `->` 访问前面成员。
- **关键概念**：`柔性数组`、`C99`、`sizeof`、`malloc`
- **出处**：鹏哥 P170

### 柔性数组与结构体含指针两种方案的对比
- **要点**：方案二是在结构体里放一个指针成员，先 `malloc` 结构体本身，再单独 `malloc` 指针指向的数组空间，扩容时用 `realloc` 调整指针指向的空间，释放时需两次 `free`（先释放指针指向的空间，再释放结构体）。两种方案都能让「数组」大小柔性变化，但柔性数组方案更优：① 只需一次 `malloc`/`free`，统一管理、释放方便；② 成员与数组成员在一块连续内存上，访问效率更高；③ `malloc` 次数少，产生的内存碎片更少。
- **关键概念**：`内存碎片`、`连续空间`、`两次 malloc`、`访问效率`
- **出处**：鹏哥 P170, P171

### 程序内存区域划分
- **要点**：① 栈区：存放函数内部创建的局部变量、函数参数、返回数据、返回地址；函数执行结束时这些存储单元自动释放；分配内置于处理器指令集中，效率高但容量有限，故局部数组不可开得太大。② 堆区：`malloc`/`calloc`/`realloc` 操作的空间，一般由程序员分配和释放；若程序员不释放，程序结束时由操作系统回收兜底。③ 数据段（静态/全局区）：存放全局变量与静态变量。④ 代码段：存放可执行代码与只读常量，如常量字符串，其中的数据不可随便修改。
- **关键概念**：`栈区`、`堆区`、`数据段`、`代码段`
- **相互关系**：递归调用、栈溢出、局部数组容量限制都由栈区特性解释。
- **出处**：鹏哥 P171；逊哥 P2, P3

## 二十四、文件操作

### 为什么使用文件
- **要点**：程序的数据默认存在内存中，程序退出内存被回收、数据就丢失，再次运行看不到上一次的数据。若要把数据持久化保存就得使用文件——文件存放在硬盘上，只要电脑不坏、重新开机后数据依然在。因此使用文件的目的就是让数据持久化保存。
- **关键概念**：`内存`、`持久化`、`硬盘`
- **出处**：鹏哥 P172

### 文件、文件名与路径
- **要点**：按功能分，文件分为程序文件（源文件 `.c`、目标文件、可执行程序等）和数据文件（程序运行时读写的数据，本章重点）。一个文件要有唯一的文件标识，文件名由文件路径、文件主干名、文件后缀三部分组成。
- **关键概念**：`程序文件`、`数据文件`、`文件名`、`绝对路径`
- **出处**：鹏哥 P172

### 二进制文件与文本文件
- **要点**：按数据的组织形式划分。数据在内存中一律以二进制形式存储，不加转换直接输出到外存文件得到的是二进制文件；若要求在外存上以 ASCII 码形式存储，则需在存储前把二进制数据转换成 ASCII 码，得到的是文本文件。
- **关键概念**：`二进制文件`、`文本文件`、`ASCII`、`数据的组织形式`
- **出处**：鹏哥 P173

### 流、标准流与文件指针
- **要点**：不同外部设备的输入输出方式各不相同，为此抽象出「流」的概念——程序员只需关注如何从流里读、如何往流里写，不必关心流与具体设备如何交互；打开一个文件时就会匹配一个流。C 程序启动时默认打开三个标准流：`stdin`（键盘）、`stdout`（显示器）、`stderr`（标准错误），故 `scanf`、`printf` 从来不需手动打开流。在缓冲文件系统中，打开一个文件时系统会在内存中开辟文件信息区，存放文件名、文件状态、文件当前位置等信息，这些信息保存在一个由系统声明的结构体变量中，类型取名为 `FILE`；文件指针就是指向 `FILE` 类型变量的指针，类型为 `FILE*`。
- **关键概念**：`流`、`标准流`、`stdin`、`stdout`、`FILE*`
- **出处**：鹏哥 P174, P175

### 文件的打开与关闭
- **要点**：所有文件在读写之前都要先打开、使用结束后要关闭。`FILE* fopen(const char* filename, const char* mode)` 按 `mode` 打开 `filename`，成功返回指向 `FILE` 对象的指针、失败返回 `NULL`，返回值须判断。`mode` 常见取值：`"r"` 只读（文件须已存在）；`"w"` 只写（会清空已有数据，文件不存在则新建）；`"a"` 追加（在文件末尾添加数据，不存在则新建）；另有 `"rb"`、`"wb"`、`"ab"` 等二进制方式。
- **关键概念**：`fopen`、`mode`、`"r"`、`"w"`
- **出处**：鹏哥 P175

### fclose 的返回值
- **要点**：`fclose` 关闭文件成功时返回值为 0，关闭时会自动刷新缓冲区。
- **关键概念**：`fclose`、`返回值 0`
- **出处**：一灯 P4；鹏哥 P182

### fputc、fgetc、feof 与 ferror
- **要点**：数据从文件读到内存叫输入（读取），从内存写到文件叫输出（写）。`int fputc(int character, FILE* stream)` 向输出流写入一个字符，成功返回写入的字符、失败返回 `EOF`（-1），写入后位置指示器自动前移一位，`stream` 也可是 `stdout`。`int fgetc(FILE* stream)` 从输入流读取一个字符并返回，读取后指示器自动前移；若已处于文件末尾则返回 `EOF` 并设置文件结束指示器，若读取过程中发生错误也返回 `EOF` 但设置的是错误指示器。`feof` 与 `ferror` 就是用来区分这两种情形的。
- **关键概念**：`fputc`、`fgetc`、`feof`、`ferror`
- **出处**：鹏哥 P176

### fputs 写字符串 / fgets 读字符串
- **要点**：`fputs(str, stream)` 把字符串写入流，不写入结尾的 `\0`、也不自动换行（要换行须自己在内容里加 `\n`），成功返回非负整数、失败返回 `EOF`。`fgets(str, num, stream)` 遇换行符、文件末尾或达到上限即停，最多读 `num-1` 个字符（留位置给 `\0`）并自动补 `\0`，读到的换行符会保留，成功返回 `str`、到末尾或出错返回 `NULL`。
- **关键概念**：`fputs`、`fgets`、`FILE*`、`\0`
- **出处**：鹏哥 P177

### fprintf 写 / fscanf 读格式化数据
- **要点**：`fprintf` 比 `printf` 只多第一个 `FILE*` 参数，可把带格式数据写到任意流（文件流或 `stdout`），返回写入的字符总数、失败返回负值。`fscanf` 比 `scanf` 只多第一个流参数，按格式从流中解析数据到变量地址，返回成功赋值的项数，可能少于预期甚至为 0，未读到任何数据即出错或到末尾则返回 `EOF`。写时格式串里的普通字符读时也须原样匹配；变量要取地址，字符数组名本身是地址故不用取。
- **关键概念**：`fprintf`、`fscanf`、`EOF`
- **出处**：鹏哥 P178

### sprintf 转字符串 / sscanf 解析字符串
- **要点**：`sprintf` 把格式化数据写入字符数组（内存缓冲区），常用于把结构体各成员拼成一个字符串或把整数转成字符串，返回写入字符数（不含 `\0`），目标数组要足够大。`sscanf` 从内存字符串按格式解析数据到变量地址，返回解析并赋值的参数个数，失败返回 `EOF`。两者一来一回；解析格式须与写入格式一致，不匹配就解不出数据。
- **关键概念**：`sprintf`、`sscanf`
- **出处**：鹏哥 P179

### fwrite / fread 二进制块读写
- **要点**：参数依次为数据块指针 `ptr`、每项字节数 `size`、项数 `count`、文件流 `stream`，返回实际读/写的项数，可能小于 `count`（出错或到文件末尾）。二进制写进去就要二进制读出来；字符串的二进制与文本存储相同故记事本看得懂，整数和浮点数则不同、会显示乱码。
- **关键概念**：`fwrite`、`fread`、`size_t`、`wb`
- **出处**：鹏哥 P180

### 三组格式化输入输出函数的对比
- **要点**：`scanf`/`printf` 只针对标准输入流 / 标准输出流；`fscanf`/`fprintf` 针对所有输入流 / 输出流（文件流与标准流皆可）；`sscanf`/`sprintf` 的源与目标是内存中的字符串，不是流。三者区别只在「数据来源 / 去向」这一维度，是常见对比考点。
- **关键概念**：`标准流`、`文件流`、`内存字符串`
- **出处**：鹏哥 P179

### fseek、ftell 与 rewind
- **要点**：`fseek(stream, offset, origin)` 按基准位置加偏移量定位文件指针。`offset` 正数向文件末尾方向、负数向开头方向、0 不动；`origin` 只能取 `SEEK_SET`（开头）、`SEEK_CUR`（当前位置）、`SEEK_END`（末尾）；成功返回 0、失败返回非零。`ftell(stream)` 返回文件指针相对文件开头的偏移量（字节数），类型 `long int`，失败返回 `-1L`。`rewind` 让文件指针回到文件开头。
- **关键概念**：`fseek`、`ftell`、`rewind`、`SEEK_SET`
- **出处**：鹏哥 P181

### 文件缓冲区与 fflush
- **要点**：C 标准采用缓冲文件系统，为每个在用的文件在内存中开辟缓冲区：写数据先入输出缓冲区，装满（或遇换行、或主动刷新）才一起送磁盘；读数据先从磁盘入输入缓冲区再交给程序，目的是减少对操作系统的调用、提升效率。`fflush(stream)` 刷新指定流的缓冲区、把未写入数据立即写入文件，成功返回 0、失败返回 `EOF`，参数为 `NULL` 时刷新所有输出流。`fflush` 对输出流行为明确、对输入流由实现决定；正常终止或 `fclose` 会自动刷新，程序崩溃则缓冲区数据丢失。
- **关键概念**：`缓冲文件系统`、`输入/输出缓冲区`、`fflush`、`fclose`
- **出处**：鹏哥 P182

### 更新文件（r+ / w+ / a+）
- **要点**：三种方式都可读可写。`r+` 要求文件已存在、保留原内容、指针在开头，直接写会覆盖；`w+` 文件不存在则创建、存在则清空、指针在开头；`a+` 会创建文件、保留原内容、指针初始在末尾追加。
- **关键概念**：`r+`、`w+`、`a+`
- **出处**：鹏哥 P183

## 二十五、编译、链接与预处理

### 翻译环境、运行环境与程序运行的四步
- **要点**：ANSI C 的每种实现都有两个环境：翻译环境把源代码转换成可执行的机器指令，运行环境用于实际执行代码。翻译环境再拆为编译与链接，编译又拆为预处理、编译、汇编三步。运行环境有四步：一、载入内存（有操作系统时由操作系统完成，独立环境须手工烧录）；二、找入口，定位 `main` 对应的二进制指令位置开始执行；三、执行，使用运行时堆栈（函数栈帧）存局部变量与返回地址，也可使用静态内存；四、终止（正常结束或意外终止）。
- **关键概念**：`翻译环境`、`运行环境`、`机器指令`、`载入内存`
- **出处**：鹏哥 P184, P186

### 预处理（预编译）阶段
- **要点**：处理所有 `#` 开头的预编译指令，全是文本操作：删除 `#define` 并展开所有宏定义（先展开再删除）；处理条件编译指令（`#if`、`#ifdef`、`#ifndef`、`#else`、`#elif`、`#endif`）；把 `#include` 的头文件内容插入该指令位置且递归进行；删除注释（本质是替换成空格，故在变量名中间插注释会把名字拆开）；另补充行号与文件标识以生成调试信息，并保留 `#pragma` 等指令。
- **关键概念**：`预处理`、`#include`、`#define`、`.i`
- **出处**：鹏哥 P185

### 编译阶段：词法、语法、语义分析
- **要点**：对 `.i` 文件做词法分析、语法分析、语义分析及优化，最终生成汇编代码（`.s`，命令 `gcc -S`）。词法分析由扫描器把代码拆成一个个记号（关键字、标识符、字面量、特殊符号）；语法分析把记号组成以表达式为节点的语法树；语义分析做语义标识与类型推导（静态语义分析），检查声明与类型是否匹配，语法错误在此阶段暴露。`gcc -E` 只做文本替换不做语法检查，缺分号要到本阶段才报错。
- **关键概念**：`词法分析`、`语法分析`、`语义分析`、`语法树`
- **出处**：鹏哥 P185

### 汇编阶段与链接阶段
- **要点**：汇编由汇编器把汇编代码逐条翻译成机器指令（二进制），生成目标文件 `.o`（`gcc -c`），汇编语句与机器指令几乎一一对应、不做指令优化。链接把多个目标文件与链接库合并成可执行程序，完成空间与地址分配、符号决议、符号重定位：生成目标文件时汇总该文件的全局符号形成符号表（局部变量与形参不汇总），声明不分配地址、定义才分配有效地址，链接时合并各符号表、同名符号取有效地址，再按符号查找被调函数地址。
- **关键概念**：`汇编器`、`目标文件`、`符号表`、`符号决议`
- **出处**：鹏哥 P185

### 预定义符号
- **要点**：C 语言预先设定、可直接使用，在预处理阶段就被替换：`__FILE__` 正在编译的源文件名、`__LINE__` 当前行号、`__DATE__` 编译日期、`__TIME__` 编译时间、`__STDC__`（遵循 ANSI C 时值为 1，否则未定义）；C99 起还有 `__func__` 表示当前函数名，常用于记录日志。`__STDC__` 可判断编译器是否完全遵循标准——VS 不完全支持会报未定义，GCC 完全遵循输出 1。
- **关键概念**：`__FILE__`、`__LINE__`、`__DATE__`、`__TIME__`
- **出处**：鹏哥 P187

### #define 定义常量
- **要点**：语法 `#define name 内容`，名字与内容之间须有空格；内容不限于数字，可是关键字，也可是一段代码。定义时一般不加分号，加了会导致替换后出现语法问题。`register` 只是建议把变量放进寄存器，是否采纳由编译器权衡；`#define` 内容过长时可用行末反斜杠 `\` 续行，反斜杠后不可有任何字符。
- **关键概念**：`#define`、`符号常量`、`register`、`续行`
- **出处**：鹏哥 P188；强哥 P22, P35, P52

### #define 定义宏与括号规则
- **要点**：`#define` 机制允许把参数替换到文本中，这种带参数的实现称宏，形式为 `#define name(参数列表) 内容`。宏在预处理阶段完成替换，不做类型检查、不做计算，是把实参原样搬过去。写宏时参数要加括号、宏整体也要加括号：如 `#define SQUARE(X) X*X` 传 `A+2` 会替换成 `A+2*A+2`，须写成 `((X)*(X))`。参数列表左括号须紧挨宏名，中间不可有空格，否则被当作定义常量；预处理阶段不检测语法错误。
- **关键概念**：`宏`、`宏参数`、`宏体`、`参数括号`
- **出处**：鹏哥 P189

### 带有副作用的宏参数
- **要点**：副作用指表达式求值时产生的永久性效果，如 `++a` 在得到结果的同时改变了 `a`。当宏参数在宏体内出现超过一次且带副作用时结果不可预测：如 `MAX(A++, B++)` 中 `A`、`B` 各出现两次，`A` 小 `B` 大时 `A` 自增 1 次、`B` 自增 2 次，反之则相反。
- **关键概念**：`副作用`、`永久性效果`、`参数多次出现`、`++`
- **出处**：鹏哥 P190

### 宏替换的规则
- **要点**：调用宏时先检查参数中是否含其他 `#define` 定义的符号，有则先被替换；然后替换文本，参数名换成对应的值插入原位置；再扫描结果，若仍含 `#define` 符号则重复上述步骤。宏参数与 `#define` 内容中都可出现其他 `#define` 符号，但宏不可递归（宏体内不可出现自身）。预处理器搜索符号时不搜索字符串常量的内容，写在双引号里的 `M`、`MAX(a,b)` 不被替换——字符串常量不参与替换正是 `#` 运算符存在的理由。
- **关键概念**：`宏替换`、`参数先替换`、`递归`、`字符串常量`
- **出处**：鹏哥 P191

### 宏和函数的对比
- **要点**：宏占优处——执行速度（无调用与返回开销）、参数类型（与类型无关，函数须为每种类型各写一个）。函数占优处——代码长度（宏每次使用都插入宏体）、操作符优先级、带副作用的参数、调试（宏在预处理后消失）、递归（宏不可递归）。宏还能做函数做不到的事——参数可是类型（如 `MALLOC(num, type)` 传入 `int`），函数参数不可是类型；`inline` 内联函数结合二者优点：传参方式同函数、无调用返回开销、展开方式同宏。
- **关键概念**：`代码长度`、`执行速度`、`操作符优先级`、`副作用`
- **出处**：鹏哥 P192, P193

### # 运算符：字符串化
- **要点**：`#` 是预处理阶段的运算符，把宏的一个参数转换成字符串字面量，称「字符串化」，用法是在宏体内写 `#参数名`。C 语言中相邻的字符串字面量会自动合并（`"hello" "world"` 等价于 `"hello world"`），因此可用 `#参数` 把参数名变成字符串，再与格式串拼接成完整的 `printf` 格式串。不加 `#` 时参数会被替换成它的值，出现在字符串位置就错了。
- **关键概念**：`#`、`字符串化`
- **出处**：鹏哥 P194

### ## 运算符：记号粘合
- **要点**：`##` 把位于它两边的符号合成一个符号，称「记号粘合」，连接须产生合法符号，否则结果未定义。典型用法是写「生成函数的模板」：`#define GENERIC_MAX(type) type max_##type(type x, type y) { return x>y?x:y; }`，用 `max_##type` 把 `max_` 与类型名拼成函数名，每调用一次就展开出一个对应类型的函数（`max_int`、`max_float`、`max_char`）。
- **关键概念**：`##`、`记号粘合`
- **出处**：鹏哥 P194

### 命令行定义
- **要点**：许多 C 编译器允许在执行编译命令时用参数定义符号（gcc 的 `-D`），该符号在源码中并未定义，却能被源码直接使用。同一个源文件因编译时符号取值不同，可编译出不同版本的程序。与 `#define` 的区别是符号不在源码里定义；与 `scanf` 的区别是命令行定义在编译时确定，`scanf` 在程序运行时确定。
- **关键概念**：`命令行定义`、`-D`、`gcc`
- **出处**：鹏哥 P196

### 条件编译的作用与 #if / #elif / #else
- **要点**：预处理阶段按条件决定一条或一组语句是否参与编译；不满足条件的代码在预处理之后直接从代码中消失，后续编译、汇编、链接都看不到它。典型用途是调试代码：调试时打开、调试完关掉而不必删除。与 `if` 语句阶段不同——`if` 在程序运行时产生效果，条件编译在预处理阶段就决定这段代码留不留。`#if 常量表达式` 到 `#endif` 之间为受控代码块，`#endif` 与 `#if` 须配对；表达式须是常量表达式、不可出现变量，因预处理发生在变量创建之前；可用 `#define` 定义的宏参与判断。
- **关键概念**：`条件编译`、`#if`、`#elif`、`#else`
- **出处**：鹏哥 P197

### 判断是否被定义：#ifdef / #ifndef / defined
- **要点**：`#ifdef 符号` 等价于 `#if defined(符号)`，判断符号是否被定义过，定义过就参与编译；`#ifndef 符号` 等价于 `#if !defined(符号)`，未定义才参与编译。这两种写法只关心有无定义，与符号的值无关：即使值为 0、甚至不给值，只要定义过就为真。与 `#if 常量表达式` 的区分点——`#if` 判断表达式的真假，`#ifdef`/`#ifndef` 判断符号是否被定义。
- **关键概念**：`#ifdef`、`#ifndef`、`defined`、`#endif`
- **出处**：鹏哥 P197

### 条件编译的嵌套
- **要点**：条件编译指令可像 `if` 语句一样嵌套，`#endif` 与最近的 `#if` 配对，形成内外层判断（外层先判断平台类符号，内层再判断具体选项符号）。标准库头文件中大量使用这种嵌套写法。
- **关键概念**：`嵌套`、`#endif`、`#ifdef`
- **出处**：鹏哥 P197

### 两种包含方式与查找策略
- **要点**：`#include "xxx.h"` 是本地文件包含，先在源文件所在目录查找，找不到再去标准库路径查找一次，两次都找不到才报错；`#include <xxx.h>` 是库文件包含，只在标准库路径查找一次，找不到直接报错。包含头文件的本质是把头文件内容拷贝到包含位置。两种方式都可用双引号写，但尖括号头文件用双引号会先白查一次当前目录，效率低；因此约定自己的头文件用双引号、标准库头文件用尖括号。
- **关键概念**：`#include`、`<>`、`""`、`查找策略`
- **出处**：鹏哥 P61, P198；强哥 P6, P7, P11

### 头文件重复包含与头文件保护
- **要点**：头文件被包含几次，其内容就被拷贝几份，会使源文件代码量大幅膨胀。重复包含在实际工程中很难规避：公共模块头文件被 A、B 两个模块分别包含，而 A、B 又同时被同一份代码包含时，该头文件内容就会出现两次。解决办法是在头文件开头用条件编译包裹全部内容：`#ifndef` 判断保护符号未定义、`#define` 定义该保护符号、末尾 `#endif` 收尾。第一次包含时符号未定义、条件为真，定义符号并把内容包含进来；第二次及以后包含时符号已定义、条件为假，内容不再参与编译。
- **关键概念**：`重复包含`、`#ifndef`、`#define`、`#endif`
- **出处**：鹏哥 P198

### #pragma once
- **要点**：写在头文件开头即可防止该头文件被重复包含，写法比 `#ifndef` 保护更简洁；老编译器不支持，较新的编译器都支持，VS 中新建头文件会默认带上它。它属于预处理指令，但不属于条件编译指令。
- **关键概念**：`#pragma once`
- **出处**：鹏哥 P198

### #pragma 与 #line 及预处理指令总览
- **要点**：`#pragma` 是一类编译器相关的预处理指令：`#pragma pack` 用于修改结构体的默认对齐数，`#pragma once` 用于防止头文件重复包含；`#line` 用于修改行号等信息。常见预处理指令还包括 `#define`、`#undef`、`#include`、`#if`、`#ifdef`、`#ifndef`、`#elif`、`#else`、`#endif`、`#error` 等，全部在预处理阶段处理。
- **关键概念**：`#pragma`、`#pragma pack`、`#line`、`#undef`
- **出处**：鹏哥 P198, P199

## 二十六、调试与常见错误分类

### 调试的基本操作
- **要点**：常用快捷键为 F5 启动调试、F9 切换断点、F10 逐过程、F11 逐语句、Ctrl+F5 开始执行不调试。调试的本质是「观察程序执行细节」，手段包括打断点、单步执行与在监视窗口查看变量与内存。
- **关键概念**：`断点`、`F9`、`F10`、`F11`、`监视`
- **出处**：鹏哥 P70, P71

### 较大工程的调试方法与心态
- **要点**：不要逐行按 F10 走到底。先在怀疑的语句处打断点、用 F5 快速到达，再用 F11 进入目标函数内部逐步观察。函数内部观察数组时直接输入数组名只能看到一行，需在监视中写成「数组名, 行数」才能看到所有元素。
- **关键概念**：`断点`、`F11`、`监视`、`验证`
- **出处**：鹏哥 P72

### 编程常见错误归类
- **要点**：① 编译型（语法）错误：编译阶段报出，如漏写分号、误写逗号；错误信息较准确，双击可跳转到出错位置附近。② 链接型错误：编译通过但链接出错，典型报错「无法解析的外部符号」、前面常带 LNK；常见原因有函数名拼写不一致、符号不存在、头文件未包含、引用的库不存在；双击不跳转，可用查找功能搜索符号名定位。③ 运行时错误：编译链接都通过但结果不符合预期，无法穷举，需借助调试定位；内存泄漏是其中很难排查的一种，程序占用内存持续增长，最终把内存耗干导致系统卡死。
- **关键概念**：`语法错误`、`无法解析的外部符号`、`运行时错误`、`内存泄漏`
- **相互关系**：与「警告 warning 不影响执行、错误 error 无法编译链接」的编译提示规则配套使用。
- **出处**：鹏哥 P73

## 二十七、经典例题与项目实践

### 关机程序（system 与字符串比较）
- **要点**：`system("shutdown -s -t 60")` 执行系统命令实现 60 秒后关机，取消关机用 `shutdown -a`。输入读到字符数组中；两个字符串不可用 `==` 比较，须用 `strcmp`，返回 0 表示相等，需包含 `<string.h>`。用 goto 或循环反复给用户输入机会。易错点是「字符串用 `==` 比较」及中文逗号导致编译报错。
- **关键概念**：`system`、`shutdown`、`strcmp`、`<string.h>`
- **出处**：鹏哥 P41

### 随机数生成与范围公式
- **要点**：`rand()` 返回 0~`RAND_MAX` 之间的伪随机数，需包含 `<stdlib.h>`；它是对「种子」运算得到的结果，默认种子恒为 1，故每次运行结果都一样。用 `srand((unsigned)time(NULL))` 以时间作种子，需包含 `<time.h>`，即可让每次运行的序列不同。生成 `[a, b]` 区间随机数的公式为 `a + rand() % (b - a + 1)`。
- **关键概念**：`rand`、`srand`、`time`、`种子`
- **出处**：鹏哥 P42, P43

### 猜数字游戏
- **要点**：外层用 do-while 让游戏可反复玩（至少进入一次），内部打印菜单并读入选择，用 switch 处理选项：选 1 进入游戏、选 0 退出、其他值提示选择错误；循环条件直接使用输入变量。
- **关键概念**：`do-while`、`switch`、`game 函数`、`while(1)`
- **出处**：鹏哥 P42, P43

### 字符从两端向中间汇聚
- **要点**：给定目标字符串与等长的全 `#` 字符串，每次从两端各替换一个字符，动态呈现汇聚过程。用两个字符数组；左下标 `left = 0`，右下标 `right = strlen(str) - 1`；`while (left <= right)` 循环，每次把 `arr1` 两端的字符赋给 `arr2` 对应位置，打印后 `left++`、`right--`。易错点：用 `sizeof` 求右下标要减 2，用 `strlen` 只需减 1；循环条件须用 `<=`，否则奇数长度会漏掉最中间字符；`\r` 方案最后一行会被清掉，需在循环结束后补打印一次。
- **关键概念**：`left`、`right`、`strlen`、`Sleep`
- **出处**：鹏哥 P51

### 扫雷游戏：多文件组织、双数组设计与宏定义常量
- **要点**：工程拆成三个文件：`test.c` 负责整体游戏逻辑与测试，`game.h` 放函数声明与宏定义，`game.c` 放游戏函数实现。用 `do while` 循环包裹「打印菜单 → 输入选择 → `switch` 分支」的流程。棋盘要存两类信息——布置好的雷和排查出的雷数，放同一个数组会产生歧义，因此创建两个大小一致的数组，便于共用同一套函数。把 9、11、雷数等常量用 `#define` 定义，宏定义行末不加分号，改棋盘大小时只改一处。
- **关键概念**：`多文件`、`模块`、`二维数组`、`越界访问`
- **出处**：鹏哥 P64, P65

### 扫雷游戏：核心函数实现
- **要点**：初始化棋盘用嵌套循环遍历整个数组，把每个元素设为指定字符，函数多接收一个字符参数。打印棋盘只打印中间的 9×9 区域，循环下标从 1 开始；每行打印前先打印行号、所有行之前先打印列号。排查雷：先判断坐标合法性，再判断该位置是否已被排查过（显示数组对应位置不是 `*` 即已排查）；未被排查过才判断是否为雷——是雷则提示被炸死并打印雷的布局，不是雷则统计周围雷数并写入显示数组。
- **关键概念**：`初始化`、`行列号`、`rand`、`坐标合法性`
- **出处**：鹏哥 P64, P65

### 扫雷游戏：可扩展方向
- **要点**：常见扩展包括选择难度（不同棋盘与雷数）、递归实现「展开一片」、标记雷（插旗）、显示排雷用时等。展开一片指排查位置不是雷且周围也无雷时，向外成片展开，需用函数递归实现。
- **关键概念**：`递归`、`展开一片`、`标记`
- **出处**：鹏哥 P65, P66
