误当成「浅色/深色各 22 个」。这正是「同一批数字在文中被两处引用、却各自含义不同」的典型翻车。

### 2.6 ★ 静态服务没有「干净 URL」回退 —— 深链一律 404（本轮已修）

VitePress 产出的是**干净 URL**：站内链接写成 `/guide/sources`，不带 `.html`。
而 studio 的静态解析只做**字面路径**映射。实测（修复前）：

| 请求 | 修复前 | 修复后 |
| :-- | :-- | :-- |
| `/darling016123/guide/sources` | **404** | 200 |
| `/darling016123/learn/ielts-past-papers` | **404** | 200 |
| `/darling016123/guide/sources.html` | 200 | 200 |
| `/overseas-development-guide/career-immigration/career-02-preparation` | **404** | 200 |

**为什么一直没被发现**：VitePress 是 SPA，**站内点击走 Vue Router 客户端跳转**，根本不向服务器要那个 URL。
只有「直接输网址 / 新标签打开 / 复制链接」才会走服务端 —— 而那正是收藏和分享的路径。

**修法**：`serveStatic` 在 `statSync` 失败时，再试 `<path>.html`、`<path>/index.html` 两个候选；
都命中不了才 404。只在**原路径不存在**时才触发，所以既有行为一字不改。

**验证**（含负向）：
- 12 条挂载前缀回归 **12/12 通过**（改动前后一致）
- 4 条干净 URL **全部 404 → 200**
- 真不存在的路径**仍 404**（`/guide/不存在的页面`、`/overseas-development-guide/nope`）
- **带编码的穿越仍 403**（`..%2f` 走 `resolveMount` 的包含性校验）

### 2.7 门户自身后端源码可被 HTTP 读取（既有行为，记录但不修）

实测 `GET /server.js` → **200**，`/studio.js`、`/data.js`、`/focus.js`、`/anki.mjs` 同样可取。

**原因**：门户根资产路由的白名单 `SAFE_ROOT_EXT` 放行 `.js` / `.mjs`（前端三件套必须走这条路），
而它按**扩展名**判断，不区分「前端资产」和「后端源码」。于是后端源码一并可下载。

**为什么判定不必修**：
- 服务只绑 `127.0.0.1`，只有本机进程能访问；
- 本机进程**本来就能直接读这些文件**，HTTP 这条路没有扩大任何权限；
- 真要收紧，得把 `server.js` / `anki.mjs` / `scripts/` 加进显式拒绝名单 —— 收益接近零，却多一处需要维护的规则。

**顺带澄清一个看着像漏洞、其实不是的现象**：`GET /darling016123/../../server.js` 返回 **200**。
这不是穿越 —— URL 里的 `..` 会被 **WHATWG URL 归一化**掉，实际请求的是 `/server.js`，
落到上面那条**本来就存在**的门户根资产路由。已用 A/B 实测确认：改动前也是 200。

> 教训：**看到 200 先别下结论，先确认「这个 200 是新引入的还是本来就有的」。**
> 用 `git stash` 把改动收起来重跑一遍，是最省事的判法。

| classless 单文件主题（`new.css` / `simple.css` / Pico / sakura） | 它们假设"内容是无 class 的裸 HTML"。studio 的 8 个 CSS 文件 + 多视图结构建立在此基础上，换基座等于重写 |
| `@custom-media` | 09-17 已用**两次独立实测**证伪：`CSS.supports('at-rule(@custom-media)')` 返回 `false`，真实注入后 computed color 仍是 `rgb(0,0,0)` |
| 引入 htmx / van.js | 与「零依赖、无构建链」直接冲突。而且 studio 的交互复杂度还没到需要它们的程度 |

| 引入任何构建链（Vite / PostCSS / Tailwind） | `AGENTS.md` §9 明文禁止。`node server.js` 直接跑是这个项目的核心约束 |

#### P1 验证（都是「改结构不改外观」，用渲染零差异证明）

**① 抽 `tokens.css`** —— 判据是**层序规则数逐位对齐**，不是「看着没变」：

| 层 | 改前 | 改后 | 差 |
| :-- | --: | --: | :-- |
| `tokens` | — | **1** | 新增（那条 `:root`） |
| `base` | 253 | **252** | **−1**（搬走的就是 `:root`） |
| `layout` / `components` / `views.desk` / `views.word` / `views.focus` / `views.kaodian` / `views.review` | 10 / 0 / 41 / 31 / 42 / 40 / 74 | 同左，**一条不差** | 0 |
| 未分层（KaTeX） | 249 | 249 | 0 |
| **规则总数** | **740** | **740** | 0 |

一条规则从 `base` 挪到 `tokens`，其余全部零位移 —— 这就是「往层序最前面加一层没有位移任何东西」的证据。
另加：`tools/cdp-propdiff.mjs` **72 组（8 视图 × 9 档宽度）零差异**。

**② `:has()` 替掉 JS 加类** —— 分三步，缺一步都不能算证明：

1. **等价性**（新工具 `tools/compare-selectors.mjs`）：旧写法 `#view-plan > .plan-grid.is-lite`
   与新写法 `#view-plan > .plan-grid:has(> .plan-more)` 命中的 grid 与 4 个子元素
   **完全相同**（含窄屏那条 `:nth-child(n)`）。该工具另做 **3 组负向测试**（不存在选择器 /
   写错子级 / 非法语法）全部变红，退出码 1 —— 它真的会失败。
2. **变异测试**（关键）：故意把 `grid-column: 1 / 5` 改成 `1 / 3`，propdiff 立刻报出
   6 个元素差异（宽度 781px vs 1616px）。**这同时证明了 `:has()` 真的在参与渲染** ——
   若它匹配不到任何元素，变异必然报 0 差异。
   > 这一步是必需的：propdiff 报「0 差异」时你无法区分「新选择器生效且结果相同」与
   > 「新选择器根本没匹配到东西」。只有变异能分开这两种情况。
3. **回归**：还原后 md5 与变异前一致，再跑 propdiff **72 组零差异**。

**③ Node 24 污染退出码（顺手修掉的既有缺陷）** —— 一个「工具在说谎」的实例：

跑验收时报 5 项失败，但每个工具**自己的输出全是通过**。根因是这些工具末尾都是
`ws.close(); process.exit(X);`，而 `ws.close()` 是异步的、`process.exit()` 会立刻拆句柄，
Node 24 在 Windows 上因此撞 libuv 断言，退出码变 `0xC0000409`，被 `acceptance.mjs` 的
`ok = !err` 判成失败。

| Node | `check-view.mjs plan` 退出码 | 断言 |
| :-- | :-- | :-- |
| v22.22.2 | **0** | 无 |
| v24.19.0 | 非零 | 出现 |

改成 `process.exitCode = X`（8 个工具）后，**Node 22 与 Node 24 都是 12 通过 / 0 失败**。
顺带排除两个错误方向：**不是负载**（停掉并行实例照样必现）、**不是「等 close 再 exit」能解决**
（实测仍断言）。

**④ 验证过程中还有一次「假警报」，判法值得记下来。**

最终全量对照曾报 **72 组里 1 个元素不同** —— `small#wm-meta`（背词本元信息行）。
CSS 一个字节没改，真因是 A/B 对照台的构造问题：副本的 `data/word-master-progress.json`
冻在**复制时刻 20:10**，而原目录在 **20:37** 被门户自己重写过。

- **判据**：差异**只集中在读 `data/` 的那几个元素**（`#wm-meta`、Pomodoro 相关），
  且每次跑位置/数量都变 ⇒ 先怀疑数据漂移，别去翻 CSS。
  两边各取一次接口直接比 md5 最省事：
  `curl -s http://127.0.0.1:43210/api/word | md5sum` vs `…:43211/api/word | md5sum`。
- **正解**：让副本的 `data/` 变成**指向原目录的 junction**（Windows 建 junction 不需要管理员权限），
  两个实例从此读同一份文件，这类假阳性整类消失。
  `server.js` 文件头本来就写着「`data/` 是共享目录」，指的正是这个安排。
- **修好后重跑：72 组零差异。** 完整说明已写进 `tools/README.md` 的 A/B 章节。
