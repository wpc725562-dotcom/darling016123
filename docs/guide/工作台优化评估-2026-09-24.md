# 工作台优化评估（2026-09-24）

> 评估对象：`D:\studio`（专升本作战台，`127.0.0.1:43210`，零依赖 Node 门户）。
>
> 这份文档**不重复** 09-17 那份 GitHub 调研（`studio/docs/github-references.html` 已经做完项目筛选与 Chrome 能力实测）。
> 它做的是三件事：**核查那份研究的建议哪些真落地了**、**补本轮新发现的问题**、**给出下一批动作**。

## 〇、结论先行

1. **09-17 的 6 项建议，落地 3 项、未落地 3 项。** 已落地：`@container` 断点（P0）、CSS 按视图拆分（P1）、`color-mix()` 收派生色（P1）。未落地：`:has()` 替 JS 切列（P0）、装饰性伪元素 a11y 替代文本（P2）、vendor open-props 纯变量文件（P2）。
2. **本轮抓到 1 个"照文档做会失败"的缺陷：`AGENTS.md:174` 让用 `restart-studio.mjs` 重启服务，而这个文件在整台机器上不存在。** 这是全库 41 个被点名文件里唯一悬空的一个。
3. **studio 最大的技术风险不是 CSS 不够现代，是「静默故障」。** 门户卡片指向的挂载目录被删了，卡片还在、点进去是 404，没有任何提示。
4. **拆分做了一半：8 个 CSS 文件已拆，但共享变量层没抽出来** —— 23 个自定义属性仍挤在 `studio.css`（678 行，仍是最大文件）。
5. **不值得继续追的方向已经很清楚**：不引入构建链、不抄 classless 主题、不引 htmx/van.js。理由见第五节。

## 二、本轮新发现

### 2.1 ★ 文档引用了不存在的脚本（`AGENTS.md:174`）

```
AGENTS.md:174  ⚠️ 改完 server.js 必须重启 43210 进程，否则跑的还是旧代码。重启用 restart-studio.mjs
```

`restart-studio.mjs` 在 `D:\studio`、笔记库、用户目录递归查找后**不存在**（只找到 `logs/portal-restart.out` 一个日志文件）。

**为什么这条优先级最高：** 它不是"少了个便利脚本"。`AGENTS.md` 是这份代码库的操作契约，第 174 行明确说"改完 server.js 必须重启"、并给出了重启方式。按文档操作的人会在这一步卡住，然后**自己想办法 kill 进程** —— 而 `AGENTS.md` 别处还写着"别误杀 studio 的 43210 进程"。两条约束在这里互相打架。

**两种修法（都不难，选一个就行）：**

- **修文档**：把第 174 行改成实际的重启方式（例如「结束占用 43210 的 node 进程后重跑 `start-studio.cmd`」），并说明怎么确认新代码已生效。
- **补脚本**：写一个 `restart-studio.mjs`，做三件事 —— 找占用 43210 的进程、只结束它、重跑启动器并轮询到 HTTP 200。这样文档不用改，且"别误杀"这条约束被脚本固化了。

> 推荐后者：把容易做错的动作（杀对进程、等到真的起来）固化成脚本，比写一段文字说明更可靠。

### 2.2 拆分只做了一半：没有共享变量层

8 个 CSS 文件已经按视图拆开了，但**变量没有下沉**：

| 文件 | 自定义属性数 |
| :-- | --: |
| `studio.css` | **23** |
| `layout.css` | 3 |
| `app.css` / `focus.css` / `kaodian.css` / `review.css` | 各 1 |
| `desk.css` / `word.css` | 0 |

`studio.css` 仍是最大的文件（678 行），因为它同时承担了「共享 tokens」和「主视图样式」两个职责。09-17 建议里那句「共享部分下沉到一个 `tokens.css`」正是没做的那一半。

**影响：** 想让 `kaodian.css` 引用一个主色，它得依赖 `studio.css` 先加载。`@layer` 解决了**顺序**问题，没解决**职责归属**问题。

### 2.3 残留一处视口断点，且没写理由

```
studio.css:223  @media (max-width: 980px) { .topbar { flex-wrap: wrap; } }
```

其余断点都改成 `@container` 了，只剩这一处。**它其实是对的** —— `.topbar` 是视口级元素（横跨整个窗口），它的换行本来就该看视口宽度而不是容器宽度。

**问题是它没写理由。** 这个仓库的习惯是给每个"看起来该改但故意没改"的地方写注释（例如 `studio.css:174` 就解释了为什么从 `@media` 改成 `@container`）。缺注释的后果是：下一个人会把它当漏网之鱼改掉。

### 2.4 已实测可用但零使用的特性

09-17 的 Chrome 152 能力表里标注"可用"，当前使用情况：

| 特性 | 使用数 | 能解决什么 |
| :-- | --: | :-- |
| `light-dark()` | **0** | 现在浅色/深色主题变量是**手写两份**（各 22 个）。`light-dark()` 能把它们合并成一行一处 |
| `oklch()` | 0 | 色阶插值更均匀，做 hover 派生色时不会发灰 |
| `@scope` | 0 | 替代 BEM 式长选择器 |
| `@starting-style` | 0 | 元素首次出现时的入场动画（不用 JS 加 class） |
| `subgrid` | 0 | 卡片内多行对齐（现在靠固定高度硬凑） |
| `field-sizing` | 0 | 输入框随内容自适应（现在靠 JS 或固定宽度） |

> 其中 **`light-dark()` 的收益最直接**：能一次性消掉约 22 行重复的主题变量声明，且不可能改变渲染结果（属于"改结构不改外观"的零风险重构）。

### 2.5 文档路径引用没有校验机制

本轮把 `AGENTS.md` 里所有反引号包起来的文件路径抽出来逐个查存在性，共 **41 个**，其中 **1 个悬空**（就是 2.1 的 `restart-studio.mjs`）。

其余"看着缺失"的都是误报，已核实：

| 引用 | 结论 |
| :-- | :-- |
| `package.json` | **刻意不存在** —— `AGENTS.md:14` 明写「没有 `package.json`，没有 bundler」 |
| `_coverage.json` / `_merged.json` | 路径在**笔记库**侧：`zhuan-sheng-ben-notes/data/bili-analyze/_extract/`（实测 50.5 KB / 1.23 MB，存在） |
| `scripts/bili_merge_extract.mjs` | 在**笔记库**侧（实测 44.7 KB，存在） |
| `study-progress.json` / `word-master-progress.json` | 在 `studio/data/` 下，运行时生成、已 gitignore（实测存在） |

> **可复用的做法**：把「文档里的文件路径当引用去校验」做成一个检查。悬空引用比断链隐蔽得多 —— 没有任何现成工具会检查它。

## 三、值得借鉴的做法

按"是否该抄"分三类，避免把已经抄到位的又重抄一遍。

### 3.1 已经抄到位，应继续保持

| 做法 | 来源 | 现状 |
| :-- | :-- | :-- |
| 容器查询替代视口断点 | Glance `utils.css` 全篇如此 | 13 处，已全量落地 |
| `color-mix()` 派生色 | 现代 CSS 原生 | 50 处，已全量落地 |
| `@layer` 管理层序 | 原生 | 10 处 |
| 零依赖、无构建链 | 项目自身选择 | 无 `package.json`、无 bundler |
| 用 CDP 直连做回归验证（`tools/` 20 个工具 + `acceptance.mjs`） | 项目自建 | 比引 Playwright 更轻，且**不需要装依赖** |
| 「渲染零差异」作为重构验收标准 | 项目自建 | 已用于 `@container` 与 `color-mix()` 两次重构 |

> 最后一条尤其值得点出来：**这是这个项目最值钱的工程习惯** —— 重构 CSS 时用真实浏览器比对 computed style，把"零差异"当验收门槛。多数项目重构样式靠肉眼看，这个项目有证据。

### 3.2 该抄但还没抄

| 做法 | 来源 | 为什么值得 |
| :-- | :-- | :-- |
| `:has()` 替掉 JS 分支 | Glance 的 `.dynamic-columns:has(> :nth-child(3))` | 五行 CSS 顶掉一段 JS 判断，且不再需要"数据变了要重算列数"的事件监听 |
| `content: '…' / ""` | Glance `utils.css` 多处 | 读屏不会把装饰性间隔号念出来。**当前 0 处，属 a11y 缺口** |
| 共享 `tokens.css` 下沉 | Glance 25 个 CSS 文件、最大 16.6 KB 的组织方式 | 补上拆分没做完的那一半 |
| vendor open-props 的纯变量文件 | open-props | 只挑 `props.colors-hsl.css` / `props.shadows.css` / `props.easing.css` / `props.sizes.css` —— 内容是纯 `:root` 自定义属性，无 at-rule 依赖，可直接 vendor |
| `light-dark()` 合并双份主题变量 | 原生 | 见 2.4，零风险重构 |

### 3.3 明确不必抄

| 做法 | 为什么不抄 |
| :-- | :-- |
| classless 单文件主题（`new.css` / `simple.css` / Pico / sakura） | 它们假设"内容是无 class 的裸 HTML"。studio 的 8 个 CSS 文件 + 多视图结构建立在此基础上，换基座等于重写 |
| `@custom-media` | 09-17 已用**两次独立实测**证伪：`CSS.supports('at-rule(@custom-media)')` 返回 `false`，真实注入后 computed color 仍是 `rgb(0,0,0)` |
| 引入 htmx / van.js | 与「零依赖、无构建链」直接冲突。而且 studio 的交互复杂度还没到需要它们的程度 |
| 整套 open-props | 只 vendor 纯变量文件即可，全量引入会带来大量用不到的 token |
| 引入任何构建链（Vite / PostCSS / Tailwind） | `AGENTS.md` §9 明文禁止。`node server.js` 直接跑是这个项目的核心约束 |

## 五、不要做的事

这些是 `AGENTS.md` 明文约束，评估时一并列出，避免"优化"名义下的越界：

- **不要把笔记正文复制进 Studio。** 内容归笔记库，Studio 只做导航。（§9）
- **不要给 Studio 引入构建链。**（§9）
- **不要动 `logs/` / `anki-backup/` / `beaverhabits-data/` / `data/`。**（§9）
- **改 CSS 必须做「渲染零差异」证明。**（§6.2）
- **改完 `server.js` 必须重启 43210 进程。**（§6.2 —— 注意 2.1：这条现在没有可用的脚本）
- **`start-studio.ps1` 必须保持纯 ASCII。** GBK 解码会让中文注释挂掉。（§1）

以及一条不属于技术约束、但写在 `AGENTS.md` §8 里的底线：

> 改 Studio 之前，先问一句：**今天的学习落账了吗？** 这个项目最大的风险不是 bug，是它变成**逃避学习的舒适区**。
