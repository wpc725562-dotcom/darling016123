# 下午题 02 · 数据库设计（E-R 模型）

> 位置：下午场第 2 题（约 15 分）
> 难度：中。**四问结构固定**，但"范式判断"是最容易丢分的一问。

---

## 一、题目长什么样

给你一段业务描述，配一张**不完整的 E-R 图**，然后四问：

1. **补充 E-R 图中的联系**（填联系名、联系类型，或补连线）
2. **将 E-R 图转换为关系模式**（写出每张表的属性，标出主键）
3. **指出外键**
4. **判断某关系模式最高属于第几范式，说明理由**

有时还会问："若改为 m:n 联系，关系模式应如何调整？"

---

## 二、第 1 问：补 E-R 图

### 联系类型判断

| 类型 | 判断依据 | 题干特征 |
|:---|:---|:---|
| **1:1** | 一个 A 对应一个 B | "一个部门只有一个负责人" |
| **1:n** | 一个 A 对应多个 B，一个 B 只对应一个 A | "一个班级有多个学生，一个学生只属于一个班级" |
| **m:n** | 互相都能对应多个 | "一个学生选多门课，一门课被多个学生选" |

### 判断方法

**对每个实体问两句**：
- 一个 A 能对应几个 B？
- 一个 B 能对应几个 A？

两个都是"多个" → m:n
一个多个一个单个 → 1:n
两个都是"一个" → 1:1

### 易错点

- **联系也可能有属性**。题干说"学生选修课程，记录成绩"——"成绩"是**联系"选修"的属性**，不是学生的属性，也不是课程的属性。
- 题干里的"可以""允许""多个"是关键词，别漏读。

---

## 三、第 2 问：E-R 转关系模式（核心）

### 三条转换规则

| 联系类型 | 转换方法 |
|:---|:---|
| **1:1** | 把一方的主键放到另一方作外键（通常放"参与度低"的那方） |
| **1:n** | **把 1 端的主键放到 n 端作外键** |
| **m:n** | **必须单独建一张表**，主键 = 两个实体主键的组合，联系自身的属性也放进来 |

### 转换步骤

1. 每个**实体** → 一张表，属性照抄，选主键
2. 每个**联系**按上表处理
3. **检查**：所有属性都有归属，没有遗漏

### 标准写法

```
学生(学号, 姓名, 性别, 班级号)
班级(班级号, 班级名称, 班主任)
课程(课程号, 课程名, 学分)
选修(学号, 课程号, 成绩)
```

**必须标出主键**（下划线或注明），否则扣分。

### 易错点

| 错误 | 正确做法 |
|:---|:---|
| m:n 联系合并到某一方 | 必须单独建表 |
| 外键放在 1 端 | 外键放在 **n 端** |
| 忘记联系的属性 | 联系有属性时，转换后要带上 |
| 主键不唯一 | 检查能否唯一确定一行 |

### 例

"一个学生可以选多门课，一门课可被多个学生选，选修有成绩"

❌ 错误：`学生(学号, 姓名, 课程号, 成绩)` —— 一个学生选多门课就存不下
✅ 正确：`学生(学号, 姓名)` + `课程(课程号, 课程名)` + `选修(学号, 课程号, 成绩)`

## 四、第 3 问：指出外键

**外键 = 另一张表的主键，出现在本表里**。

### 快速定位法

看关系模式，凡是**某个属性在另一张表里是主键**，它就是外键。

```
学生(学号, 姓名, 班级号)      ← 班级号 是外键，引用 班级(班级号)
班级(班级号, 班级名称)
选修(学号, 课程号, 成绩)      ← 学号、课程号 都是外键
```

### 答题格式

> 学生表中的"班级号"是外键，引用班级表的主键"班级号"。

**要说明引用关系**，只说"班级号是外键"不够完整。

## 五、第 4 问：范式判断（最容易丢分）

### 判定流程（照着走）

**第 1 步：找候选键**

候选键 = 能唯一确定一行、且**最小**的属性集。

- 单属性能确定 → 单属性键
- 需要多个属性组合 → 组合键

**第 2 步：分主属性 / 非主属性**

- 主属性：包含在**任一候选键**中的属性
- 非主属性：不在任何候选键中的属性

**第 3 步：逐级判定**

| 检查 | 不满足则 | 满足则 |
|:---|:---|:---|
| 有没有非原子属性？ | 不是 1NF | 是 1NF，继续 |
| 非主属性对候选键有**部分依赖**吗？ | 不是 2NF | 是 2NF，继续 |
| 非主属性对候选键有**传递依赖**吗？ | 不是 3NF | 是 3NF，继续 |
| 每个函数依赖的左部都含候选键吗？ | 不是 BCNF | 是 BCNF |

### 关键判断技巧

**如果候选键是单属性**：
- 一定满足 2NF（不存在"部分"）
- 只需检查传递依赖 → 判断 3NF

**如果候选键是组合属性**：
- 检查有没有非主属性只依赖其中一部分 → 有则不是 2NF

### 典型例子

**例 1**：`学生(学号, 姓名, 系号, 系主任)`
- 候选键：学号（单属性）
- 依赖：学号→姓名，学号→系号，系号→系主任
- 学号→系号→系主任 是**传递依赖**
- 结论：**2NF**（满足 2NF，不满足 3NF）

**例 2**：`选修(学号, 课程号, 成绩)`
- 候选键：(学号, 课程号) 组合键
- 依赖：(学号,课程号)→成绩，成绩完全依赖整个键
- 结论：**3NF**（也是 BCNF）

**例 3**：`选课(学号, 课程号, 课程名, 成绩)`
- 候选键：(学号, 课程号)
- 依赖：(学号,课程号)→成绩，但 课程号→课程名（只依赖一部分）
- 课程名对组合键是**部分依赖**
- 结论：**1NF**（不满足 2NF）

### 答题模板

> 该关系模式最高属于 **2NF**。
> 理由：候选键为"学号"（单属性），不存在部分函数依赖，故满足 2NF；但存在"学号→系号，系号→系主任"的传递函数依赖，不满足 3NF。

**必须写出依赖链**，只写"有传递依赖"不给满分。

## 六、易错点清单

| 错误 | 后果 | 正确做法 |
|:---|:---|:---|
| m:n 联系合并进实体 | 该问全错 | 单独建表 |
| 外键方向搞反 | 扣分 | 1 端主键 → n 端 |
| 忘记联系自身的属性 | 扣分 | 联系有属性要带上 |
| 范式判断只说结论不说理由 | 扣一半分 | 写出依赖链 |
| 把"3NF"和"BCNF"搞混 | 扣分 | BCNF 要求所有依赖左部含候选键 |
| 主键没标出来 | 扣分 | 下划线标注 |

## 七、示例题（自编，非真题）

> 按考点自编，非真题。

**背景**：某医院管理系统中，一个科室有多名医生，一名医生只属于一个科室；一名医生可以为多名患者诊治，一名患者也可以被多名医生诊治；每次诊治记录诊治日期和诊断结果。

**问题**：
1. 医生与科室是什么联系？医生与患者是什么联系？
2. 转换为关系模式。
3. 指出外键。
4. 诊治关系模式最高属于第几范式？

**参考答案**：

1. 医生—科室：**1:n**（一个科室多名医生，一名医生一个科室）
   医生—患者：**m:n**（互相都能对应多个）

2. 关系模式：

   ```
   科室(科室号, 科室名称)
   医生(医生号, 姓名, 职称, 科室号)
   患者(患者号, 姓名, 性别, 年龄)
   诊治(医生号, 患者号, 诊治日期, 诊断结果)
   ```
   主键分别是：科室号 / 医生号 / 患者号 / (医生号, 患者号, 诊治日期)
   （若同一医生同一天对同一患者只诊治一次，则主键可为 (医生号, 患者号, 诊治日期)；否则需要加流水号）

3. 医生表中的"科室号"引用科室表主键；诊治表中的"医生号"引用医生表主键，"患者号"引用患者表主键。

4. 诊治关系模式最高属于 **3NF**。
   候选键为 (医生号, 患者号, 诊治日期)，非主属性"诊断结果"完全依赖于整个候选键，不存在部分依赖；也不存在非主属性之间的传递依赖。故满足 3NF。

## 八、练习建议

1. 重点练**转换规则**：m:n 单独建表、1:n 外键放 n 端，这两个是铁律
2. 范式判断**必须动手写依赖链**，不能只在脑子里想
3. 每做完一套，检查自己的关系模式有没有**遗漏属性**

**目标**：这道题拿 10 分以上（满分约 15）。范式那一问丢 2–3 分是常见的，不要紧。
