## H1 面向对象基本概念 ★★★ L1

| 概念 | 一句话 | 考题特征 |
|:---|:---|:---|
| **封装** | 隐藏内部实现，只暴露接口 | "外部不能直接访问私有属性" |
| **继承** | 子类复用父类，可扩展 | "is-a" 关系 |
| **多态** | 同一消息，不同对象不同响应 | "运行时才确定调用哪个方法" |
| **抽象** | 提取共性，忽略细节 | 抽象类、接口 |

**多态的两种绑定**：
- **静态绑定**（编译时）：重载（overload）——同名不同参
- **动态绑定**（运行时）：重写（override）——子类覆盖父类方法

**必考判断**：重载是编译时多态，重写是运行时多态。

## H2 UML 图分类 ★★★ L2

### 结构图（静态）vs 行为图（动态）

| 类别 | 图 | 用途 | 关键词 |
|:---|:---|:---|:---|
| **结构图** | 类图 | 类与类的关系 | 静态结构 |
| | 对象图 | 某一时刻的对象快照 | 实例 |
| | 组件图 | 软件组件及依赖 | 构件 |
| | 部署图 | 硬件节点与部署 | 物理部署 |
| | 包图 | 分组 | 组织 |
| **行为图** | **用例图** | 系统与外部参与者的交互 | 谁用什么功能 |
| | **活动图** | 业务流程、并发 | 流程、并行 |
| | **状态图** | 对象的状态变迁 | 状态、事件触发 |
| | **时序图**（顺序图） | 对象间按时间顺序的消息 | 消息先后 |
| | 协作图（通信图） | 对象间的链接关系 | 强调结构 |

### 高频对应关系（背下来）

| 题目问 | 选 |
|:---|:---|
| 系统有哪些功能、谁来用 | **用例图** |
| 业务流程、审批流 | **活动图** |
| 一个订单从"待支付"到"已发货"的变化 | **状态图** |
| 多个对象按时间顺序发消息 | **时序图** |
| 类与类的静态关系 | **类图** |
| 软件装在哪台服务器上 | **部署图** |

### 易错点

- **活动图**画的是"流程"，**状态图**画的是"一个对象的状态"。题目主语是"业务流程"选活动图，是"某个对象"选状态图。
- **时序图**强调时间顺序（有生命线），**协作图**强调对象间的链接（有编号）。
- 用例图中，参与者（Actor）可以是人，也可以是**外部系统**。

## H3 类图关系 ★★★ L2

### 六种关系，从弱到强

| 关系 | 符号 | 语义 | 例子 |
|:---|:---|:---|:---|
| **依赖** | 虚线箭头 `- ->` | 临时使用，一方变化影响另一方 | 人用计算器 |
| **关联** | 实线 `——` | 长期的结构关系 | 老师教学生 |
| **聚合** | 空心菱形 `◇——` | 整体与部分，**部分可独立存在** | 班级与学生 |
| **组合** | 实心菱形 `◆——` | 整体与部分，**同生共死** | 人与心脏 |
| **泛化**（继承） | 空心三角实线 `——▷` | is-a | 学生是人 |
| **实现** | 空心三角虚线 `- -▷` | 类实现接口 | 类实现 Runnable |

**强弱排序**：依赖 < 关联 < 聚合 < 组合 < 泛化/实现

### 聚合 vs 组合（最常考）

判断标准：**整体消失，部分还在吗？**

- 在 → 聚合（空心菱形）。例：班级解散，学生还在。
- 不在 → 组合（实心菱形）。例：人死了，心脏不能独立活。

**记忆**：空心=松，实心=紧。

### 易错点

- 菱形永远在**整体**那一端，不是部分那端。
- 泛化是"is-a"，聚合/组合是"has-a"。
- 依赖是最弱的关系，通常表现为"作为方法的参数或局部变量使用"。

## H4 设计模式分类 ★★★ L2

### 三大类，23 种

| 类别 | 数量 | 解决什么问题 | 代表 |
|:---|:---:|:---|:---|
| **创建型** | 5 | 怎么创建对象 | 单例、工厂方法、抽象工厂、建造者、原型 |
| **结构型** | 7 | 怎么组合类和对象 | 适配器、桥接、组合、装饰器、外观、享元、代理 |
| **行为型** | 11 | 对象间怎么通信与分配职责 | 观察者、策略、模板方法、命令、状态、职责链、中介者、迭代器、访问者、备忘录、解释器 |

**记忆口诀**：
- 创建型 5：**单工抽建原**
- 结构型 7：**适桥组装外享代**
- 行为型 11：**观策模命状链中迭访备解**

## H5 常见设计模式识别 ★★★ L2

这是本域**最常考**的部分。题目给一段场景描述，问"应采用哪种设计模式"。

| 模式 | 识别特征（看到这些词就选它） |
|:---|:---|
| **单例 Singleton** | "全局唯一实例"、"只能有一个"、日志器、配置管理器、连接池 |
| **工厂方法 Factory** | "不关心具体类"、"由子类决定创建哪种" |
| **抽象工厂 Abstract Factory** | "一族相关产品"、"换皮肤"、"跨平台 UI 组件" |
| **建造者 Builder** | "分步骤构建复杂对象"、"组装"、套餐配置 |
| **原型 Prototype** | "克隆"、"复制现有对象" |
| **适配器 Adapter** | "接口不兼容"、"转换"、"复用老代码" |
| **装饰器 Decorator** | "动态增加功能"、"一层层包装"、Java IO 流 |
| **代理 Proxy** | "控制访问"、"远程代理"、"延迟加载"、"权限控制" |
| **外观 Facade** | "简化复杂子系统"、"统一入口" |
| **观察者 Observer** | "一对多依赖"、"状态变化通知"、事件监听、订阅 |
| **策略 Strategy** | "多种算法可互换"、"运行时切换"、支付方式、排序算法选择 |
| **模板方法 Template** | "固定流程，部分步骤可变"、钩子方法 |
| **命令 Command** | "把请求封装成对象"、撤销/重做、队列请求 |
| **状态 State** | "状态改变行为也改变"、订单状态机 |
| **职责链 Chain** | "逐级处理"、"审批流"、"过滤链" |

### 易错点（最容易混淆的三组）

**1. 策略 vs 状态**
- 策略：由**客户端**选择用哪个算法，算法之间**不知道彼此**
- 状态：由**对象自己**在状态变化时切换到下一个状态，状态之间**知道彼此**

**2. 适配器 vs 装饰器**
- 适配器：**改变接口**，让不兼容的能用
- 装饰器：**不改变接口**，只增加功能

**3. 代理 vs 装饰器**
- 代理：**控制访问**，通常只有一个被代理对象，客户端不知道代理的存在
- 装饰器：**增强功能**，可以层层嵌套

## H6 面向对象设计原则（SOLID）★★ L2

> **教材 7.3，原版本遗漏，2026-10-29 补入**。

| 原则 | 英文 | 一句话 |
|:---|:---|:---|
| **单一职责** | SRP | 一个类只负责**一件事**，只有一个引起它变化的原因 |
| **开闭** | OCP | 对**扩展开放**，对**修改关闭** |
| **里氏替换** | LSP | **子类可以替换父类**而不影响程序正确性 |
| **依赖倒置** | DIP | 依赖**抽象**，不依赖具体实现 |
| **接口隔离** | ISP | 接口要**小而专**，不要强迫实现用不到的方法 |

**开闭原则是总纲**：几乎所有设计模式都在实现它——用扩展代替修改。

**常考问法**："以下哪项违反了 XX 原则"。
- 一个类既管数据库又管日志 → 违反**单一职责**
- 每加一个功能就要改原有代码 → 违反**开闭**
- 子类重写父类方法后行为异常 → 违反**里氏替换**

## H7 面向对象分析（OOA）五个层次 ★ L1

> **教材 7.2，原版本遗漏，2026-10-29 补入**。偶尔考"OOA 分哪几个层次"。

教材采用 Coad/Yourdon 方法，分五层：

| 层次 | 做什么 |
|:---|:---|
| **主题层** | 划分子系统（把大系统分成几个主题） |
| **对象类层** | 识别类和对象 |
| **结构层** | 识别类间关系（分类结构、组装结构） |
| **属性层** | 定义类的属性 |
| **服务层** | 定义类的操作（方法） |

**两个结构**：
- **分类结构** = 继承（is-a）
- **组装结构** = 组合/聚合（has-a）
