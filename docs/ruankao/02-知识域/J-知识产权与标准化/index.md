## J1 著作权（版权）★★★ L1

### 三个核心特点

1. **自动产生**：作品完成即享有著作权，**不需要登记**
2. **保护的是表达，不是思想**：算法思想不受保护，但代码实现受保护
3. **保护期**：作者**终身 + 死后 50 年**（署名权、修改权、保护作品完整权**永久**保护）

### 归属判定（高频）

| 情形 | 归属 |
|:---|:---|
| **职务作品** | 一般归**作者**，单位有优先使用权；但**主要利用单位物质技术条件**创作、单位担责的，归**单位** |
| **委托作品** | 有合同按合同；无合同归**受托方**（创作者） |
| **合作作品** | 共同享有，可分割的各自享有 |
| **软件著作权** | 归**开发者**；职务开发归单位 |

**软件开发常考**：程序员在职期间为本职工作开发的软件，著作权归**单位**。

### 不受保护的对象

- 思想、处理过程、操作方法、数学概念
- 法律法规、国家机关公文
- 时事新闻
- 历法、通用表格

## J2 专利权与商标权 ★★ L1

### 专利三种类型

| 类型 | 保护对象 | 期限 | 特点 |
|:---|:---|:---:|:---|
| **发明** | 产品、方法或其改进 | **20 年** | 技术要求最高 |
| **实用新型** | 产品的形状、构造 | **10 年** | 技术要求较低 |
| **外观设计** | 产品的形状、图案、色彩 | **15 年** | 只保护外观 |

**必须申请才享有**（与著作权不同）。

**新颖性要求**：申请前不能公开。公开了就不能再申请（除非有宽限期）。

### 商标权

- 期限 **10 年**，可**无限续展**
- 需注册
- 分类注册（45 个类别）

### 三者的核心区别

| | 著作权 | 专利权 | 商标权 |
|:---|:---|:---|:---|
| 产生方式 | **自动** | 申请 | 申请 |
| 保护对象 | 表达 | 技术方案 | 标识 |
| 期限 | 终身+50 年 | 20/10/15 年 | 10 年可续 |

## J3 侵权判定 ★★ L1

### 不构成侵权的行为

| 行为 | 说明 |
|:---|:---|
| **合理使用** | 个人学习研究、新闻报道、教学科研、免费表演等，**不经许可不付费** |
| **法定许可** | 不经许可但**要付费**（如转载、录音） |
| **强制许可** | 特定条件下政府批准使用 |

### 常见判定

- **修改开源代码后闭源发布**：如果许可证是 GPL，**侵权**（GPL 要求衍生作品也开源）；如果是 MIT/Apache，**不侵权**（只需保留版权声明）
- **买正版软件装在多台电脑**：超出许可数量即侵权
- **反向工程**：为兼容目的可能合法，为复制则侵权

### 易错点

- **合理使用不需要付费**，法定许可需要付费。这两个别混。
- 开源许可证不是"随便用"，不同许可证约束不同。

## J4 标准化 ★ L1

### 标准分级

| 级别 | 代号 | 说明 |
|:---|:---|:---|
| **国际标准** | ISO、IEC、ITU | 国际组织制定 |
| **国家标准** | **GB**（强制）、**GB/T**（推荐） | 中国国家标准 |
| **行业标准** | SJ（电子）、YD（通信）等 | 部委制定 |
| **地方标准** | DB | 省级 |
| **企业标准** | Q | 企业自己 |

**关键**：**GB 是强制性标准，GB/T 是推荐性标准**。这是必考点。

### 标准有效期

一般 **5 年**复审一次。

## J5 开源许可证 ★★ L1

> **教材 11.2 提到，原版本遗漏，2026-10-29 补入**。考试偶尔考，而且和你的开发者身份相关。

### 四类主流许可证

| 许可证 | 传染性 | 商用 | 修改后是否必须开源 |
|:---|:---|:---:|:---|
| **GPL** | **强传染** | 可以 | **必须开源**（衍生作品也 GPL） |
| **LGPL** | 弱传染 | 可以 | 动态链接可不开源，静态链接要 |
| **MIT / BSD** | 无 | 可以 | **不需要**，只需保留版权声明 |
| **Apache 2.0** | 无 | 可以 | 不需要，且**附带专利授权** |

### 关键概念：传染性（Copyleft）

**GPL 的传染性**：你的代码只要**链接/包含**了 GPL 代码，你的整个作品就必须也以 GPL 发布。

**这就是商业公司最怕 GPL 的原因**——用了就不能闭源。

### 常考判断

| 场景 | 是否侵权 |
|:---|:---|
| 修改 GPL 代码后**闭源**发布 | **侵权** |
| 修改 MIT 代码后闭源发布 | **不侵权**（保留声明即可） |
| 用 GPL 库做内部系统，不对外分发 | 通常**不侵权**（GPL 约束的是"分发"） |
| 用 LGPL 库动态链接，自己的代码闭源 | **不侵权** |

### 易错点

- **MIT 是最宽松的**（几乎随便用），**GPL 是最严的**
- **"开源"不等于"免费"**，也不等于"可以随便用"
- **不分发就不触发 GPL**（SaaS 场景下 GPL 有争议，AGPL 才是补这个洞的）
