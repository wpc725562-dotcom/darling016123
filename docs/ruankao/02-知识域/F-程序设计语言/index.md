## F1 编译 vs 解释 ★★ L1

| | 编译 | 解释 |
|:---|:---|:---|
| 产物 | **目标代码**（可执行文件） | 不生成目标代码 |
| 执行速度 | **快**（一次编译多次运行） | 慢（每次都要解释） |
| 跨平台 | 差（要为每个平台编译） | **好**（有解释器就能跑） |
| 例子 | C、C++、Go | Python、JavaScript |

**混合型**：Java 先编译成字节码，再由 JVM 解释/即时编译执行。

## F2 编译过程五阶段 ★★★ L2

**这是本域最常考的点，顺序必须记死。**

```
源程序
  ↓ ① 词法分析
记号流（Token）
  ↓ ② 语法分析
语法树
  ↓ ③ 语义分析
带语义的中间表示
  ↓ ④ 中间代码生成
中间代码（四元式、三地址码）
  ↓ ⑤ 优化
优化后的中间代码
  ↓ ⑥ 目标代码生成
目标代码
```

### 各阶段做什么（必考）

| 阶段 | 输入 → 输出 | 能发现什么错误 |
|:---|:---|:---|
| **词法分析** | 字符流 → 记号流 | 非法字符、拼写错误（如 `whi1e`） |
| **语法分析** | 记号流 → 语法树 | 语法结构错误（如缺分号、括号不匹配） |
| **语义分析** | 语法树 → 带语义的树 | **类型不匹配**、变量未声明、除数为 0（常量） |
| **中间代码生成** | 语义树 → 中间代码 | — |
| **优化** | 中间代码 → 更优的中间代码 | — |
| **目标代码生成** | 中间代码 → 机器码 | — |

**关键判断**：
- **词法错误**：字符不合法
- **语法错误**：结构不合法
- **语义错误**：结构合法但意思不对（类型不匹配是典型）

### 符号表

贯穿整个编译过程，记录标识符的属性（类型、作用域、地址）。**词法分析时建立，语义分析时填充**。

### 易错点

- 顺序不能错：词法 → 语法 → 语义。
- **静态语义错误**（类型检查）在语义分析阶段发现；**动态语义错误**（除零、数组越界）在运行时才能发现。

## F3 文法与语言分类 ★ L2

### 乔姆斯基四类文法

| 类型 | 名称 | 说明 | 对应自动机 |
|:---|:---|:---|:---|
| **0 型** | 短语文法 | 最一般 | 图灵机 |
| **1 型** | 上下文有关文法 | 产生式左部长度 ≤ 右部 | 线性界限自动机 |
| **2 型** | **上下文无关文法** | 左部是单个非终结符 | **下推自动机** |
| **3 型** | **正规文法** | 产生式形如 A→aB 或 A→a | **有限自动机** |

**程序设计语言通常用 2 型（上下文无关文法）描述语法**，用 3 型（正规式）描述词法。

**包含关系**：3 型 ⊂ 2 型 ⊂ 1 型 ⊂ 0 型

### 易错点

- 语法分析用**上下文无关文法**（2 型），词法分析用**正规式**（3 型）。这两个别搞反。

## F4 数据类型与程序控制 ★ L1

### 表达式三种表示

中缀 `a + b`、前缀 `+ a b`、后缀 `a b +`

**中缀转后缀**：遇到操作数直接输出，遇到运算符按优先级出栈。

**后缀求值**：遇到操作数入栈，遇到运算符弹出两个计算再入栈。

### 传值 vs 传引用

见 F5。

## F5 参数传递 ★★ L2

| 方式 | 说明 | 改形参影响实参吗 |
|:---|:---|:---|
| **传值**（值调用） | 把实参的值复制给形参 | **不影响** |
| **传址**（引用调用） | 把实参的地址给形参 | **影响** |
| **传名** | 类似宏替换，用到时才求值 | 视情况 |

### 例

```c
void swap(int a, int b) { int t=a; a=b; b=t; }   // 传值，调用后实参不变
void swap(int *a, int *b) { int t=*a; *a=*b; *b=t; }  // 传址，实参改变
```

### 易错点

- Java 只有**传值**（对象传的是引用的值，但仍是值传递）。这是常考的辨析点。

## F6 作用域与生存期 ★★ L2

### 静态作用域 vs 动态作用域

| | 静态（词法）作用域 | 动态作用域 |
|:---|:---|:---|
| 看什么 | **定义的位置** | **调用的顺序** |
| 主流语言 | C、Java、Python | 早期 Lisp、部分 Shell |

**判断方法**：静态作用域下，变量的可见范围由**代码的嵌套结构**决定；动态作用域下，由**函数调用链**决定。

### 变量的生存期

- **静态变量**：程序运行期间一直存在
- **局部变量**：函数执行期间存在（栈上）
- **动态分配**：手动申请释放（堆上）

## F7 汇编程序的两次扫描 ★ L1

> **教材 2.2.1，原版本遗漏，2026-10-29 补入**。

**为什么需要两次**：汇编语言里可以**向前引用**（跳转到一个还没定义的标号）。第一次扫描时不知道那个标号的地址，所以必须先扫一遍建表。

| 扫描 | 做什么 | 产出 |
|:---|:---|:---|
| **第一次** | 确定所有符号（标号、变量）的地址 | **符号表** |
| **第二次** | 根据符号表生成机器指令 | 目标代码 |

**教材还提到汇编程序要处理伪指令**：伪指令不生成机器码，只是给汇编程序的指示（如 `START`、`END`、`EQU`）。

## F8 程序设计语言发展史 ★ L1

> **教材 2.1.1，原版本遗漏，2026-10-29 补入**。只考几个"第一"。

| 语言 | 关键点 |
|:---|:---|
| **Fortran**（1957） | **第一个**被广泛使用的高级语言，面向科学计算 |
| **ALGOL 60** | **首次采用 BNF** 描述语法，是后来所有语言语法的范本 |
| ALGOL 68 | 引入类型概念 |
| PASCAL | 结构化程序设计教学语言 |
| C | 贴近硬件，系统级开发 |
| C++ | 在 C 上加面向对象 |
| Java | 删掉 C++ 的"不好的特征"，跨平台（JVM） |
| Ruby | 纯面向对象、解释型 |

**常考**：
- 第一个高级语言 → **Fortran**
- 第一个用 BNF 描述语法的 → **ALGOL 60**
