## 三、核心内容蒸馏

### 12.1 结构化分析与设计

#### 12.1.2 结构化分析：DFD 建模的四条原则（教材明确列出）

这四条是下午场第 1 题的**评分依据**：

1. **一个加工必须既有输入又有输出**（不能有黑洞或奇迹）
2. **每个数据流和数据存储都要在数据字典中有定义**
3. **最底层的加工必须有加工说明**（用结构化自然语言、判定表或判定树）
4. **父图和子图必须平衡**——父子图中对应加工的输入输出数据流必须**完全一致**，数据流或数据项**既不能多也不能少**

**第 4 条是最常考、最容易丢分的**。

**教材的补充**：
- 输入数据流要说明"如何使用"
- 输出数据流要说明"如何产生或选取"
- 数据存储要说明"如何选取、使用、修改"

#### 12.1.3 总体设计：DFD → 模块结构图（★★★ 这是下午题第 1 题的高阶考点）

**教材的核心内容**：DFD 有两种类型，决定了两种映射方法。

| DFD 类型 | 特征 | 映射方法 |
|:---|:---|:---|
| **变换型** | 数据从"输入"经"变换中心"到"输出" | **变换分析** |
| **事务型** | 数据到达一个"事务中心"，根据类型分派到不同处理 | **事务分析** |

##### 变换分析的步骤

1. 确定**输入、变换中心、输出**三部分
2. 设计顶层模块（主控模块）
3. 为每个输入设计一个输入模块
4. 为变换中心设计一个变换模块
5. 为每个输出设计一个输出模块
6. 优化（合并、消除冗余）

##### 事务分析的步骤

1. 确定**事务中心**（接收数据并判断类型的那部分）
2. 设计顶层模块
3. 为事务中心设计接收模块
4. 为每种事务类型设计一个处理模块

**怎么判断是变换型还是事务型**：
- 数据流**线性推进**（输入→处理→输出）→ **变换型**
- 数据流**分叉**（一个输入对应多种处理路径）→ **事务型**

**这个区分在下午场偶尔考**，多数时候第 1 题只考 DFD 本身，不考映射。

#### 12.1.4 详细设计

**教材强调**：**详细设计的结果基本上决定了最终程序代码的质量**。

**详细设计的工具**：
- 程序流程图
- N-S 图（盒图）
- PAD 图（问题分析图）
- PDL（程序设计语言，伪代码）
- 判定表 / 判定树

### 12.2 数据库分析与设计（下午题第 2 题）

#### 12.2.1 设计的策略与步骤（必背）

教材给的六步：

| 步骤 | 产出 |
|:---|:---|
| 1. **需求分析** | 数据字典、数据流图、需求说明书 |
| 2. **概念结构设计** | **E-R 图**（独立于 DBMS） |
| 3. **逻辑结构设计** | 关系模式（E-R 转表）、规范化 |
| 4. **物理结构设计** | 索引、存储结构、分区 |
| 5. **数据库实施** | 建库、建表、导入数据 |
| 6. **运行与维护** | 监控、调优、备份恢复 |

**关键理解**：
- **概念设计独立于任何 DBMS**，是用户和设计者的沟通桥梁
- **逻辑设计才开始考虑具体的数据模型**（关系模型）
- **物理设计才涉及具体的 DBMS 特性**（索引类型、存储引擎）

#### 12.2.3 概念结构设计（E-R 图）

**设计方法**：
- **自顶向下**：先定全局框架，再细化
- **自底向上**：先定局部 E-R 图，再集成（**最常用**）
- 混合策略

**E-R 图集成的冲突**（教材提到）：
1. **属性冲突**（同一属性在不同分 E-R 中类型不同）
2. **命名冲突**（同名异义、异名同义）
3. **结构冲突**（同一对象在不同分 E-R 中抽象不同）

#### 12.2.4 逻辑结构设计

**E-R 图转关系模式的规则**（与第 9 章一致）：

| 联系类型 | 转换 |
|:---|:---|
| 1:1 | 一方主键放另一方作外键 |
| 1:n | 1 端主键放 n 端作外键 |
| **m:n** | **单独建表**，主键 = 两实体主键组合 |

**规范化**：一般要求达到 **3NF**。

**反规范化**：为了提高查询性能，有时会故意降低范式（增加冗余），比如在数据仓库里。

#### 12.2.7 案例分析（教材的完整例子）

教材用**图书管理系统**做完整案例，包括：
- 功能：图书购入、借阅、归还、注销
- 购入新书要编制**图书卡片**（分类目录号、流水号）
- 借阅要记录借阅者、日期
- 归还要更新库存

**这个案例值得完整看一遍**，因为它的分析思路和下午场第 2 题一模一样。

### 12.3 面向对象分析与设计（下午题第 3、5 题）

#### 12.3.1 步骤（教材的顺序）

```
1. 需求说明
2. 建模用例（用例图）—— 系统做什么，谁用
3. 建模活动（活动图）—— 业务流程怎么走
4. 设计类图（类图）—— 有哪些类，什么关系
5. 建模对象状态（状态图）—— 关键对象的状态变化
6. 建模交互（时序图）—— 对象之间怎么协作
```

**这个顺序就是下午场第 3 题的出题逻辑**：题目给一段业务描述，让你补用例图、补类图、判断关系。

#### 12.3.3 建模用例

**找参与者的方法**（教材的思路）：
- 谁使用系统的主要功能？
- 谁需要系统的支持以完成日常任务？
- 谁负责维护、管理系统？
- 系统需要与哪些外部系统交互？

**找用例的方法**：
- 每个参与者的每个目标，通常对应一个用例
- 用例名用**动宾结构**（"借阅图书""查询库存"）

#### 12.3.5 设计类图（关键）

**从用例到类的转换**（教材的方法）：
- **名词 → 候选类**（"读者""图书""借阅记录"）
- **动词 → 候选方法**（"借阅""归还"）
- **形容词 → 属性**（"可借""已借出"）

**关系的判断**（与第 7 章一致）：
- is-a → **泛化**
- has-a（部分可独立）→ **聚合**
- has-a（同生共死）→ **组合**
- 使用 → **依赖**

#### 12.3.7 建模交互（时序图）

**时序图的元素**：
- **对象**（顶部，带下划线）
- **生命线**（垂直虚线）
- **激活条**（矩形，表示对象正在执行）
- **消息**（水平箭头，实线是同步，虚线是返回）

**消息的类型**：
- 同步消息（实心箭头）：调用后等待返回
- 异步消息（开放箭头）：调用后不等待
- 返回消息（虚线箭头）

### 12.4 算法分析与设计（下午题第 4 题）

**教材的重点**：用 C 语言实现算法。

**教材给的案例**：通常是某个经典算法（排序、查找、动态规划）。

**这一节与第 8 章的关系**：
- 第 8 章讲**算法思想**（分治、动规、贪心、回溯）
- 第 12.4 讲**怎么用 C 实现**

**下午场第 4 题的准备**：
1. 认识算法类型（看代码结构）
2. 会填关键的空（循环边界、数组下标、条件判断、递归参数）
3. 会算复杂度
4. 会判断策略

详细套路见 `04-下午题专项/04-算法设计.md`。

### 12.5 面向对象的程序设计与实现（下午题第 5 题）

**教材的重点**：把类图翻译成 Java/C++ 代码。

**转换规则**（与第 7 章一致）：

| 类图元素 | Java | C++ |
|:---|:---|:---|
| 类 | `class X { }` | `class X { };` |
| 接口 | `interface X { }` | 纯虚类 |
| 泛化 | `extends` | `: public` |
| 实现 | `implements` | `: public` |
| 私有属性 | `private` | `private:` |
| 公有方法 | `public` | `public:` |

**下午场第 5 题的准备**：
1. 把类图翻译成代码骨架（这一步做对，填空就是填空）
2. 记住三个判断：实线→extends、虚线→implements、`-`→private
3. 多态题一律按**运行时类型**判断

详细套路见 `04-下午题专项/05-面向对象程序设计.md`。

## 四、教材强调但容易忽略的

1. **DFD 四条原则里，"父子图平衡"是唯一会被扣分的硬性要求**。其他三条错了也扣，但平衡最容易错。

2. **变换型 vs 事务型的判断**：数据流线性推进 → 变换型；数据流分叉 → 事务型。

3. **概念设计独立于 DBMS**，这是它存在的意义——让设计不被具体产品绑架。

4. **E-R 集成的三种冲突**：属性冲突、命名冲突、结构冲突。这个偶尔考。

5. **从用例到类的转换方法**：名词→类，动词→方法，形容词→属性。这是 OOA 的实用技巧。

6. **详细设计决定代码质量**。教材原话，说明详细设计的重要性被低估了。
