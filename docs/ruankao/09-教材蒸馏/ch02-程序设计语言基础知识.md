## 三、核心内容蒸馏

### 2.1.1 基本概念

#### 三个层次：语法、语义、语用

教材的划分（这三个是常考的概念辨析）：

| 概念 | 管什么 | 例子 |
|:---|:---|:---|
| **语法** | 符号组合的**形式规则** | `if (x > 0) y=1;` 写法对不对 |
| **语义** | 语法成分的**含义** | 这段代码是什么意思 |
| **语用** | 语言与**使用者、环境**的关系 | 这段代码用来干什么 |

**教材的进一步划分**：
- 语法分**词法规则**（单词怎么构成）和**语法规则**（句子怎么构成）
- 语义分**静态语义**（编译时可检查，如类型匹配）和**动态语义**（运行时才能确定，如除零）

**这个划分直接对应编译阶段的错误检测**，是理解 2.2.2 的前提。

#### 文法分类（乔姆斯基体系）

教材按产生式的限制程度分四类：

| 类型 | 名称 | 产生式限制 | 对应自动机 |
|:---|:---|:---|:---|
| **0 型** | 短语文法 | 无限制 | 图灵机 |
| **1 型** | 上下文有关文法 | 左部长度 ≤ 右部 | 线性界限自动机 |
| **2 型** | **上下文无关文法** | 左部是**单个非终结符** | **下推自动机** |
| **3 型** | **正规文法** | 右部形式受限 | **有限自动机** |

**必记的对应关系**：
- 程序设计语言的**语法**用 **2 型（上下文无关文法）** 描述
- **词法**用 **3 型（正规文法/正规式）** 描述

**这个对应关系是高频考点**，别搞反。

**包含关系**：3 型 ⊂ 2 型 ⊂ 1 型 ⊂ 0 型（限制越少，能描述的语言越多）

#### 语言发展史（★ 偶尔考）

教材列了一串语言，考试只考几个"第一"：

- **Fortran**（1957）：**第一个**被广泛使用的高级语言，面向科学计算
- **ALGOL 60**：首次采用 **BNF（巴科斯范式）** 描述语法，是后来所有语言语法的范本
- **PASCAL**：结构化程序设计教学语言
- **C**：贴近硬件，系统级开发
- **C++**：在 C 上加面向对象
- **Java**：删掉了 C++ 中一些"不好的特征"，跨平台（JVM）
- **Ruby**：纯面向对象、解释型

### 2.1.2 基本成分

程序设计语言的四类成分（教材的分类）：

1. **数据成分**：数据类型、变量、常量
2. **运算成分**：算术、逻辑、关系运算
3. **控制成分**：顺序、选择、循环
4. **传输成分**：赋值、输入输出

**表达式的三种表示**（常考）：

| 形式 | 例子 | 特点 |
|:---|:---|:---|
| 中缀 | `a + b` | 人易读，需括号和优先级 |
| 前缀（波兰式） | `+ a b` | 无需括号，运算符在前 |
| 后缀（逆波兰式） | `a b +` | 无需括号，**用栈求值** |

**中缀转后缀的口诀**：
- 遇到操作数，直接输出
- 遇到运算符，若优先级高于栈顶则入栈，否则弹出栈顶直到满足
- 遇到左括号入栈，右括号弹出直到左括号
- 结束后弹出栈中剩余运算符

**后缀求值**：遇到操作数入栈，遇到运算符弹出两个计算再入栈，最后栈里剩的就是结果。

### 2.2.1 汇编程序基本原理

汇编语言是**面向机器**的低级语言，用助记符代替机器指令。

**汇编程序的工作**：
1. 把汇编指令翻译成机器指令
2. 处理伪指令（不生成机器码，只给汇编程序看的指示）
3. 地址分配（确定每条指令和数据的地址）

**两次扫描**（教材强调）：
- 第一次：确定符号地址（建立符号表）
- 第二次：生成目标代码

### 2.2.2 编译程序基本原理（★★★ 本章核心）

#### 五个阶段（必须记死顺序）

```
源程序
  ↓ ① 词法分析
记号流（Token）
  ↓ ② 语法分析
语法树
  ↓ ③ 语义分析
带语义信息的中间表示
  ↓ ④ 中间代码生成
中间代码（四元式、三地址码）
  ↓ ⑤ 优化
  ↓ ⑥ 目标代码生成
目标代码
```

**教材把"中间代码生成、优化、目标代码生成"合称"后端"，前三个阶段称"前端"。**

#### 各阶段发现什么错误（必考）

这是本章最高频的考点。教材明确指出：

| 阶段 | 输入 → 输出 | 能发现 |
|:---|:---|:---|
| **词法分析** | 字符流 → 记号流 | **非法字符**（如 `whi1e`）、拼写错误 |
| **语法分析** | 记号流 → 语法树 | **结构错误**（缺分号、括号不匹配） |
| **语义分析** | 语法树 → 带语义的树 | **类型不匹配**、变量未声明、运算符与操作数类型不符 |
| 中间代码生成 | 语义树 → 中间代码 | 不查错 |
| 优化 | 中间代码 → 更优的中间代码 | 不查错 |
| 目标代码生成 | 中间代码 → 机器码 | 不查错 |

**判断技巧**：
- 字符层面不对 → **词法**
- 结构层面不对（配对、顺序）→ **语法**
- 意思层面不对（类型、声明）→ **语义**

**教材特别说明**：**动态语义错误**（除零、数组越界）编译期发现不了，只能运行时暴露。

#### 符号表

贯穿整个编译过程。教材的说法：

- **词法分析时开始建立**（遇到标识符就登记）
- **语义分析时填充属性**（类型、作用域、地址）
- 后续阶段都查这张表

#### 中间代码的常见形式

| 形式 | 例子 |
|:---|:---|
| 四元式 | `(+, a, b, t1)` 表示 t1 = a + b |
| 三地址码 | `t1 = a + b` |
| 逆波兰式 | `a b +` |
| 树形表示 | 语法树 |

**为什么要有中间代码**：与具体机器无关，便于优化，便于移植（换机器只需换后端）。

### 2.2.3 解释程序基本原理

| | 编译 | 解释 |
|:---|:---|:---|
| 是否生成目标代码 | **生成** | **不生成** |
| 执行速度 | **快**（一次编译多次运行） | 慢（每次都要解释） |
| 跨平台性 | 差（要为目标平台编译） | **好**（有解释器就能跑） |
| 错误发现时机 | 编译期集中发现 | **边解释边发现**（运行到才报） |
| 代表语言 | C、C++、Go | Python、JavaScript、Ruby |

**教材的补充**：解释程序也可以先把源程序翻译成某种中间代码（如字节码），再解释执行中间代码。Java 就是这种**混合模式**——先编译成字节码，再由 JVM 解释/即时编译（JIT）执行。

**这个"混合模式"是常考点**：Java 既不是纯编译也不是纯解释。

## 四、教材强调但容易忽略的

1. **静态语义 vs 动态语义**：教材明确区分。类型检查是静态语义（编译期），除零是动态语义（运行期）。这个区分决定了"哪个阶段能发现什么错"。

2. **2 型文法对应下推自动机**，不是有限自动机。有限自动机对应的是 3 型（正规文法）。这两个最容易搞混。

3. **汇编程序的两次扫描**：第一次建符号表，第二次生成代码。因为向前引用（跳转到还没定义的标号）必须先知道地址。

4. **中间代码的价值不在"运行"，在"可优化 + 可移植"**。教材专门解释了这一点。

5. **Java 的混合模式**：编译成字节码 + JVM 解释执行。这是"编译 vs 解释"二分法的一个例外，考试常用来设置干扰项。
