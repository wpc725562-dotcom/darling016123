## 三、核心内容蒸馏

### 9.1 三级模式与两级映像（★★★）

#### 三级模式

| 模式 | 别称 | 描述 | 数量 |
|:---|:---|:---|:---:|
| **外模式** | 子模式、用户模式 | 用户看到的数据视图 | **多个** |
| **模式** | 逻辑模式、概念模式 | 全体数据的逻辑结构 | **一个** |
| **内模式** | 存储模式、物理模式 | 数据在磁盘上的存储方式 | **一个** |

**记忆**：**外多个、模一个、内一个**。

#### 两级映像与独立性（必考）

| 映像 | 作用 | 保证 |
|:---|:---|:---|
| **外模式/模式** | 模式改变时，改映像，外模式不变 | **逻辑独立性** |
| **模式/内模式** | 存储改变时，改映像，模式不变 | **物理独立性** |

**必记**：外/模 → 逻辑独立性；模/内 → 物理独立性。**这两个最容易搞反。**

**理解方法**：
- 外模式是用户看到的，模式是全局逻辑的。改了全局逻辑，用户视图不变 → **逻辑**独立性。
- 模式是逻辑的，内模式是物理的。改了存储方式，逻辑结构不变 → **物理**独立性。

### 9.2 E-R 模型（★★★）

#### 三要素

| 元素 | 图形 | 说明 |
|:---|:---|:---|
| **实体** | 矩形 | 客观存在的事物 |
| **属性** | 椭圆 | 实体的特征 |
| **联系** | 菱形 | 实体间的关系 |

#### 联系的类型与转换（下午场核心）

| 类型 | 转换规则 |
|:---|:---|
| **1:1** | 一方主键放到另一方作外键，或单独建表 |
| **1:n** | **1 端主键放到 n 端作外键** |
| **m:n** | **必须单独建表**，主键 = 两实体主键组合 |

**例**：学生（学号）与课程（课程号）是 m:n 的"选修"，有属性"成绩"
→ `选修(学号, 课程号, 成绩)`，主键 `(学号, 课程号)`

#### 易错点

- **m:n 联系不能合并到任一方**
- 1:n 的外键放在**多**的一端
- **联系也可以有属性**（如"选修"有"成绩"），转换时要带上

### 9.3 关系代数（★★★）

#### 五个基本运算

| 运算 | 符号 | 作用 | 类比 SQL |
|:---|:---:|:---|:---|
| **投影** | π | **选列**（垂直切） | SELECT 列名 |
| **选择** | σ | **选行**（水平切，按条件） | WHERE |
| **并** | ∪ | 合并（去重） | UNION |
| **差** | − | 在 A 不在 B | EXCEPT |
| **笛卡尔积** | × | 所有组合 | CROSS JOIN |

**必记**：**π 选列，σ 选行**。这两个符号最容易搞反。

#### 派生运算

| 运算 | 符号 | 说明 |
|:---|:---:|:---|
| 交 | ∩ | 同时属于两者 |
| **自然连接** | ⋈ | 按同名属性等值连接，**结果去掉重复属性** |
| 除 | ÷ | 用于"对所有…"的查询 |

#### 自然连接 vs 等值连接

- **等值连接**：按条件连接，结果**保留所有属性**（含重复的）
- **自然连接**：自动按同名属性连接，结果**去掉重复属性**

**题目问"结果有几个属性"，自然连接要去重。**

### 9.4 SQL

#### 执行顺序（重要）

书写顺序：`SELECT ... FROM ... WHERE ... GROUP BY ... HAVING ... ORDER BY`
执行顺序：**FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY**

**这解释了为什么 WHERE 不能用聚合函数**（那时还没分组），而 HAVING 可以。

#### 关键语法

```sql
-- 分组过滤
SELECT 系号, AVG(成绩) FROM 学生 GROUP BY 系号 HAVING AVG(成绩) > 80;

-- 连接
SELECT s.姓名, c.课程名
FROM 学生 s JOIN 选修 e ON s.学号 = e.学号
JOIN 课程 c ON e.课程号 = c.课程号;

-- 子查询
SELECT 姓名 FROM 学生 WHERE 学号 IN (SELECT 学号 FROM 选修 WHERE 成绩 > 90);
```

#### 易错点

- `WHERE` 过滤**行**，`HAVING` 过滤**组**
- `COUNT(*)` 算所有行，`COUNT(列名)` **不统计 NULL**
- `DELETE` 删数据（可回滚），`DROP` 删表结构（不可回滚），`TRUNCATE` 清空表（保留结构，不可回滚）

### 9.5 规范化理论（★★★ 必考）

#### 四个概念

| 概念 | 定义 |
|:---|:---|
| **函数依赖** X→Y | X 确定 Y |
| **部分函数依赖** | X 是组合属性，Y 只依赖其中一部分 |
| **传递函数依赖** | X→Y，Y→Z，且 Y 不→X |
| **候选键** | 能唯一确定元组的最小属性集 |

#### 四个范式

| 范式 | 条件 | 消除什么 |
|:---|:---|:---|
| **1NF** | 每个属性都是**原子值** | 非原子属性 |
| **2NF** | 1NF + 非主属性**完全依赖**于候选键 | **部分函数依赖** |
| **3NF** | 2NF + 非主属性**不传递依赖**于候选键 | **传递函数依赖** |
| **BCNF** | 3NF + 所有依赖左部都**包含候选键** | 主属性对候选键的部分/传递依赖 |

#### 判定步骤（照着做）

1. **找候选键**（能推出所有属性的最小集合）
2. 分主属性 / 非主属性
3. 有非原子属性？→ 不是 1NF
4. 候选键是组合键？
   - 是 → 检查非主属性有无**部分依赖** → 有则不是 2NF
   - 否（单属性）→ **一定满足 2NF**
5. 有非主属性之间的**传递依赖**？→ 不是 3NF
6. 每个依赖左部都含候选键？→ 否则不是 BCNF

#### 经典例子

`学生(学号, 姓名, 系号, 系主任)`
- 候选键：学号（单属性）→ 一定满足 2NF
- 学号→系号→系主任 是**传递依赖**
- 结论：**2NF**（不满足 3NF）

分解为 3NF：`学生(学号, 姓名, 系号)` + `系(系号, 系主任)`

#### 易错点

- **单属性候选键一定满足 2NF**（没有"部分"可言）
- 判断 3NF 只看**非主属性**之间的依赖
- BCNF 比 3NF 严，区别在**主属性**

### 9.6 并发控制

#### 三种并发问题

| 问题 | 描述 |
|:---|:---|
| **丢失更新** | 两个事务同时读同一数据，后写的覆盖先写的 |
| **脏读** | 读到了别的事务**未提交**的数据 |
| **不可重复读** | 同一事务内两次读同一数据，结果不同 |
| **幻读** | 同一事务内两次查询，结果集行数不同 |

#### 两级锁

| 锁 | 别名 | 允许 |
|:---|:---|:---|
| **共享锁 S** | 读锁 | 别人可读，不可写 |
| **排他锁 X** | 写锁 | 别人不可读不可写 |

#### 两段锁协议（2PL）

- **扩展阶段**：只能加锁，不能解锁
- **收缩阶段**：只能解锁，不能加锁

遵守 2PL 是**可串行化**的**充分条件**（不是必要条件）。

### 9.7 数据库设计（★★★ 下午场）

#### 四个阶段

| 阶段 | 产出 |
|:---|:---|
| **需求分析** | 数据字典、数据流图 |
| **概念结构设计** | **E-R 图**（与具体 DBMS 无关） |
| **逻辑结构设计** | 关系模式（E-R 转表）、规范化 |
| **物理结构设计** | 索引、存储结构 |

**概念设计是关键**——它独立于任何 DBMS，是用户和设计者的沟通桥梁。

#### 设计原则

- 一个实体一张表
- m:n 联系单独建表
- 1:n 联系把外键放 n 端
- 尽量达到 3NF（但有时为了性能会**反规范化**）

### 9.8 数据仓库（★）

| | OLTP（操作型） | OLAP（分析型） |
|:---|:---|:---|
| 用途 | 日常交易 | 决策分析 |
| 数据 | 当前、细节 | 历史、汇总 |
| 操作 | 增删改查频繁 | 大量读、批量加载 |
| 设计 | 规范化（3NF） | **反规范化**（星型/雪花） |

**星型模型**：一个事实表 + 多个维度表，维度表不再分解。
**雪花模型**：维度表还可以再规范化分解。

**数据挖掘任务**：分类、聚类、关联规则、序列模式、回归。

## 四、教材强调但容易忽略的

1. **外模式/模式 → 逻辑独立性；模式/内模式 → 物理独立性**。这两个最常搞反，记的时候想"外-模都是逻辑层面的，所以是逻辑独立性"。

2. **π 选列，σ 选行**。π 的形状像"竖着的门"，σ 像"横着的波浪"——这只是助记，本质要记清。

3. **单属性候选键一定满足 2NF**。这是判范式时最省时间的一条。

4. **自然连接去掉重复属性，等值连接不去**。问"结果属性个数"时要注意。

5. **WHERE 不能用聚合函数，HAVING 可以**。根源是执行顺序。

6. **2PL 是可串行化的充分条件，不是必要条件**。也就是说存在不遵守 2PL 但可串行化的调度。
