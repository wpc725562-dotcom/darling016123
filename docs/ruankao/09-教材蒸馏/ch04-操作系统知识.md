## 三、核心内容蒸馏

### 4.1.1 基本概念

**教材的定义**：操作系统是能有效地组织和管理系统中的各种软硬件资源，合理地组织计算机系统工作流程，控制程序的执行，并且向用户提供一个良好的工作环境和友好接口的系统软件。

**两个作用**（教材原文）：
1. **通过资源管理提高计算机系统的效率**（提高吞吐量）
2. **改善人机界面，向用户提供友好的工作环境**

**五大管理功能**（必背）：

| 功能 | 管什么 |
|:---|:---|
| **处理机管理** | 进程控制、同步、通信、调度 |
| **存储管理** | 存储分配与回收、地址转换、存储保护、虚拟存储 |
| **设备管理** | 设备分配、启动、完成、虚拟设备 |
| **文件管理** | 文件存储空间、目录、读写、存取控制 |
| **作业管理** | 任务、界面、人机交互 |

### 4.1.2 分类及特点（常考对比）

| 类型 | 特征 | 目标 |
|:---|:---|:---|
| **批处理** | 成批提交，无交互 | 提高**吞吐量**，CPU 利用率 |
| **分时** | 时间片轮转，多用户交互 | **响应时间**短，公平 |
| **实时** | 严格时限，立刻响应 | **及时性 + 可靠性**，宁可牺牲效率 |
| **网络** | 管理网络资源，实现共享 | 资源共享、通信 |
| **分布式** | 多台计算机协同，任务可分布 | 透明性、并行处理 |
| **嵌入式** | 专用、资源受限 | 精简、可靠 |

**判断技巧**：
- 看到"时间片""多用户""交互"→ 分时
- 看到"时限""不能延迟""控制工业过程"→ 实时
- 看到"多台机器协同完成一个任务"→ 分布式（不是网络）

**分时 vs 实时的核心区别**：分时追求"每个用户都感觉不到等待"（秒级），实时追求"必须在规定时间内完成"（毫秒甚至微秒级）。

### 4.2.1 进程的基本概念

**进程的定义**：程序在一个数据集合上运行的过程，是系统进行资源分配和调度的**独立单位**。

**进程与程序的区别**：
- 程序是**静态**的（一堆指令）
- 进程是**动态**的（一次执行过程）
- 一个程序可以对应多个进程（多次运行）

**PCB（进程控制块）**：进程存在的**唯一标志**。包含进程标识、状态、程序计数器、寄存器、优先级、资源清单。

#### 三态模型（必考）

```
        就绪 ←──── 时间片到 ──── 运行
         │                        │
      被调度                  等待事件
         ↓                        ↓
        运行 ──── 请求资源 ───→ 阻塞
                                  │
                              资源就绪
                                  ↓
                                就绪
```

**四条转换规则**：

| 转换 | 触发 | 主动/被动 |
|:---|:---|:---|
| 就绪 → 运行 | 被调度程序选中 | 被动 |
| 运行 → 就绪 | 时间片用完 | 被动 |
| 运行 → 阻塞 | 请求资源/等待事件 | **主动** |
| 阻塞 → 就绪 | 资源就绪/事件发生 | 被动 |

**必考**：**阻塞不能直接转到运行**，必须先回就绪队列。

#### 五态模型

在三态基础上加**新建**（刚创建，还没进就绪队列）和**终止**（执行完或异常结束）。

### 4.2.2 进程控制：PV 操作（★★★ 教材重点）

这一节是我原来 `02-知识域` 没细讲的部分，但教材给了很大篇幅。

#### 信号量机制

**信号量 S**：一个整型变量，只能通过两个原子操作访问：

- **P 操作**（wait）：`S = S − 1`；若 `S < 0`，进程阻塞
- **V 操作**（signal）：`S = S + 1`；若 `S ≤ 0`，唤醒一个阻塞进程

**理解要点**：
- S 的初值表示**可用资源数**
- S 为负时，**绝对值表示等待队列中的进程数**

#### 互斥（临界区保护）

```
semaphore mutex = 1;   // 初值 1，表示一个资源

P(mutex);
  临界区代码
V(mutex);
```

**为什么初值是 1**：表示只有一个资源可用，一次只能进一个进程。

#### 同步（先后顺序控制）

```
// 要求：A 执行完后 B 才能执行
semaphore S = 0;      // 初值 0

进程A: { ...; V(S); }
进程B: { P(S); ... }
```

**为什么初值是 0**：B 必须先等 A 发信号，初始时没有信号可用。

#### 生产者-消费者问题（经典模型）

```
semaphore mutex = 1;    // 互斥访问缓冲区
semaphore empty = n;    // 空缓冲区数量
semaphore full = 0;     // 满缓冲区数量

生产者:
  P(empty);   // 等空位
  P(mutex);   // 独占缓冲区
    放入产品
  V(mutex);
  V(full);    // 增加满位

消费者:
  P(full);    // 等产品
  P(mutex);
    取出产品
  V(mutex);
  V(empty);   // 增加空位
```

**注意 P 操作的顺序**：先 P(empty)/P(full)，再 P(mutex)。**反过来会死锁**（占着互斥锁等资源）。

这个顺序问题是高频考点。

### 4.2.6 死锁（★★★）

#### 四个必要条件

1. **互斥**：资源一次只能被一个进程占用
2. **占有并等待**（请求和保持）：占着资源还申请新资源
3. **不可剥夺**：不能被强行抢走
4. **循环等待**：存在进程的环形等待链

**破坏任一条件即可预防死锁**：
- 破坏互斥：资源可共享（但很多资源本质互斥，做不到）
- 破坏占有并等待：一次性申请所有资源
- 破坏不可剥夺：可抢占
- **破坏循环等待**：按序申请资源（最常用）

#### 银行家算法（安全序列）

**思路**：每次找一个"还需要 ≤ 当前可用"的进程，假设它执行完并释放资源，继续找下一个。能找到全部 → 安全。

**例**：系统有资源 A、B、C 各 10 个

| 进程 | 已分配 | 最大需求 | 还需 |
|:---|:---|:---|:---|
| P1 | 2,0,0 | 3,2,2 | 1,2,2 |
| P2 | 3,0,2 | 6,1,3 | 3,1,1 |
| P3 | 2,1,1 | 3,3,2 | 1,2,1 |

可用 = (10,10,10) − (7,1,3) = **(3,9,7)**

- P1 还需 (1,2,2) ≤ (3,9,7) ✅ → 完成，可用变 (5,9,7)
- P3 还需 (1,2,1) ≤ (5,9,7) ✅ → 完成，可用变 (7,10,8)
- P2 还需 (3,1,1) ≤ (7,10,8) ✅ → 完成

安全序列：**P1 → P3 → P2**（可能不唯一）

**注意**："不安全"≠"已死锁"，是"可能死锁"。

### 4.3 存储管理

#### 分页 vs 分段（必考对比）

| | 分页 | 分段 |
|:---|:---|:---|
| 划分依据 | **物理**，固定大小 | **逻辑**，按程序模块 |
| 大小 | 固定（如 4KB） | 不定 |
| 地址 | **一维**（页号 + 页内偏移） | **二维**（段号 + 段内偏移） |
| 碎片 | **内部碎片**（最后一页没装满） | **外部碎片**（段之间有空隙） |
| 目的 | 提高内存利用率 | 便于共享和保护 |
| 对用户 | **不可见** | **可见**（程序员知道段） |

**这个对比表几乎每年考**，重点记"物理/逻辑""一维/二维""内部/外部碎片"。

#### 页面置换算法（★★★）

| 算法 | 规则 | 特点 |
|:---|:---|:---|
| **OPT** | 淘汰**将来最久不用**的 | 理论最优，**无法实现**（要预知未来） |
| **FIFO** | 淘汰**最早进入**的 | 简单，有 **Belady 异常** |
| **LRU** | 淘汰**最久没访问**的 | 接近 OPT，实现成本高 |

**Belady 异常**：FIFO 算法下，**增加物理块数反而缺页次数增加**。这是 FIFO 特有的问题。

**缺页次数计算**：
**缺页次数 = 置换次数 + 物理块数**（前面填充的几次也是缺页，但不算置换）

**例**：3 块，序列 1,2,3,4,1,2,5,1,2,3,4,5

FIFO 过程：

| 访问 | 1 | 2 | 3 | 4 | 1 | 2 | 5 | 1 | 2 | 3 | 4 | 5 |
|:---|:---|:---|:---|:---|:---|:---|:---|:---|:---|:---|:---|:---|
| 块1 | 1 | 1 | 1 | 2 | 2 | 2 | 5 | 5 | 5 | 3 | 3 | 3 |
| 块2 | | 2 | 2 | 3 | 3 | 3 | 1 | 1 | 1 | 4 | 4 | 4 |
| 块3 | | | 3 | 4 | 4 | 4 | 2 | 2 | 2 | 5 | 5 | 5 |
| | 缺 | 缺 | 缺 | 缺 | 缺 | 缺 | 缺 | 命 | 命 | 缺 | 缺 | 命 |

缺页 **9 次**

#### 虚拟存储

**理论基础**：局部性原理（时间局部性 + 空间局部性）。

**核心思想**：只把当前用到的部分调入内存，其余留在外存，需要时再调。

**三个前提**：
1. 有足够大的外存
2. 有页表/段表支持地址转换
3. 有缺页中断机制

### 4.4 设备管理

#### SPOOLing 技术（假脱机）

**作用**：把**独占设备**虚拟成**共享设备**。

**原理**：用磁盘上的缓冲区代替独占设备，进程往缓冲区写，由系统统一调度输出。

**典型应用**：**打印机共享**。多用户同时"打印"，实际上都写进了磁盘队列。

**教材强调**：SPOOLing 是**用空间换设备**，代价是需要大容量磁盘。

#### 缓冲技术

| 类型 | 说明 |
|:---|:---|
| 单缓冲 | 一个缓冲区，输入输出不能并行 |
| 双缓冲 | 两个缓冲区，可并行 |
| 缓冲池 | 多个缓冲区统一管理 |

**目的**：缓和 CPU 与 I/O 设备的速度差。

### 4.5 文件管理

#### 目录结构

单级目录 → 两级目录 → 树形目录 → 图形目录（支持共享）

#### 文件的物理结构

| 结构 | 随机访问 | 碎片 | 说明 |
|:---|:---|:---|:---|
| **连续分配** | 快 | 有外部碎片 | 需预知文件大小 |
| **链接分配** | 慢（要顺着链找） | 无 | 指针占空间 |
| **索引分配** | 快 | 无 | 需要索引块 |

#### 索引节点（inode）

**存什么**：文件的元信息（权限、大小、时间、数据块地址）
**不存什么**：**文件名**（文件名在目录项里）

这是常考的辨析点。

#### 位示图

用二进制的每一位表示一个物理块是否被占用。

**计算**（常考）：
- 字号 = 块号 / 字长（**从 0 开始**）
- 位号 = 块号 % 字长（**从 0 开始**）

**例**：字长 32 位，块号 100
- 字号 = 100 / 32 = **3**
- 位号 = 100 % 32 = **4**

### 4.6 作业管理

#### 调度算法

| 算法 | 特点 | 缺点 |
|:---|:---|:---|
| **FCFS** | 简单，按到达顺序 | 短作业等长作业，平均等待长 |
| **SJF**（短作业优先） | **平均等待时间最短** | 长作业可能饿死；需预知运行时间 |
| **优先级** | 按优先级 | 低优先级饿死 |
| **响应比高者优先** | 兼顾等待时间和运行时间 | 计算复杂 |

**响应比** = (等待时间 + 要求服务时间) / 要求服务时间

#### 周转时间（必考）

- **周转时间** = 完成时间 − 到达时间
- **带权周转时间** = 周转时间 / 运行时间
- **平均周转时间** = 所有作业周转时间之和 / 作业数

**例**：

| 作业 | 到达 | 运行 |
|:---|:---:|:---:|
| A | 0 | 3 |
| B | 1 | 2 |
| C | 2 | 1 |

**FCFS（A→B→C）**：
- A：0–3，周转 3
- B：3–5，周转 4
- C：5–6，周转 4
- 平均 = 11/3 ≈ **3.67**

**SJF（A→C→B）**：
- A：0–3，周转 3
- C：3–4，周转 2
- B：4–6，周转 5
- 平均 = 10/3 ≈ **3.33**

## 四、教材强调但容易忽略的

1. **PV 操作中 P 的顺序**：生产者-消费者问题里，必须先 P(empty/full) 再 P(mutex)，反过来会死锁。教材专门分析了这个死锁场景。

2. **信号量为负时的含义**：绝对值 = 等待进程数。这个理解能解决很多 PV 题的"信号量初值"问题。

3. **分页对用户不可见，分段可见**：这是两者最本质的区别，其他区别都由此派生。

4. **缺页次数 = 置换次数 + 物理块数**：很多人只数置换，漏了前面填充的几次。

5. **SPOOLing 是用空间换设备**：教材明确说了这个权衡。

6. **inode 不存文件名**：文件名在目录项里，inode 只存元信息和数据块地址。
