## 三、核心内容蒸馏

### 7.1 面向对象基本概念

#### 五个核心概念

| 概念 | 定义 | 关键 |
|:---|:---|:---|
| **对象** | 系统中用来描述客观事物的一个实体，是**封装**的基本单位 | 有状态和行为 |
| **类** | 具有相同属性和操作的对象的集合 | 类是对象的**模板**，对象是类的**实例** |
| **封装** | 隐藏内部实现，只暴露接口 | 信息隐蔽 |
| **继承** | 子类复用父类的属性和方法 | **is-a** 关系 |
| **多态** | 同一消息，不同对象产生不同响应 | 同一接口，不同实现 |

#### 多态的两种形式（必考）

| 形式 | 英文 | 绑定时机 | 例子 |
|:---|:---|:---|:---|
| **重载**（过载） | overload | **编译时**（静态绑定） | `add(int, int)` 和 `add(double, double)` |
| **重写**（覆盖） | override | **运行时**（动态绑定） | 子类覆盖父类的 `speak()` |

**必记**：**重载是编译时，重写是运行时**。这是最高频的辨析点。

**为什么重载是编译时**：编译器根据参数类型和个数就能确定调用哪个方法，不需要运行时信息。

**为什么重写是运行时**：编译器只知道变量声明类型（父类），实际调用哪个方法取决于对象的**运行时类型**（子类）。

#### 消息

对象之间通过消息通信。一条消息包含：接收者、选择子（方法名）、参数。

### 7.2 面向对象分析（OOA）

教材引用 Coad/Yourdon 方法，分**五个层次**：

| 层次 | 做什么 |
|:---|:---|
| **主题层** | 划分子系统 |
| **对象类层** | 识别类和对象 |
| **结构层** | 识别类之间的关系（分类结构、组装结构） |
| **属性层** | 定义类的属性 |
| **服务层** | 定义类的操作 |

**分类结构** = 继承（is-a），**组装结构** = 组合/聚合（has-a）。

### 7.3 面向对象设计（OOD）

#### 五条设计原则（SOLID，教材提到部分）

| 原则 | 含义 |
|:---|:---|
| **单一职责原则（SRP）** | 一个类只负责一件事 |
| **开闭原则（OCP）** | 对扩展开放，对修改关闭 |
| **里氏替换原则（LSP）** | 子类可以替换父类而不影响正确性 |
| **依赖倒置原则（DIP）** | 依赖抽象，不依赖具体实现 |
| **接口隔离原则（ISP）** | 接口要小而专，不要大而全 |

**开闭原则是最核心的**——设计模式的存在就是为了实现它。

### 7.4 UML（★★★）

#### 三种基本构造块

1. **事物**（Things）：类、接口、用例、构件、节点等
2. **关系**（Relationships）：关联、依赖、泛化、实现
3. **图**（Diagrams）：把事物和关系组织起来

#### UML 的 14 种图（教材列了常用的几种）

##### 结构图（静态）

| 图 | 用途 | 关键词 |
|:---|:---|:---|
| **类图** | 类与类的静态关系 | 静态结构 |
| **对象图** | 某一时刻的对象快照 | 实例 |
| **组件图**（构件图） | 软件组件及依赖 | 构件 |
| **部署图** | 硬件节点与部署 | 物理部署 |
| **包图** | 分组 | 组织 |
| **组合结构图** | 类的内部结构 | 内部组成 |

##### 行为图（动态）

| 图 | 用途 | 关键词 |
|:---|:---|:---|
| **用例图** | 系统与外部参与者的交互 | 谁用什么功能 |
| **活动图** | 业务流程、并发 | 流程、并行 |
| **状态图** | 对象的状态变迁 | 状态、事件触发 |
| **时序图**（顺序图） | 对象间按时间顺序的消息 | 消息先后 |
| **通信图**（协作图） | 对象间的链接关系 | 强调结构 |
| **交互概览图** | 活动图 + 时序图的混合 | 概览 |
| **定时图** | 时间约束 | 实时系统 |

#### 图的选择（必考）

| 题目问 | 选 |
|:---|:---|
| 系统有哪些功能、谁来用 | **用例图** |
| 业务流程、审批流、并发 | **活动图** |
| 一个订单从"待支付"到"已发货" | **状态图** |
| 多个对象按时间顺序发消息 | **时序图** |
| 类与类的静态关系 | **类图** |
| 软件装在哪台服务器上 | **部署图** |

**活动图 vs 状态图（最容易混）**：
- 主语是**业务流程** → 活动图
- 主语是**一个对象** → 状态图

#### 类图的六种关系（★★★）

| 关系 | 符号 | 语义 | 代码表现 |
|:---|:---|:---|:---|
| **依赖** | 虚线箭头 `--->` | 临时使用 | 方法参数、局部变量 |
| **关联** | 实线 `——` | 长期结构关系 | 成员变量 |
| **聚合** | **空心**菱形 `◇——` | 整体-部分，**部分可独立** | 成员变量（集合） |
| **组合** | **实心**菱形 `◆——` | 整体-部分，**同生共死** | 成员变量（强引用） |
| **泛化** | 空心三角实线 `——▷` | is-a 继承 | `extends` |
| **实现** | 空心三角虚线 `--▷` | 实现接口 | `implements` |

**强度排序**：依赖 < 关联 < 聚合 < 组合 < 泛化/实现

##### 聚合 vs 组合（最常考）

**判断标准**：**整体消失，部分还在吗？**

| 场景 | 关系 | 理由 |
|:---|:---|:---|
| 班级 — 学生 | **聚合** | 班级解散，学生还在 |
| 人 — 心脏 | **组合** | 人死了，心脏不能独立活 |
| 订单 — 订单项 | **组合** | 订单删除，订单项无意义 |
| 电脑 — 鼠标 | **聚合** | 电脑报废，鼠标还能用 |

**记忆**：**空心=松，实心=紧**。菱形永远在**整体**那一端。

#### 用例图的三种关系

| 关系 | 符号 | 含义 | 判断 |
|:---|:---|:---|:---|
| **包含** include | `A ---> B` 标 «include» | A 一定用到 B | "必须"、"每次都" |
| **扩展** extend | `B ---> A` 标 «extend» | B 在特定条件下补充 A | "可选"、"如果" |
| **泛化** | 空心三角实线 | 子用例是一种父用例 | "是一种" |

**箭头方向**（最容易错）：
- `A «include» B`：箭头从 **A 指向 B**
- `B «extend» A`：箭头从 **B 指向 A**

### 7.5 设计模式（★★★）

#### 23 种，分三大类

| 类别 | 数量 | 解决什么 | 代表 |
|:---|:---:|:---|:---|
| **创建型** | 5 | 怎么创建对象 | 单例、工厂方法、抽象工厂、建造者、原型 |
| **结构型** | 7 | 怎么组合类/对象 | 适配器、桥接、组合、装饰器、外观、享元、代理 |
| **行为型** | 11 | 对象间怎么通信 | 观察者、策略、模板方法、命令、状态、职责链、中介者、迭代器、访问者、备忘录、解释器 |

**记忆口诀**：
- 创建型 5：**单工抽建原**
- 结构型 7：**适桥组装外享代**
- 行为型 11：**观策模命状链中迭访备解**

#### 高频模式的识别特征（考场上直接对号）

| 模式 | 看到这些词就选它 |
|:---|:---|
| **单例** | "全局唯一"、"只能有一个"、配置管理器、连接池 |
| **工厂方法** | "不关心具体类"、"子类决定创建哪种" |
| **抽象工厂** | "一族相关产品"、"换皮肤"、"跨平台 UI" |
| **建造者** | "分步骤构建复杂对象"、"套餐" |
| **原型** | "克隆"、"复制现有对象" |
| **适配器** | "接口不兼容"、"转换"、"复用老代码" |
| **装饰器** | "动态增加功能"、"层层包装"、Java IO 流 |
| **代理** | "控制访问"、"延迟加载"、"权限控制" |
| **外观** | "简化复杂子系统"、"统一入口" |
| **观察者** | "一对多依赖"、"状态变化通知"、事件监听 |
| **策略** | "多种算法可互换"、"运行时切换"、支付方式 |
| **模板方法** | "固定流程，部分步骤可变"、"钩子" |
| **命令** | "把请求封装成对象"、撤销/重做 |
| **状态** | "状态改变行为也改变"、订单状态机 |
| **职责链** | "逐级处理"、"审批流"、"过滤器链" |

#### 三组最容易混的模式

**1. 策略 vs 状态**
- **策略**：由**客户端**选择用哪个算法，算法之间**不知道彼此**
- **状态**：由**对象自己**在状态变化时切换，状态之间**知道彼此**

**2. 适配器 vs 装饰器**
- **适配器**：**改变接口**，让不兼容的能用
- **装饰器**：**不改变接口**，只增加功能

**3. 代理 vs 装饰器**
- **代理**：**控制访问**，通常只代理一个对象，客户端不知道代理存在
- **装饰器**：**增强功能**，可以层层嵌套

## 四、教材强调但容易忽略的

1. **重载是编译时多态，重写是运行时多态**。这是本章最高频的辨析点，教材专门对比过。

2. **聚合和组合的区别是"部分能否独立存在"**，不是"包含关系强弱"。教材用"班级-学生"和"人-心脏"这两个例子区分。

3. **用例图的包含和扩展，箭头方向相反**。`A «include» B` 是 A→B，`B «extend» A` 是 B→A。

4. **活动图和状态图的主语不同**：流程用活动图，对象用状态图。

5. **设计模式的分类口诀**（单工抽建原 / 适桥组装外享代 / 观策模命状链中迭访备解）能解决"某模式属于哪一类"的题。

6. **开闭原则是设计模式的总纲**：对扩展开放、对修改关闭。几乎所有模式都在实现这一点。
