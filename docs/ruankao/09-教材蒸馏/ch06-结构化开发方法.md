## 三、核心内容蒸馏

### 6.1.1 结构化分析的基本思想

**核心**：**自顶向下、逐层分解**。

**三个模型**：
1. **功能模型** → 数据流图（DFD）
2. **数据模型** → E-R 图
3. **行为模型** → 状态转换图

**教材强调**：结构化分析不关心"怎么做"，只关心"做什么"（数据怎么流动、被怎么处理）。

### 6.1.2 数据流图（DFD）（★★★）

#### 四种元素（必背）

| 元素 | 图形 | 说明 |
|:---|:---|:---|
| **外部实体** | 矩形（或带阴影） | 系统之外的人、组织、外部系统 |
| **加工（处理）** | 圆角矩形或圆 | 对数据做变换 |
| **数据流** | 箭头 | 数据流动方向，**必须命名** |
| **数据存储** | 开口矩形或双横线 | 数据库、文件 |

**注意**：教材里没有"数据源点/终点"这个第五元素，外部实体已经涵盖。

#### 分层 DFD

```
顶层图（0 层）  —— 整个系统是一个加工，展示系统与外部实体的关系
    ↓ 细化
0 层图（1 层）  —— 把顶层那个加工拆成若干子加工
    ↓ 细化
1 层图（2 层）  —— 继续拆
```

**教材的编号约定**：
- 顶层图的加工编号为 0
- 0 层图的加工编号为 1、2、3……
- 1 层图的加工编号为 1.1、1.2、2.1……

#### 父子图平衡（最重要的规则）

**定义**：父图中某个加工的**输入流和输出流**，必须与子图中对应加工的**输入流和输出流**一致。

**常见错误**：
- 子图多了一条父图没有的输入流
- 子图少了一条父图有的输出流
- 子图的数据流名称与父图不一致

**这是下午场第 1 题的必考点**。

#### 四条铁律（画图和改错都要用）

| 规则 | 说明 |
|:---|:---|
| **外部实体之间不能直接有数据流** | 必须经过加工中转 |
| **数据流必须命名** | 不能只画箭头 |
| **数据流不能双向** | 两个方向画两条箭头 |
| **每个加工必须有输入和输出** | 不能只有输入（黑洞）或只有输出（奇迹） |

#### 补充规则（教材提到）

- 数据流不能直接连接两个数据存储（必须有加工介入）
- 一个加工的输出流不能与输入流同名（除非是同一个数据被修改后返回）

### 6.1.3 数据字典（★★★）

**作用**：对 DFD 中出现的每个数据元素给出**严格的定义**，让 DFD 可被准确理解。

#### 四类条目（必背）

| 条目 | 定义什么 | 例子 |
|:---|:---|:---|
| **数据项** | 不可再分的基本单位 | 学号、姓名 |
| **数据结构** | 数据项的组合 | 学生记录 = 学号 + 姓名 + 性别 |
| **数据流** | 流动中的数据 | 借书请求 = 读者号 + 图书号 |
| **数据存储** | 静态存储的数据 | 图书表 = \{图书号 + 书名 + 库存\} |

**注意**：**加工不在数据字典里**（加工在 DFD 里）。这是常考的辨析点。

#### 数据字典的符号

| 符号 | 含义 |
|:---|:---|
| `=` | 定义为 |
| `+` | 顺序连接（和） |
| `[ \| ]` | 选择（或），如 `[男\|女]` |
| `{ }` | 重复，如 `{课程}` 表示 0 到多次 |
| `( )` | 可选，如 `(备注)` |

**例**：
```
学生记录 = 学号 + 姓名 + 性别 + {课程成绩}
课程成绩 = 课程号 + 成绩
性别 = [男|女]
```

### 6.1.4 判定表与判定树（★★）

**用途**：描述**复杂的条件组合与动作**之间的关系。当 DFD 无法表达"在什么条件下做什么"时，用判定表。

#### 判定表的结构

| | 规则1 | 规则2 | 规则3 | 规则4 |
|:---|:---:|:---:|:---:|:---:|
| **条件1** | Y | Y | N | N |
| **条件2** | Y | N | Y | N |
| **动作1** | ✓ | | ✓ | |
| **动作2** | | ✓ | | ✓ |

**四部分**：条件桩、条件项、动作桩、动作项。

**规则数** = 2^(条件数)。两个条件 → 4 条规则。

#### 判定树

把判定表画成树形，更直观但条件多时会很庞大。

**教材的建议**：条件少用判定表，条件多用判定树（或反过来，看具体教材版本，考试一般不深究）。

### 6.2 结构化设计（SD）

#### 模块结构图

**元素**：
- **模块**：矩形，标注模块名
- **调用**：箭头，从调用者指向被调用者
- **数据**：箭头旁标注传递的数据（空心圆表示数据，实心圆表示控制信息）

#### 设计准则（启发式规则）

教材列的几条：

| 准则 | 含义 |
|:---|:---|
| **高内聚低耦合** | 核心目标 |
| **模块扇入扇出合理** | 扇入高说明复用性好，扇出一般 3–7 |
| **模块的作用域应在控制域内** | 一个模块的影响范围不超过它的控制范围 |
| **力争降低模块接口的复杂度** | 参数少、简单 |
| **模块功能可预测** | 相同输入必得相同输出 |
| **模块大小适中** | 一般 50–200 行 |

**扇入 vs 扇出**：
- **扇入**：有多少模块调用它（越高越好，说明复用）
- **扇出**：它调用多少模块（适中，太多说明太复杂）

### 6.3 结构化编程

**核心**：只用三种基本控制结构——**顺序、选择、循环**。

**理由**：这三种结构可以表达任何算法（结构化定理），且每种结构**只有一个入口一个出口**，便于验证正确性。

**教材强调**：避免使用 `goto`，因为它破坏单入口单出口的性质。

## 四、教材强调但容易忽略的

1. **数据字典里没有"加工"**：加工属于 DFD，数据字典只管数据。这是最常考的辨析点。

2. **父子图平衡是"输入输出流"的平衡**，不是"加工个数"的平衡。子图可以比父图多很多加工，但输入输出必须对得上。

3. **DFD 的四种元素里，数据存储不能直接连数据存储**，必须有加工。

4. **判定表的规则数 = 2^条件数**，这个计算偶尔考。

5. **扇入越高越好（复用），扇出适中为好（3–7）**。这两个方向相反，别记反。

6. **结构化编程只允许三种控制结构**，`goto` 是反例。
